# 大肥鱼管理中心：当前功能规格（原型第四轮）

本轮只完善原型，不开发业务后端。本文已替换上一轮的分类、提示词预览与活动预算方案。

## 范围与分类原则

一个功能块只管理一个对象或行为。同一页面可以容纳多个功能块，但身份、接收范围、内容处理和资源预算分别管理。一个配置只在所属模块维护，其他页面展示摘要或提供跳转。

本轮包括 QQ、人格与记忆、多媒体、DSH 工具、系统执行、自主活动、任务记录、提示词预览与实例运行。**B站已有功能保留管理 UI；发表评论、发布弹幕等扩展功能暂不开发，也不提供相应 UI。** 总览、能力卡片、自主探索、上下文贡献与健康状态正常包含已有 B站能力。本轮不修改业务代码。

## QQ 的三块结构

### 连接组件

只负责 SnowLuma、OneBot HTTP/WS、组件版本与位置、机器人账号、连接状态和连接凭据。高级地址也归本块。连接检查不主动发送 QQ 测试消息。检测、下载、校验、装配和启动需要各自的后端状态；原型只模拟。

### 饲养员身份

只负责唯一主人 QQ 的绑定与更换。不引入其他管理角色；饲养员不是机器人账号。群范围和自然称呼不改变主人身份。

### 消息收发

| 子功能 | 单一管理对象 | 内容 |
| --- | --- | --- |
| 可观察群列表 | 群观察范围 | 候选群、是否观察、过滤原因；观察不等于每条消息都回复 |
| 自然称呼 | 回应触发名称 | 明确称呼与普通提及、引用、代码分别处理 |
| 限时观察窗口 | 观察材料范围 | 同群背景时间/条数/内容量；按需历史回看独立说明，不自动注入全部历史 |
| 连续消息合并 | 输入提交节奏 | 静默等待、最长等待、最多消息 |
| 自然聊天延迟 | 回复发送节奏 | 最少延迟、每字增量、最大延迟、后续消息间隔及试算 |
| 表情包管理 | 已收集素材 | 预览、搜索、名称/说明/标签、来源、使用记录、停用、删除和恢复 |
| 多媒体处理 | 渠道媒体许可 | 接收类型、发送类型、语音指令；引擎参数跳转多媒体模块 |

延迟公式：min（最大延迟，最少延迟 + Unicode 字符数 × 每字增量）。媒体字节不计数；一次逻辑回复只等待一次；后续消息间隔独立。新规则不重新计算正在发送的回复。

当前固定延迟值是 2 秒、每字 20ms、最多 10 秒、消息间隔 650ms；原型将其参数化。消息合并已具有 quietMs、maxWaitMs 和 maxMessages。表情原件独立于可重建缓存保存，素材编辑不能扩大来源范围，删除不改写历史使用记录。

源码依据：packages/channel-qq/src/reply-delay.ts、batch.ts、index.ts、history.ts、sticker-store.ts、onebot.ts、snowluma-groups.ts。

## 同类分类问题的统一修正

| 页面 | 当前功能块 |
| --- | --- |
| B站 | 内容账号、浏览器连接、公开内容读取、媒体读取、请求节奏、请求时限、响应大小、主人绑定、私信接收、私信任务 |
| 多媒体 | 文件处理限制、缓存管理、图片理解、视频画面读取、语音识别、声音事件识别、文档读取、语音回复 |
| DSH 工具 | 工具连接、文件工具、浏览器工具、插件装配、调用时限、调用记录 |
| 系统执行 | 执行环境、运行开关、任务来源授权、文件访问范围、程序运行范围、执行时限、用量归属 |
| 任务详情 | 概况、执行记录、任务结果、自主反思、用量记录、上下文 |
| 运行 | 实例运行、程序版本、模型选择、记忆存储、媒体缓存、运行诊断 |

视频读取引用图片理解的视觉路由，不重复编辑。QQ 媒体许可不重复管理模型、解码器和缓存。语音识别与声音事件分别配置。任务结果与反思分开，用量与上下文分开。系统执行开关不能自动授予管理员权限。

任务操作仍由当前状态和权限决定：运行中请求暂停/取消；等待补充时提交主人说明；已暂停从有效检查点继续；效果未知只核对回执，不自动重发或重演。

## 活动预算：先执行，完成后检查

- 一轮指一次有效空闲触发后的活动时段，可包含多个具体活动。
- 经费界面单位为**万 Token**，默认 **10**，即 100,000 Token，可自行调整。底层仍保存整数 Token 精度。
- 时长界面单位为分钟；原型保留 15 分钟初始示例值，可调整。
- 有效触发后默认至少执行一次活动。经费和时间预算不在首次活动开始前拦截。
- 每个活动完成后累计实际经费和实际用时，达到或超过任一预算就结束本轮，不再开启下一活动。
- 本次活动使累计值超过预算是允许的正常结果；如实记录超出量，不把该活动判为违规。
- 自主活动预算**不设严格 Token 上限，不做调用前额度预留，不设收尾预留，不因轮次预算在活动中途截断执行**。
- 例：预算 10 万 Token，首次活动完成消耗 12 万 Token，允许完成、记录 12 万，然后结束本轮。
- 例：目标 3 分钟，活动结束累计 3 分 30 秒，记录真实时长，不开启下一活动。
- 取消、权限失效、前台优先及工具故障依照各自规则处理；“先执行”不绕过授权，也不保证活动一定成功。

累计主模型、辅助理解、反思与执行子进程的实际用量；输入含缓存、输出含推理，避免重复相加。用量缺失显示待核实，不按零结算。时间包含模型/工具等待，扣除前台抢占暂停。设置对下一轮生效，当前轮不会通过暂停/继续/保存设置重置累计值。

未来轮次记录包括 roundId、配置快照、活动列表、执行段、实际累计用量、已完成次数和结束原因。按活动完成事件幂等结算，再决定续行；不为该轮次引入 reservedTokens 或硬预算准入逻辑。

“允许自主活动”内部按活动开关、空闲判定、轮次间隔、安静时段、活动类别、探索能力范围拆分。最小间隔从上一轮结束计算。程序判断运行条件，Agent 决定具体内容；不代替 Agent 决定人格。

当前业务仍有 occurrence/run 及运行中 maxActiveMs/dailyActiveMs 检查，尚未实现上述完成后判断的轮次语义。正式开发时需要调整，本轮不修改业务。

## 提示词预览：渲染文本

- 只读，以提示词文本为主体，不再以功能概括列表代替正文。
- 固定提示词、系统提示词采用标题与可展开分项；固定文字从当前源码字面量提取，来源及哈希见 prompt-sources.json。
- 动态部分的正文只渲染 **【动态提示词】**，不在占位符内填入概括、示例聊天或推理。
- 不同模块用颜色、边线和名称共同区分，模块名称提供跳转。颜色与标签属于 UI 标注，不额外发送给模型。
- 请求场景包括 QQ 对话、主人任务、自主活动、独立视觉分析。视觉分析是独立请求，不拼入主对话系统提示词。
- tools 作为独立字段展示标题和动态占位，不冒充 system 正文。B站已有读取能力的观察结果以动态占位显示，并提供模块跳转。
- 初始化身份底色在首次导入记忆后稳定保存，不能误标为每轮变化。当前自我认识、召回、目标、历史及调用结果动态占位；不读取模板覆盖人格。未连接实例时不伪造底色正文。

后续只读接口提供贡献 ID、所属模块、请求位置、固定文本或动态标志、参与条件、管理入口和 revision。预览不运行模型/工具，不重新调用会写事件的 prepare，不展示凭据、其他会话原文、模型内部推理或子进程原始私密会话。

源码依据：packages/core/src/runtime.ts、native-runtime.ts、harness-runtime.ts、context-runtime.ts；packages/contracts/src/qq-expression.ts；packages/media/src/service.ts。

## 后端关联（暂不实施）

模块管理自己的描述、配置 schema、读取/校验/保存、生效状态、诊断与操作。管理中心只组合；每个参数明确单位、约束、作用范围和生效时机。权限与状态校验由后端执行，不只隐藏前端按钮。

未来接口仍统一为单一当前版本，模块同步调整。B站已有功能 UI 在范围内，发表评论等新增扩展及其 UI 不在范围内。验证只做基础单元与少量短装配检查，不恢复长流程回归。

## 缓存讨论（尚未实现）

缓存匹配请求前缀；当前预览仅为逻辑分层，不代表供应商最终 Token 顺序。稳定规则、稳定底色与工具定义保持一致；合法历史尽量只追加；新的动态状态放到本轮增量。普通状态更新与真正撤回必须区分，权限/来源失效时允许破坏缓存前缀。详见 [提示词缓存讨论](提示词缓存讨论.md)。

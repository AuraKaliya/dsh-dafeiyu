# 自主活动4D：Host装配、迁移与联合检查

2026-10-25；基线`d1604f5`。4A—4D本地开发完成，未做真实模型、平台或服务器验收。

Host正式识别可选activity插件、策略与依赖，先装配／恢复，再在daemon的ready后开始计时；single-run保存计划但不运行后台机会。关闭先停止调度，再等待或取消核心工作，最后关闭库。状态只显示计数、生命周期及稳定错误，关闭后保留计数；不包含活动目标或观察正文。

新增`core/activity.sqlite` v1，已有profile首次启用需要显式迁移。迁移计划包含activity声明、原库备份和行摘要，创建新库失败后可续做；不会调用init覆盖旧数据。完成后将activity加入原profile的权威库清单。关闭插件也不删除其数据。只读检查识别活动身份／完整表集，并补齐memory v11新增表的完整性检查。

联合流程实际运行Host／DSH／SQLite：single-run保存计划→到期仍不后台执行→关闭→daemon恢复→无QQ输入进行虚构探索→自主选择保留观察并暂停后续计划→核心维护Run整理经验→关闭重启→没有重复模型调用。示例为[host.activity.example.json](../profiles/host.activity.example.json)。脚本模型只用于程序检查，不是可用性或真实成长的证明。

## 发现和修正

首次Host联合流程发现：历史活动上下文被错误地拿来与当前维护机会比较，导致合法来源被判stale。改为按原始不可变机会校验，同时严格要求同Task和当前有效来源。随后补强目标授权：wake的来源锚点进入原生输入证明，不依赖可选上下文是否装入；维护锚点继承实际原生输入依赖。即使上下文预算为0，原计划来源被撤销后也不会通过派生Task目标再次进入维护模型。旧记录缺少可核依据时不虚构补齐；普通旧native／wake接口仍兼容。

QQ定向兼容检查中，一份合成v9测试库只去掉v10表，却保留了新的v11表，形成了不真实的混合schema。修正测试使用既有旧库构造助手移除后加表；没有放宽生产迁移检查。新增测试类型引用曾遗漏可选参数的undefined分支，修正后重新构建。

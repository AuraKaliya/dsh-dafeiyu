## 2C-1缓存契约

保留messages／receipts／handled三表，v3追加消息元信息、会话缓存代次及浏览快照表。旧行不回填虚构时间或媒体类型；首次读取旧消息可建立版本索引，但时间仍为unknown。每条消息保留实际消息ID、发送者、时间（已取得才有）、媒体种类、文本截断事实、内容哈希和版本。重复事件不重入模型；相同ID内容改变推进版本。撤回留下墓碑，迟到的重复入站不能复活。

浏览仅针对插件收到的最多200条会话缓存，按本地接收顺序由新到旧。每页最多20条，规范化页面正文限制8000个UTF-16单元，切片保持Unicode码点完整；超长单条可以从上一页游标继续其余文字。页面明确本地水位、缓存缺口、时间未知、媒体未读和文本截断，不声称平台全量历史。

首个页面固定水位，后续新消息不插入原分页窗口。游标绑定程序签发的owner、会话、查询条件和缓存代次；撤回／修订／缓存淘汰使旧分页游标失效。消息版本索引独立于缓存正文：正文被淘汰不自动抹掉已选择记忆的历史证据，后续收到撤回仍能使相应证明失效。

短期页面快照默认最多256份、1小时；快照ID是随机票据，绑定插件本次装载和实际执行范围，不是可自报的授权。过期／重开／卸载后的旧选择票据无效。每次浏览回收过期及上一装载快照，达到容量会明确返回资源不足，不增加每轮调用次数上限。none不将页面正文写入长期记忆；短期缓存／审计和长期贡献分开。

## 2C-2授权与观察契约

QQ渠道仍用兼容v2入口，浏览能力由独立 `qq-capabilities` v3扩展提供。核心核验真实ExecutionContext对象及所属插件；聊天资源从真实入站会话确定，不能借owner私聊读其它群。原生任务的资源白名单由可信运行配置／策略指定，模型中的groupId只是请求，不授予访问资格。Task origin保持native，不伪造聊天。

观察先记录实际批次、覆盖、来源版本及曝光事实，再由大肥鱼选择none／原文／片段／摘要。能力只提供已取得材料和可回查证明；核心提供当前作用域、操作因果和历史输入依赖；记忆负责持久化、幂等、派生范围和失效。新接口不能让QQ自行拼装可信memory authority，也不直接调用记忆插件内部存储。

原文和片段由程序从实际页面切取；摘要是模型推断，必须继承全部实际输入及历史限制。未取得有效历史追踪时，摘要贡献明确拒绝，不能以空依赖冒充完整追踪。来源撤回／修订、删除、范围变化和服务卸载应撤下相关工具正文、派生记忆及摘要；记录恢复不能复活旧版本证明。未来自动经历关联／人格采用仍属于记忆E阶段。

接口细化：原生资源范围放在 `authorityPolicies[].resources`，缺省为空；聊天始终只准当前真实入站会话，不借用该白名单跨会话。v3扩展可注册只读 `resourceProofs`（current／epoch），核心验证所属插件、活跃调用及资源范围后调用记忆观察端口。来源根身份由能力提供并验证，重复观察不凭新UUID增加独立证据。

memory v9增量增加 `capability_observations`／`capability_selections`。观察只保存元信息、正文哈希、资源证明、覆盖和因果；返回的execution-source引用指向这份元信息，并不冒充可永久读取的原文。实际工具结果仍按DSH原有历史机制保存；这与长期memory item分开。选择原文／片段由缓存实际页面验证；摘要附全部当前请求依赖。none只记录选择，不创建memory item。原生任务贡献使用任务边界、对外表达关闭；聊天贡献保持当前会话边界。

`memory.sourceTracking:true`只启用来源追踪，不主动压缩、不新增辅助模型调用；已有compaction配置也提供追踪。无可核验当前请求时，选择接口拒绝猜测“模型已看到”。摘要含未追踪／仅历史查看等临时依赖时拒绝保存；以后历史依赖暂时无法复核时，该摘要暂不返回，不能当成依据仍有效。删除记忆后同源观察不能重新入库，明确恢复原记忆也不会复活引用旧状态版本的摘要。

## 2C-3装配与范围

功能显式启用，旧配置保持原行为。Host在连接QQ前检查所需memory／timeline／执行策略和来源追踪配置；缺失时给出可诊断错误，不把配置存在当成能力可用。状态与动作清单一致，关闭遵循停准入→等待动作→卸载→关闭库。

`qq_groups`仅返回当前作用域获准的会话信息；原生Task也只看到显式资源白名单与平台允许范围的交集。`qq_browse`返回实际页面、观察票据、覆盖和继续位置；`qq_observe_select`提交选择，不提供任意发送工具。群同步、昵称及平台加入资格不能扩大记忆出口。撤回处理仅以实际收到的本账号事件为依据，不声称能发现离线期间全部变化。

实施补充：开启能力后缓存使用账号＋会话键，旧未绑定账号缓存保留且不自动暴露；避免猜测旧行属于哪个账号。来源版本指纹按会话计算，另一群的变化不撤下无关材料。Journal增记撤回事实而不抹除原始记录；聊天来源、历史回查与记忆追踪共同拒绝已撤回材料，避免只让浏览结果失效却又从原聊天输入重新引入。重复撤回不重复审计，并能补齐缓存已打墓碑、审计尚未落盘的中断步骤。本步不新增schema版本。

## 2. 内部观察、贡献与来源防护

观察具有primary、digest、self-report三种内容性质。primary仅表示能力实际取得的外部文字，不能据此证明文字的断言真实；digest／自述不被升级成原始事实。贡献原文及片段保持来源类型，模型摘要标为inference。保存经历不自动增加偏好、信念或成长分数。

能力结果先有真实操作回执，记忆贡献可以之后独立重试。贡献、引用谱系和记忆outbox在同一memory事务提交；贡献失败不会要求重新执行原能力。摘要产生的自述来源与贡献一起回滚。来源观察本身仍保留为已经发生的事实。

原生Task记忆使用`MemoryBoundary schemaVersion:2`，`sourceScene=execution-task`、`internalUse=task`、`externalExpression=none`。旧Conversation边界v1不变；没有创建假Conversation、sender或聊天消息。已有D1记忆必须带当前有效的规则、Task授权、选择及范围证明，不能用同一个agent作为全局通行证。新Task范围暂未接入全量语义检索或独立分析器。

模型可用的新工具包括来源分页、贡献、证据选择、来源删除／恢复、贡献删除／恢复、任务异议和意图查询。受信插件通过`ctx.dafeiyuMemory.persona`调用相应方法；每次仍核验核心原上下文、生产插件与读／本地写权限。`recordObservation`不是直接开放给模型的任意事实写入工具。

人格候选可引用本轮已曝光的`task-link`、`execution-source:<id>`及`memory:<id>:<revision>`。核心绑定完整曝光依赖，模型引用不能缩小真实依赖集合；支持和反证的根来源仍去重。

删除、更正、撤下或授权变化使受影响的当前上下文、派生结果、压缩片段及待提交输出停止使用。恢复产生新版本，旧证明不自动复活。Task目标变更会使旧Run结果不能当作当前交付，但不会无条件抹掉同Task内仍可核验的历史观察；原D1授权仍按当前状态检查。

操作已产生效果时，即使后来来源回执不合法，也先保存实际效果，随后阻止结果提交。未知效果不能通过换requestId、新Run或改变同Task目标绕过；本步不提供把unknown猜成成功的入口。

事件索引只向模型返回操作身份、状态、版本、因果关系等有限元数据。自由文本的选择理由仍在原审计归档中，但不会被事件索引当成新证据返回，防止其绕过删除传播。需要正文应通过受控来源接口读取。

## 3. 独立判断与任务执行

`RunOrigin`回答“怎么唤醒”，`Motivation`回答“为何做这件事”。新受信普通任务默认explicit-task；受信生产者可通过`executionProducer(id,{motivation})`声明self-exploration等动机。旧记录没有动机时仍为unknown，不回填；模型工具参数不能改变生产者动机。

偏好和方法异议允许表达，但不能标为阻断，也不能擅自替换目标或降低交付标准。前提、信息、范围问题可以阻断列出的相关动作；其它步骤仍可继续。未列动作且标为阻断表示整个任务需要讨论。未解决的阻断最终使Run进入waiting，不报完成。

`resolveObjection(TaskRef, input)`只在受信生产者入口提供，核验真实TaskRef和当前epoch；未向模型提供“替用户确认解决”工具。解决并不增加平台权限，后续操作仍经过原授权检查。继续运行使用明确的父Run及检查点，提供已确认操作的状态／回执引用；历史已确认动作不由恢复过程自动执行。

本步提供业务契约及受控执行，不声称已完成QQ自然语言意图分类、真实自主活动调度或“按兴趣自主规划”的长期评价。

## 4. DSH压缩与接续

新增`HistoryFrame`表示实际聊天或原生任务来源。任务仍是`dafeiyu-execution`程序输入；聊天沿用真实入站。两者复用既有CompactionRuntime、SourceTracker、分片证明与工具调用／结果配对退出保护。启用来源追踪不必同时启用模型摘要；未配置摘要时只做校验和失效退出。

v3上下文进入真实请求预算，并保存身份、版本、内容哈希及验证回调。实际模型请求继承所有合法暴露的输入、上下文及工具来源；同一Run已见资料不能因后续压缩移除而“洗掉”依赖。其它插件的上下文保持独立验证。

工具来源回执以显式包裹值经过DSH复制，再将纯业务内容呈给模型、将证明保存为元数据。核心记录实际插件版本及动作版本，修正过去把动作版本误当插件版本的记录方式；旧操作不改写，缺少新旁表时明确未绑定动作版本。

本步增加原生历史分区版本，旧无来源证明的会话不被静默当成新会话。继续保留Task／epoch／授权／输入／阶段投影的分区；分区变化时从合法阶段、已选资料与检查点重建。工具调用轮仍不做语义压缩；完整原始档案由DSH保留。

检查点在DSH完成flush后保存：底色哈希、阶段修订、Task／epoch、会话与seq、来源及完整曝光依赖哈希、任务意图事件、已完成／未知操作、可见结果短说明及缺口。较长或检测到敏感形态的结果不复制为检查点正文，改为按权限回查DSH。检查点不是新的最高权限提示词，也不用于恢复模型思考。

提交顺序为memory检查点／依赖／outbox事务，然后runtime引用及检查点事件；最终结果投影通过runtime outbox幂等补齐。memory已保存而runtime未关联的孤立检查点保留、不采用；结果投影丢确认时启动恢复可补齐而不调用模型。暂停／异常结束没有合法完整检查点时，保留原运行账本与缺口，不能把部分输出当成完整接续。

真实验收发现旧摘要输出额度`maxChars*2`不足以覆盖推理模型的完成预算。新增可配置`summaryMaxOutputTokens`（默认8192）；摘要可见字数继续按每组字符预算独立校验。它是单次摘要的资源额度，不是调用次数限制。输出不完整、校验失败或压缩无收益时保留原历史，不能写入半份摘要。

4. 注入贡献事务失败，保留原观察，重试记忆而不重复能力。
5. 阻断仅影响相关动作、独立步骤继续、waiting及受信解决后续行。
6. 偏好不阻断任务，可信探索动机与native起因分别保存。
7. memory已提交、runtime关联失败时，孤立检查点不被重启采用或重放。
8. v3原生上下文实际装配，验证失效阻止结果。
9. 多轮原生压缩、来源记录与重启续接。
10. 非空来源回执严格核验；引用错误不抹掉已经发生的效果，也不能提交结果。
11. 未知效果不因新Run及新参数而重做。
12. runtime已完成、memory结果投影失败时，重启补投影不调用模型／动作。

## 7. 真实模型验收与限制

`npm.cmd run accept:phase1e3-continuity`使用新底色、现有DSH凭据引用、DeepSeek实际服务和全新隔离profile。能力材料、记忆与任务全部虚构，不接真实QQ／B站账号，不读取管理中心旧人格或私人记忆。

[最终真实记录](results/phase1e3-continuity-real.json)：**19次提供者调用（13次任务、6次摘要），7项检查通过，3次压缩实际提交，9份检查点**。

- 模型实际读取带来源的部分文字、贡献推断摘要、选择证据并提出非阻断方法建议。
- 贡献只在Task内部可用，对外表达关闭。
- 同Task重启采用绑定检查点和原DSH会话，取得随机标记与材料局限；观察操作没有重做。
- 另一个Task未取得该内部资料。
- 实际模型摘要与压缩提交后重启，仍说明结论未定、保留反证、未验证声音与画面。
- 持久化文件检查未发现模型reasoning／opaque replay。

[首次真实记录](results/phase1e3-continuity-real-initial.json)原样保留：16次调用，其余6项检查通过，但3次摘要均以max-tokens结束，0次压缩提交，整体失败。不能把“请求正常结束”当成“摘要已通过”；修正完成预算后才得到最终成功记录。

本步证明有限接口及接续路径可用。未完成1G的162次场景协议、完整／压缩盲评、长期人格成长、真实探索时间安排或B站音画理解集成。现有1A音画探针仍单独计量，字幕／这次文字样本都不等于音画理解。

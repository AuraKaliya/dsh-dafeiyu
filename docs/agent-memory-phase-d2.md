# D2：表达判断、独立交付材料与干净重建

日期：2026-10-24。项目0.18.0，contracts/core/memory 0.14.0，memory.sqlite schema v6。本轮在本机以实际DSH模型传输接口、脚本模型和虚构资料验证，没有调用真实生成模型、接入真实QQ或修改服务器。

## 职责与对外边界

D1授予任务内部读取权；D2根据目标判断所选证据和现有结论能否表达，并建立独立材料与回答草稿。材料和草稿均返回sendAuthorized=false。D3仍负责目标会话人格整理、最终交付凭据、发送前校验和渠道状态，本轮没有自动装配普通聊天或发送入口。

D2只向受信原生TaskController提供接口，不注册普通聊天工具，不向ExtensionHandle提供跨场景原文导出。模型不能自行创建表达规则，不能用声明的citations删掉程序记录的实际输入。

## 接口

| 接口 | 用途 |
|---|---|
| core.setTaskExpressionPolicy(input) | 明确、版本化地将指定原记忆版本授权给一个目标会话 |
| controller.expression.prepare(input) | 从任务选中链接与结果槽筛选表达材料 |
| controller.expression.open({packetId,target}) | 复查后读取目标材料，目标必须完全匹配 |
| controller.expression.generate({requestId,packetId,target},signal?) | 从允许证据和实际入站问题独立重建回答 |
| controller.expression.result({jobId,target}) | 复查全部来源与权限后读取已完成草稿 |
| controller.expression.withdraw({requestId,packetId,expectedVersion}) | 逻辑撤回材料，保留档案且不可恢复旧凭据 |

prepare使用requestId、inboundId、linkIds、slots以及可选policy{id,version}。inboundId必须是本地核心已接收的消息回执；目标、问题文本、原始引用及哈希由核心日志解析，不接受任意question/prompt/target文本替换。无法找到入站来源就拒绝，不能退回内部任务目标。

所有入口使用严格结构校验。target包括渠道、账号、会话类型与会话ID，不凭用户昵称或任务标题认定对象。D2只绑定会话级受众；群成员变化和实际收件身份交付校验仍由D3及渠道适配处理。

## 表达判断规则

每份证据先检查D1授权（如有）、任务来源证明、当前记忆版本、原权限、祖先和删除状态。原始externalExpression=none或internalUse=none不能被D2普通表达规则覆盖。

原记录允许在来源会话表达且目标就是该会话时，可以进入材料。向另一个场景表达必须有受信配置显式签发的表达规则，固定目标、记录ID、revision、状态version、contentHash及完整来源证明。没有泛化公开通配符，不自动把“主人”当作全部私聊的接收者。

该规则是明确的定向发布授权，不修改旧记录的boundary。规则所选择的原记录及其完整输入闭包被一起固定；记录修订、来源删除/恢复或规则版本替换后，旧材料失效。externalExpression=none的记录不能被简单改写、去名字或更换任务绕过；需使用独立允许表达的证据重新生成。

规则版本以expectedVersion进行比较更新。停用规则即使所选来源已失效也能执行；重新启用要重新核验来源并产生新版本，不恢复旧包。

## 多来源结论

现有结果槽的内容必须通过slot名称从任务工作区读取，调用方不能传入替代正文或自报来源。程序取得该结果的不可变job输入与观察输出证明；所有实际记录的输入均允许向目标表达，才能将结论纳入材料。

例如：工作项读取A和内部私有B，完成文本只声称“参考A”。D2仍按A+B判断，不能通过只列A的引用发布这个结论。source不完整、空依据、旧slot版本、任务epoch改变或任一依赖失效，都会拒绝。

这里的完整性基于受信能力插件与核心已经登记的实际输入。不能证明同进程恶意插件没有自行读取未登记内容；这不是操作系统沙箱。原生协调器和真实插件适配应继续通过既有输入/观察接口记录来源。

prepare逐项筛选，拒绝项只返回内部判定元数据，不把其正文复制进材料包。允许证据和允许的旧结论分区保存。旧结论可以供后续受控交付检查，但干净重建一律不使用旧结论，即使它已被判定为可表达。

## 干净上下文重建

生成请求只含固定整理指令、目标会话实际入站问题，以及允许的原记忆片段S1、S2等短引用。以下内容不会进入请求：

- 内部任务标题、目标、待办、检索查询和完整内部快照。
- 未获准证据、被拒结论、允许的旧结论及此前生成结果。
- 其它会话历史、当前聊天全部历史、宿主原生提示区域及其它插件区域。
- 完整授权/来源证明、原生数据库ID和内部审核理由。

每次生成使用新的memory-expression-generate会话标识，通过现有DSH LLM服务调用当前绑定模型；没有另写模型循环或注册继承工具。生成后使用另一个新会话标识独立检查回答是否忠于同一批允许证据，保留限定、时间、归属、否定和不确定性。验证请求只新增候选回答，不接收私有来源用于“核对”。

工具调用、不完整输出、无效JSON、未知引用以及保真检查不通过均拒绝保存成功结果。模型没有权限决策权：范围在调用模型前由程序判断。模型检查是保真质量控制，不是对事实正确性或任意模型行为的数学保证。

没有允许证据时返回expression_insufficient_evidence，不调用模型，不用私有结论兜底。允许证据本身不足以回答时，模型可返回insufficient=true并说明不足。

最终结果保存全部实际提供给生成/验证请求的证据和问题证明；citations只作为展示字段。即使回答只引用S1，提供过的S2仍属于实际曝光依赖，S2删除会使该结果退出。

## 时效、授权与删除

材料固定任务epoch、目标问题、授权证明、可选表达规则版本、选中证据、旧结论slot版本和15分钟有效期。所有读取均重新校验，生成在开始、流式输出期间、验证和提交前检查状态。

目标原问题保留真实入站引用、脱敏内容哈希和来源状态屏障。删除基于该问题的来源记忆会使它退出；恢复推进屏障，旧材料仍不会重新有效。来源记忆删除、范围收紧、修订、D1授权撤销/过期、表达规则停用、任务目标变化或材料撤回同样生效。

生成中发生失效时不返回可用草稿。未通过校验的模型正文不保存到expression_jobs，不记录推理文本。已成功保存后才失效的结果保留历史档案，但正常result不再返回正文。已发送给模型的输入无法收回；本机制阻止后续使用与交付，不声称撤销过去的暴露。

一个材料包是固定输入快照，任一被纳入材料的依赖改变都会使该包失效；可以重新prepare只含剩余有效项的包。独立材料、其它任务及DSH插件区域保持不变。旧结论虽然不进入重建模型，仍是其所在材料包的依赖；需要更小失效范围时应分开建立材料包。

## 持久化与恢复

schema v6新增expression_policies、expression_policy_revisions、expression_requests、expression_packets和expression_jobs。材料正文与任务绑定不可变；撤回只推进状态。终态任务记录不可覆盖；规则/材料/任务档案不物理删除。

prepare、规则变更、撤回、生成状态及对应outbox均在SQLite事务内提交。审计写入失败时整体回滚。审核日志只记录内部任务路由的身份、状态与数量，不把私有证据或模型推理写入统一日志。

requestId提供幂等性；重复完成请求在重新校验来源后返回原结果，不重新调用模型。相同请求在运行中不会启动第二次调用；参数变化则冲突。中断或失败的请求不自动重跑，需要新的明确请求ID。

重启保留有效材料、已完成结果及撤回状态；孤立running任务转为interrupted，不重放模型、工具或发送。卸载提供者时先取消并等待本次活动生成收尾，再关闭存储。沿用单一活动MemoryService宿主假设，没有分布式任务租约。

v5→v6迁移不改变旧记忆边界、D1授权或删除状态，不生成默认表达规则。正式部署仍需版本配套和一致性备份；本轮未迁移真实数据。

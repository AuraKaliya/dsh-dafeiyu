# QQ 2E：可信任务与结果交付实施方案

日期：2026-10-25；基线 `db139bd`。2D已完成，按用户授权继续QQ阶段，不连接服务器。旧D3的模拟且最新消息限制保持；以下实现独立的消息任务／结果交付契约。

## 分步出口

| 步骤 | 实现与检查 |
|---|---|
| 2E-1 | 核心绑定实际Journal消息、主人身份、原始主正文、固定策略与来源版本；原生Task受理／状态；伪造上下文、引用指令、跨群和非主人拒绝 |
| 2E-2 | 任务取消、改目标、异议解决与继续；幂等、epoch失效、阻断异议、普通新群消息不取消任务 |
| 2E-3 | 记忆侧原生任务表达材料：只选目标可见的原始证据，继承来源限制，私有内部报告不直通；增量持久包与撤下 |
| 2E-4 | 新task-result锚点与凭据账本、干净目标人格整理、独立忠实性校验、逐段发送；部分／未知／重启不重放 |
| 2E-5 | Host装配／模板、完整本地回环流程与使用记录；随后继续2F阶段整合 |

每步只运行改动相关测试并提交记录／Git。真实模型的任务语义判定、人格表达及真实平台验收全部延期，全量回归留到部署／发布。

## 受理与独立判断

QQ增加显式开启的tasks配置，默认关闭。模型动作只能提议任务种类／标题与探索目标，不能填写发送者、主人、producer、目标会话或权限。core核验实际v3调用对象和Journal真实来源，任务producer由装配固定。原生Run保持native origin，另存触发消息证明，不伪造新的聊天入站。

明确任务的目标由程序从当前主人消息的主正文提取，不能由模型改写。首版识别直接的“任务：…”“请／请你…”“帮我…”“麻烦你…”等请求引导，允许配置称呼前缀；纯引用／代码中的指示不授予任务权限。不能确定时仍可正常聊天，任务动作返回需明确指示，不猜测已获授权。QQ将主正文与附加引用／媒体说明分别保存；旧消息没有该字段时不倒推授权。语义理解质量仍待最终真实验收。

兴趣探索使用独立self-exploration动机，目标由大肥鱼提出，不冒充主人命令；其资源仅当前会话。明确主人任务的资源为当前来源会话与配置白名单，来源范围由core签发，模型群号不授予权限。日常偏好／观点不因任务受理而改变；TaskIntent保留明确目标、异议与处理过程。

状态只向同一来源会话返回任务元数据，不直接返回内部结果或含私有证据的异议全文。主人取消／改目标／解除阻断需要当前真实指示及原任务来源关系；目标变更通过Task epoch使旧Run及结果失效，普通新消息不变更epoch。所有操作保持幂等与来源审计。

2E-2实施补充：明确任务按真实消息身份去重，换一个模型requestId不能重复受理同一指示；探索按消息与探索目标区分。控制请求固定实际消息、目标Task和操作／异议身份。控制回执属于正在执行控制动作的聊天Run，不写进已经完成的任务Run。取消以Task暂停和epoch推进落实，活动Run合作取消；改目标从新主正文取值并创建新epoch的Run。解决异议继续时必须继承原消息资源范围。状态提供resultCurrent，避免把旧Run的completed误认为新目标完成。更新后发生故障则保留已改事实并记录unknown，不能回报无副作用。

## 结果表达与交付

执行器原始报告只在任务内部。memory根据目标范围与既有表达策略筛选原始证据，不把执行器总结、跨范围历史或最终引用列表当成降级授权。目标可见的QQ原始观察需对照实际操作结果、已保存观察hash和当前来源证明；私有／任务内部记忆在无独立表达授权时排除。证据不足时明确等待／拒绝，不能以模型改写绕过。

限定材料持久化并绑定taskId、runId、taskEpoch、实际请求消息、目标会话、来源版本、有效期与表达策略版本。目标人格在新的干净DSH会话中整理，只接收这份材料及有效人格投影；不继承执行会话或其它群历史。独立验证只依据相同材料检查最终文字，失败不发送。发送凭据绑定最终正文hash、锚点和来源；每段复检，调用2D传输。已确认部分／unknown永久可查，重启不自动重演已开始的外部操作。

## 数据与兼容

2E-1／2沿既有execution_requests和run_inputs保存带schemaVersion的消息来源证明；新增字段可选，旧无消息原生任务保持兼容，不重写已有Run。旧Host不能解析新的tasks配置，因此不得以旧程序运行启用了此特性的profile。新增实际持久表达包或交付表时再增量提升其所属库版本，并添加旧库样本检查；不提前创建未实现阶段的表。

新接口与旧D2／D3分开，不修改旧唯一入站约束来承载多个任务结果。旧缓存／回执、真实记忆、原未提交文档全部保留；只更新项目源码、虚构测试、模板和记录。

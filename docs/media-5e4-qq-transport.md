# 统一媒体5E-4：QQ逐部件媒体传输

2026-10-25；基线`c6f313f`。

QQ新增独立`media.sendEnabled`开关，兼容默认关闭，依赖已启用媒体能力。渠道显式声明parts-v1并提供受控字节回调后，核心才调用媒体传输；旧v2／v3装配均保留并校验这些接口。接收开关不会自动扩大为发送权限。

每个正文分段、图片、record和file单独调用消息数组接口，传输只接收核心批准的清单及字节。图片／语音采用Base64输入形式；file使用NapCat扩展消息段。群里正文／图片带原消息引用，语音和文件保持独立消息段。接口形态参考[OneBot消息段](https://github.com/botuniverse/onebot-11/blob/master/message/segment.md)和[NapCat文件处理](https://napneko.github.io/develop/file)，真实平台兼容仍待整体验收。

字节先完整核对长度和hash，再做本部件最后一次账号／群／来源校验，随后持久化sending并调用平台。确认回执先入账，再更新缓存；媒体缓存只存占位，不从占位制造新的内容观察。已确认不重发，响应丢失为unknown，部分成功如实保留。整份成功才写完整回执。状态和停止后的只读查询合并文字／媒体账本。

原生路径实际经过独立目标人格渲染、校验和媒体凭据后，才取得核心访问对象并送给渠道；内部执行器报告未进入发送正文。计划与传输参数采用独立快照，回调仍绑定原清单。历史材料查询不因普通字节回收被伪装成逻辑删除，重新发送仍必须有实际字节。

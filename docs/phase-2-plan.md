## 模型配置

用户要求沿用当前DSH绑定模型。只读检查本机 `%USERPROFILE%/.dsh/profiles/desktop/cordis.patch.yml` 中的 `agent-default-model` 条目得到：

- provider：`deepseek-official`
- model：`deepseek-flash`
- reasoningEffort：`max`

以上是保存的桌面默认配置，不是对正在运行的特定会话做出的推断。真实调用开始前重新核对实际选择，并在每次验收记录中保存模型路由及推理强度；一次验收期间固定配置，避免默认设置变化混淆结果。

第一阶段核心尚未显式传递reasoningEffort，第二阶段需要补充并测试，不能只对齐模型名称。通过DSH已有模型提供方和认证机制接入，不在QQ插件中直接调用模型，不替换为另一个供应商。

使用独立测试profile、会话与持久化目录。如何安全复用当前本机认证由实施阶段核验；不复制整个日常profile或凭据文件、不打印令牌、不将认证材料写入Git。如果隔离profile无法使用现有认证机制，先明确具体限制再决定本地登录方式。此项尚未实施或验证。

本阶段不新增每轮调用次数上限。记录调用量、耗时及提供方可用的用量信息；当前没有用户指定的费用预算，不自行假定无限额长期运行。仅按确定的有限验收场景执行真实调用，不启动无人值守主动活动。

## 实现范围

1. 独立DSH本地测试启动配置，保留第一阶段模拟验收入口。
2. 新增 `@dafeiyu/channel-qq`，注册到主插件，负责标准化消息与交付。
3. SnowLuma适配器处理认证、登录账号核验、事件连接、发送回执和连接恢复。
4. 主人私聊文字收发；专用测试群真实@和约定的引用触发。普通群闲聊默认不触发。
5. 引用仅限本会话的真实消息；需要读取引用原文时校验来源，不能按任意外部编号读取。
6. QQ消息、模型回合、插件操作和交付回执在统一事件记录中关联。
7. 检查失败、超时、重复事件、重启和结果未知，不盲目重跑有副作用的操作。

图片理解、语音、文件交付、合并转发展开、主动刷群、B站、长期记忆及专用压缩策略不属于本阶段。收到暂不支持的消息类型时明确记录类型和处理结果，不假装理解内容。

初期模型只获得无副作用的测试操作，不挂接终端、文件管理或服务器任务。引用及@等新元数据先设计类型与兼容策略，不向第一阶段严格消息结构随意添加平台字段。

## 本机隔离与连接

- DSH测试实例、SnowLuma配置、会话、数据库及令牌均使用独立位置，不使用服务器地址或配置。
- 本机OneBot接口仅绑定回环地址，端口先检查占用再确定；启用独立访问令牌。
- 显式关闭SnowLuma自动注入，确认只挂接测试QQ进程；不凭不同目录认定进程已隔离。
- 首次连接、重连及发送前根据连接状态核验实际登录账号为1994142241。事件self_id必须匹配。
- 私聊只接收756013063，群聊只接收1106067626；不自动接受好友或群邀请。
- 当前会话之外的目标不能由模型自由指定；普通回复仍由核心送回原会话。
- 初期优先采用事件连接接收消息；历史补取必须单独验证时间范围、来源和去重，不能重放旧聊天。
- 不承诺补回平台未保留的离线消息。对连接空窗和可能缺口记录状态；本地已接收且持久化的消息按核心恢复规则处理。
- 固定实际验证的QQ、SnowLuma、DSH和Node版本组合；不在验收中途升级。

## 必须满足的验收标准

- 错误登录账号、错误self_id或未允许会话不进入模型，不向其交付回复。
- 指定主人私聊文字可以完成真实闭环，回复只回原处。
- 测试群真实@及指定引用触发有效，普通闲聊默认不触发。
- 私聊和群分别保持上下文，不混入对方原文；群内昵称不授予主人权限。
- 同一平台消息重复到达不生成第二轮回复；引用指向真实同会话消息。
- 模型失败和超时不发送半截最终回复，失败状态可查询。
- 明确未发送可补发；发送结果未知不得自动重发或伪称成功。
- 重启恢复会话与持久化工作状态，已交付消息不重发。
- 每次交互可以追踪到消息、DSH会话、模型回合、操作和交付回执。
- 测试期间没有连接线上账号、服务器或线上数据目录。

观察项：响应耗时、调用量及可用费用信息、人格自然程度、明确纠正的连续理解、是否准确复述实际工具结果、是否编造未完成行为。不以单次模型表现宣称长期人格或记忆质量通过。

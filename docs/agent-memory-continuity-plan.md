# 智能体级记忆与跨场景任务连续性方案

日期：2026-10-24。大肥鱼是记忆所有者，具体聊天继续由DSH分别管理。沿用已有来源链、逻辑删除、独立分析、装配与压缩机制；本机开发测试，服务器和真实QQ运行配置不变。

## 职责与原则

- DSH负责各群聊、私聊的消息、模型循环、持久化和恢复。
- 能力插件设计怎样观察、选择兴趣、生成摘要和贡献经历，可以贡献原文、片段、摘要、发现，也可以没有贡献。
- 记忆插件保存、分析、关联和检索大肥鱼跨时间、跨插件、跨场景的经历与认识。
- 主插件签发任务和范围，协调当前注意内容、工作快照和对外交付。

安装插件不等于全量保存其输入。收到、选入模型上下文、分析过、贡献过和长期保存分别记录，不能虚构“已读”。插件可以只提交摘要，或记录一次无贡献的观察活动。没有留存且不能再取得原文时，只能回查观察批次与摘要，不能承诺逐条恢复原文。

## 五个独立维度

| 维度 | 含义 |
|---|---|
| owner | 稳定的智能体所有权 |
| sourceScene | 信息来自什么场景；完整证据仍使用各自来源引用 |
| task | 产生或使用记忆的任务归属，历史未知时不猜测 |
| internalUse | 哪些内部任务或范围可以读取和分析 |
| externalExpression | 可以向哪些对象引用或表达 |

来源场景、所有权和存储位置都不能单独充当授权。统一记忆不等于全库上下文；每次仍按任务、关联性、时间和预算选择。私聊、群聊、公开资料、工具结果和混合分析分别配置表达规则；改写、去名字或替换包装不自动扩大范围。

## 跨场景任务工作区

后续引入智能体级任务ID和版本化工作区，保存目标、约束、进度、观察链、选中证据、当前判断及变化原因、未完成事项、下一步与交付位置。一项任务可经过多个场景，多个任务可并行。

任务维持行动连续性，DSH会话维持与具体对象的交流连续性。群A回复和主人私聊汇报获得不同的任务视图。迟到结果不能覆盖其它任务。无明确任务的探索可先归属观察活动，再建立有依据的任务关系。同名任务、同名用户不自动合并身份或权限。

## 观察与记忆贡献接口

阶段B区分活动记录和记忆贡献。活动包括开始、完成、失败、未选中内容；贡献包括原文片段、摘要、发现和经验候选。应记录真实插件身份、任务/活动、来源场景、发生/观察/记录时间、内容性质、依据及覆盖范围、保留策略和建议用途。

插件负责选择策略；核心核验身份和范围；记忆插件负责来源、去重、版本、分析与关联。实际模型曝光范围与长期保存选择分开：只留下摘要，不等于摘要没有受到其它已读材料影响。保留足以支持追踪和失效处理的来源标识、版本或批次证明。

## 内部使用与表达

获准的跨场景内部分析使用独立任务上下文；具体回复只装配允许向当前对象表达的材料，不把全部私有信息塞入回复模型后再要求它保密。稳定配置和核心任务授予可以提供授权，不需每次回忆都人工确认。

内部检索先过滤读取范围，对外装配再检查表达范围。全文、BGE、关系遍历、来源回查和缓存遵守相同规则。多来源结论继承实际依赖限制；扩大范围须明确授权或独立合法依据，不能删掉来源标签。

## 经历如何影响后续任务

插件贡献 → 经历记录 → 按需独立分析和关联 → 任务认识/长期候选更新 → 后续任务召回。保存“当时判断—行动—结果—新证据—修正”，区分事实、推测、经验和未知，不把一次失败总结成永久规则。

任务开始、恢复、异常、新证据到达和任务结束可触发整理与检索。不要求每条观察调用模型。事件保留发生、观察、记录时间、程序顺序和因果关系；并行任务中的时间先后不自动成为因果。

## 来源与删除

来源身份逐步提升到智能体范围，保留渠道、账号、会话、原始对象及版本。避免同一来源经不同插件转述后绕过删除。来源变化或范围收紧时，定位跨任务/跨会话派生节点，独立内容保持。

逻辑删除保留档案并退出正常使用；恢复推进状态版本，不激活旧快照；重建仅读取当前有效且获准的原文。已经发出的消息保留历史事实，系统阻止后续继续传播，不声称能收回过去的暴露。

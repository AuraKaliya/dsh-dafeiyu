# QQ 2C-2：资源授权与选择性记忆接口检查

日期：2026-10-25；接续 `7a7f2bf`。本步实现通用核心／记忆接口，下一步2C-3再装配实际QQ能力动作。没有连接真实QQ、模型服务或服务器。

## 已实现

核心按真实v3调用对象核验所属插件和作用域。聊天只能请求实际入站会话；原生Task只能请求运行策略中显式列出的resources。资源名称、账号、昵称、模型参数和序列化的上下文都不能代替授权，Task不会被伪装为聊天。来源provider随扩展注册／卸载，资源版本变化进入来源追踪指纹，不能因缓存了“曾经有效”而放过撤回。

记忆v9追加两张观察／选择表。观察保存哈希、覆盖、来源根身份、实际操作与范围，未选择的页面正文不复制进长期记忆。DSH本身的工具历史按原机制保留，不能把“未创建memory item”解释成从未保留过工具记录。返回的来源引用是观察元信息；读取时标示metadata及rawAvailable:false。

选择none／原文／片段／摘要分开处理：原文和片段来自实际页面，摘要标为inference并携带当前请求的全部历史依赖。必须已出现在当前模型请求的来源清单中，猜到旧ID不能据此写入。选择幂等，摘要输入限制不得通过只列最终引用来缩减；同源记忆处于删除状态时阻止重新入库。恢复原记忆不会恢复旧摘要所依赖的旧状态版本。

新增可选 `memory.sourceTracking`，用于只追踪而不自动压缩的配置；旧配置保持原行为。对原生任务保持内部边界，对外表达为none；聊天记忆保持当前范围。sourceTracking缺失／历史来源不可复核时明确拒绝写入或暂不返回，不能补造证明。

同时修复v3写操作的不确定状态按null taskId跨会话扩散的问题，现按完整执行scope隔离；另保证聊天v3 operation.started先投影到Journal，再记录其观察子事件，保留因果顺序。

## 迁移

memory v1—v8递进至v9，保留原人格、记忆、来源、墓碑、任务及回执；新表初始为空。旧schema构造夹具显式移除后来添加的表，旧语义断言保留。Host预检／迁移目标／状态同步更新；状态读取仍接受旧快照中的memory v8。包发布版本与正式联合验收仍延期，不用旧程序写新库。

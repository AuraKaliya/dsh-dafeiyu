# 阶段5：统一媒体与QQ多媒体开发方案

日期：2026-10-25；基线`be31c0b`。本方案先提交，再按5A—5F开发。依据[总方案](unified-runtime-wakeup-plugin-plan.md)第11—12节、[记忆E](memory-e4-integration.md)、[自主活动](activity-4d-integration.md)与[1A适配记录](phase1a-adaptation.md)。仅本地开发；真实模型、真实平台、162次1G与发布全量回归仍延期。

## 1. 现有基础与本步范围

| 已有事实 | 本阶段工作 |
|---|---|

| 1A已实际测试Whisper tiny CPU和YAMNet ONNX；当前聊天适配未声明audio | 语音转写和关键声音事件分开处理，以带时间戳的结果接入模型；不把音频字节伪装成文字或字幕 |
| 本机PATH解析到D盘FFmpeg／ffprobe 8.1，已读取版本；已有D盘Whisper权重、YAMNet与Python运行时 | 可配置、受约束的媒体工作进程；不假定服务器具备相同依赖，不重跑真实推理来冒充新管线验收 |
| QQ在`index.ts`识别文字／at／引用，其它段只保留“不支持”说明；`OneBot.call`仅列少量接口 | 绑定实际收到的图片、语音、视频、文件描述符，按需获取和阅读；不全群自动下载／识别 |
| Reply、原生任务渲染与QQ v4交付账本为文字 | 增量增加受信媒体部件、目标材料／凭据、逐部件回执和未知效果，保留旧文字协议 |

首版提供：图片理解、音频分段转写与声音事件、视频按时间点取帧／音轨区间、普通文档的有界读取，以及QQ图片／语音／文件的接收与受控交付。B站搜索、账号和弹幕／评论读取仍是阶段6；但阶段5必须提供完整音画基础，不能用字幕代替音频。

文档首版支持UTF-8／带BOM文本、Markdown、CSV、JSON、PDF文本层、DOCX段落／表格、XLSX单元格／缓存值。扫描PDF、嵌入图片、宏、外部链接、公式重算等分别显示未覆盖，不执行。发送已有文件不等于任意文件生成能力。TTS作为可选后端，把获准最终文本合成普通系统语音；不提供克隆声音。

## 2. 责任、来源和端口

新增`@dafeiyu/media`，依赖核心实际上下文与记忆观察端口，借DSH执行独立视觉／语义分析。QQ／B站提供平台对象的解析、账号和范围核验、受控字节读取；media负责字节治理、解码／模型处理、覆盖与产物。core负责授予执行范围和交付；memory负责观察选择、长期来源和整理；activity不解释媒体、不直接发布识别结果。

| 接口 | 作用 |
|---|---|
| 注册媒体源provider | 程序绑定provider身份、资源证明、stat／read／range读取与current校验；模型不能传入任意路径、URL或请求头 |
| `MediaSourceRef` | 代表已识别的平台对象／轨道，只含受控ID、来源版本、范围和已知元信息；存在该引用不代表取得内容 |
| `MediaAssetRef` | 代表已经取得的不可变字节或派生产物，含assetId、版本、字节SHA256、实际类型、尺寸／时长、来源与范围；不把元信息hash冒充完整原片hash |
| `acquire/inspect/status/release` | 取得／检查／查询／逻辑释放；重复请求保持固定身份，半文件不变ready |
| `readImages/readAudio/readDocument` | 对实际获准材料读取有限画面、音频区间或文档页／段；输出结构化观察和明确缺口 |
| 来源／贡献接口 | 通过已有ResourceProof与CapabilityObservation记录实际曝光，选择none／原文／片段／摘要；所有实际输入限制随派生结果传播 |
| `MediaOutboundPort` | 核验目标表达范围、固定部件和最终字节，给交付端受控短期读取权；不把路径／URL交给模型 |

媒体源provider及core签发的作用域才是权限来源。模型参数中的assetId只是请求定位；每次打开、处理前后、贡献、渲染和发出部件前复核真实scope、Task epoch、账号、来源版本和资源范围。撤回、逻辑删除、权限收紧立即使旧引用无效，不等后台整理；恢复推进版本，不复活旧票据。

来源区分原图／视频帧／实际音轨／字幕／OCR／ASR／声音分类／模型解释。模型解释为推断，作者观点为转述；同一原始材料的帧、转写和摘要沿用根谱系，不增加独立证据票数。文件内容中的命令、文件名、图片文字及视频声音均不能自行更改权限或底色。

## 3. 字节与工作进程

媒体库为独立`core/media.sqlite` v1；对象和工作目录位于`core/media/`。原始资源、派生资产、处理作业、曝光、租约、回执和审计分开保存。文件先写临时文件、核验实际长度／hash／格式，再原子发布；失败和取消不发布半资产。资产元信息与文件清理保留可恢复记录。

本地测试继续全部使用D盘受管入口。媒体缓存也有独立可配置配额；初始缓存上限1 GiB、单个取得文件64 MiB、文档16 MiB、图片16 MiB且不超过1600万像素。默认工作并发1、每个处理作业120秒、工作进程内存约束512 MiB、单次读取音频最多120秒／取帧最多8张。尺寸、字节、时长、页面和输出预算是明确资源边界，不是工具调用次数上限；可以继续分段读取。

FFmpeg／ffprobe、Python、ASR模块和模型文件由配置选择固定路径／版本／hash，不由模型参数决定。不执行任意shell。Windows工作进程需使用可核验的内存／生命周期限制，配合输出大小、时间、取消、受管cwd和TMP/TEMP；约束不可用时明确拒绝相应处理，不静默转为无界进程。stderr只形成稳定诊断，不保存含临时URL或路径的原始错误文本。

只接受明确允许的容器／图片格式，不让播放器跟随任意清单或外部文件引用。视频／音频可经受控范围读取broker处理较大源：源provider仍持有真实URL／凭据，解码进程只访问一次任务的受限字节入口；限制总读取字节、范围和重定向，不把Cookie给解码器。派生片段／帧各自有实际字节hash，未取得完整原片时保留partial和读取范围。

缓存回收不删除活跃租约／固定交付引用中的文件。普通回收只改变可再次读取的可用性，不伪装成用户删除；保存下来的摘要保留当时hash、覆盖和“原字节是否仍可回查”。逻辑删除则立即阻断派生使用。保护模型权重、1A正式证据与项目文档，不把它们当临时作业清理。生产路径由最终部署方案配置，本轮不改OneBot或服务器缓存设置。

## 4. 实际模态与独立分析

### 4.1 图片与视频帧

字节格式检查和完整解码先于模型请求。记录原始尺寸、实际提供的缩放尺寸、动画是否只取首帧、帧的请求时间与实际PTS／误差。使用DSH image block与AttachmentStore；原图未进入请求时不能生成“已看过”观察。路由不声明image则拒绝相应分析，不用文件名或旁白替代图像。

已安装的DeepSeek适配器从宿主AttachmentStore取得请求字节，因此采用受限附件路由器：每个独立分析会话只注册本次获准资产的临时引用，按核心guard提供字节，结束立即撤销。不能覆盖既有不兼容附件服务或暴露主机任意路径。分析会话没有聊天历史、全局提示、工具权限或内部思考持久化。

视频读取按大肥鱼指定的时间点／区间，记录实际PTS、取样方式、数量及未覆盖部分。只看若干帧不等于看完整片；缩放后不能声称辨认未保留的细节。

### 4.2 音频与语音输出

先把实际音轨区间转为已核验的PCM，再分别运行ASR和声音事件后端。沿用1A验证过的Whisper tiny CPU／YAMNet接口作为本地适配起点；逐段时间戳映射回原音轨，保留尾部覆盖、静音、缺口、模型／词表版本。分数只按原始模型分数显示，不称概率。没有声纹／分离证据时不猜说话者身份。

本轮用脚本后端验证协议与范围，真实视觉／ASR／声音分类质量在整体完成后统一复测。历史1A真样本记录保留原义，不等于新的整条管线已经真实验收。

可选TTS只处理最终获准文本，输出与文本hash、目标材料和音色配置绑定；不能把执行器内部报告直接合成后外发。未配置时明确不可用，不冒充已发送语音，也不自动调用云服务。

### 4.3 文档

按页、段、行或工作表／单元格有界返回。压缩文档先检查成员数量、单项／合计解压大小、压缩比和允许成员，不展开任意路径；不执行宏、公式、嵌入脚本或外部关系。PDF文本层与扫描图像区分；文本层缺失给出缺口，不补造OCR。解析范围、实际输出及截断位置进入观察证明。

## 5. QQ接收、浏览与语音任务

OneBot标准包含image／record段，`get_image/get_record`可能返回本地资源路径；这不授予任意文件读取权。NapCat另提供file段及资源取得方式。实现以明确的NapCat兼容模式和严格范围为前提，使用消息数组，逐部件保留真实message_id；不把本机路径交给模型。[OneBot接口](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)、[NapCat消息兼容说明](https://napneko.github.io/develop/msg)。

QQ收到媒体时先固定账号、场景、消息ID、段序、类型和平台句柄；原始URL／路径只在受限resolver中使用，不进入Journal正文、普通缓存或模型。普通未触发群消息只登记必要元数据，不自动下载或调用模型。大肥鱼通过浏览或当前消息获得受控ID，再自行选择打开。raw silk按平台转换接口或声明的解码能力处理，不当作普通WAV。[NapCat文件处理说明](https://napneko.github.io/develop/file)。

本地文件路径必须在明确允许的OneBot缓存根内，拒绝UNC、设备路径、符号链接逃逸及越界；HTTP来源只能来自配置允许的目标，禁止凭据URL、私网绕行和任意重定向。token只发给已配置的回环OneBot。文件取得前后核验账号与资源范围；来源撤回即停用，包括解码／分析中的作业。

新增QQ媒体能力独立于渠道：列出／打开消息媒体、按需读取、选择记忆、准备回复部件。纯图片／语音消息仍能触发现有私聊规则；群内不为识别语音称呼而扫描全部音频。mainText仍是实际文字正文，引用、文件名、OCR和外部视频声音不进入主人指示字段。

直接语音任务另设可选`voiceDirectives`（兼容默认关闭）。启用后，仅当前实际主人消息的新record段、完整技术覆盖且检测到讲话的ASR结果可作为语音主输入。core固定原消息、资产／转写hash、覆盖和后端版本，从该转写按已有指示规则形成Goal；模型不能填写自由转写或sender。撤回、资产变更、转写失效沿任务祖先链阻断。带文字指示时以文字为主；引用／转发文件和视频音轨不能借此变成主人命令。普通语音交流无需这个开关，语义不清时正常讨论，不增加每条消息的人工审批。

## 6. 多媒体交付

增加带版本的ReplyParts／媒体草案：正文和image／record／file引用有固定顺序。普通回复草案绑定实际入站／Run／目标；原生任务草案绑定实际Task结果锚点。模型不提供任意目标、路径、URL或直接发送API参数。

交付前由core和media核验允许表达的资产及全部实际输入限制；memory的任务结果材料仍负责范围判断。必要时在干净目标上下文重新整理，只使用允许的原始材料，不用私有报告改写“洗成公开”。文本保真检查和媒体身份／来源／字节检查分别记录；需要识别图片内容的判断必须实际提供图像，不用hash当视觉证据。TTS只从已批准正文生成。

QQ用文字分段与媒体独立部件组成固定计划，尤其语音独立发出。每部件在发送前重验账号、目标、来源与最终字节；已确认不重发，调用后结果不明永久保留unknown，重启不重新渲染或重试。准备失败与已产生外部效果分开。文件优先使用已声明兼容的file消息段，取得真实返回ID；其它上传协议若没有相同回执能力，不伪造message_id或偷偷降级为成功。[NapCat消息段定义](https://napneko.github.io/onebot/segment)。

没有媒体的回复仍走原v1文字计划，旧D3模拟协议不改含义。新部件清单hash进入材料包、渲染确认、凭据和传输计划；换一张图、音频或文件即不再匹配旧凭据。缓存只保留带来源的交付占位／元信息，不把派生媒体内容重新当成独立原始事实。

## 7. 数据与装配

- media为可选插件，旧profile默认关闭；开启需要memory及来源跟踪、可用工作进程配置和对应policy。Host先检查路径／身份／依赖，注册media与附件服务，再打开QQ入站。停止时先停接收／新作业，取消或排空处理／交付，再撤销租约和关闭库。
- media v1为独立追加库。QQ v4→v5增加媒体源／草案元数据及版本化媒体交付记录；旧文字行、哈希、墓碑和回执保持。runtime v3→v4保存带部件hash的原生交付凭据／材料附加记录；不重写旧Run或发送旧待交付项。memory如需新媒体引用表，另行定版增量迁移，不偷换已有来源含义。
- 原Message／Reply可选字段采用带版本的媒体引用，缺字段的旧输入保持文字行为。不得从旧“不支持”占位反推图片内容、转写或实际看过的经历。
- 迁移遵循计划→完整现状核对→备份→增量应用→校验。媒体元数据、固定租约／保留资产及独立分析审计目录明确纳入清单；可重建缓存标注其限制，不宣称仅复制SQLite就备份了所有媒体。回退不能覆盖后来增长的记忆。
- 新示例全部使用虚构账号、模拟分析后端和D盘目录。真实路由／音频权重仍需最终配置核验；不下载大型新权重、不更改既有桌面或服务器profile来完成开发检查。

## 9. 进度

### 5D细分与持久化约定（2026-10-25，5C完成后核对）

1. 5D-1：QQ v4→v5追加媒体源表，固定账号／会话／消息／段序／版本与私有平台句柄；纯文字旧行、旧hash和交付表保持。v5同时预留带JSON版本的媒体草案、固定媒体交付计划和逐部件账本表，5E只启用其协议，不静默修改v5结构。先实现受控本地缓存路径／HTTPS读取及get_image／get_record／get_file适配。

私有平台句柄保留在QQ运行库的专用字段，不能进入Journal正文、普通浏览缓存、模型或检查记录；文件读取限定明确缓存根，拒绝UNC／设备路径和链接逃逸。HTTPS限定配置主机、公开地址及固定解析结果，不跟随重定向；OneBot令牌仅用于既定回环控制接口。取件前后及流式处理中复核范围／来源，失败保留稳定错误码。平台实际格式和返回结构仍需整体阶段的真实验收。

### 5D-3直接语音任务接口细化

- 5D-3a先完成程序语音证据接口：既有`dafeiyu_media_read(mode=audio)`先按正常授权读取；保存完整原音频资产、实际总时长、从0开始的完整PCM区间、ASR／声音事件版本和完整转写hash。只有两个后端技术处理完整、检测到Speech、转写非空并已在当前模型请求曝光，才能取得语音证据。部分音轨、视频音轨、字幕、普通文件和缺少总时长者不能取得此证据。
- 5D-3b再接主人任务：`qq_task_submit/control`只增加可选`voiceExposureId`定位符，不接受转写正文、sender、目标或任意证明。核心先核验实际主人与当前真实入站；程序从已登记证据取转写，并确认它对应当前消息自己的record段。非空mainText优先按原文字规则处理，不能被语音覆盖。原入站mainText保持不变。
- 语音证明进入不可变任务来源及后续控制来源，包含原消息、音频／PCM／转写hash、处理版本与观察证明。运行、续跑、修改／解决异议和交付继续核验祖先链；源撤回、原资产删除、证据失效均使旧目标失效。缓存字节回收保留当时的证据身份；恢复不复活被逻辑删除的来源。

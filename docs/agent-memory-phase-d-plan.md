# 第四步开发方案：核心授权、跨场景检索与受控对外交付

日期：2026-10-24。接续阶段C跨场景任务工作区。本阶段在本机分步实现，使用虚构场景和资料；服务器、真实QQ及私人记忆不参与自动迁移或测试。

## 目标与职责

大肥鱼在获准任务中使用不同场景的记忆，向指定对象表达时重新判断范围。DSH继续管理各聊天历史与模型循环；主插件签发任务能力、执行授权和交付校验；记忆插件负责检索、证据、版本和依赖失效；能力插件负责观察选择和实际渠道操作。

统一所有权不等于全库权限。来源场景、任务ID、主人称呼和模型理由都不能单独授予访问。加入任务的插件也不会自动获得全部任务正文。已有record boundary仍是限制：internalUse=none不能被普通任务授权绕过。

## 两层授权

稳定规则指定允许内部使用的来源场景和可选的记录白名单。受信配置/协调器按版本更新规则；模型不能创建规则。任务授权只能收窄规则，固定任务、用途、执行主体、来源集合、规则版本和有效期。规则替换或停用撤销旧版本授权的有效性；重新启用不自动恢复旧授权。

D1执行主体固定为主插件的原生任务协调器，用途固定internal。不会把跨场景读取函数注册为普通聊天工具，也不让任意能力插件通过声明executor或purpose获得权限。未来内部分析执行器需通过受控上下文入口绑定身份与曝光范围后接入。

常规任务可以由已有稳定规则自动签发短期授权；不需要每次询问主人。扩大稳定规则或表达范围必须有明确的配置/身份依据，不能由检索相关性或模型决定。

## D1：任务内部跨场景检索

授权范围 → 源权限和当前版本过滤 → 原场景内全文/BGE召回 → 跨场景合并 → 显式选择片段 → 任务内部工作区。

复用现有中文FTS5、BGE-small-zh-v1.5、token分片与完整profile。索引和向量可以是派生缓存，权限以持久授权及当前原始记录为准；缓存命中不能绕过过滤。内部索引与普通聊天检索分区，任务、授权和来源范围也相互区分。

未选结果不装配到任务。保留短期命中证明用于回查/选择，不保存完整未选正文为长期记忆。关联证据保留原来源场景、记忆状态版本、修订、原始依赖、片段范围和授权版本。内部使用不会修改原记录的externalExpression。

## D2：表达判断与交付材料（本机实现）

交付材料面向明确对象，必须同时满足目标身份、表达规则、实际输入依赖、来源有效性和版本条件。多来源结论继承所有已曝光输入的限制，不能只保留模型最终引用。

内部分析工作区与对外回复上下文分开。私有输入、内部目标、检索查询和内部结论不能未经检查进入普通回复模型。仅凭“去名字”“改写”“摘要”不放宽表达范围。

混合结论有两条可用路径：已有明确表达授权时按范围组织；或者仅从允许表达的独立证据，在干净上下文重新生成，允许结论变弱或证据不足。后一条也不能把私有结论通过问题、提示词或检索参数偷渡进去。

第一版表达规则不接受宽泛的“原文不能说但随便概括可以”。必要的有限表达以确定字段/模板或单独授权建模。模型可辅助检查，但不能自行批准权限。

## D3：交付凭据与模拟渠道闭环（本机模拟实现）

交付凭据绑定任务、工作项、渠道/账号/目标会话、选中证据、来源和授权版本、正文哈希及有效期。目标会话中的大肥鱼人格负责整理表达，执行器原始报告不直接转发。

发送前复查；生成中发生删除、撤销、版本或目标变化时，旧凭据失效。明确未发送才能按策略重试，发送状态不确定不得盲目重发。工具参数、搜索词及对外提问同样可能泄露内容，应纳入后续输出边界。

## 迁移与验收

旧数据保持既有边界，不生成默认全局授权。权限扩展使用独立版本化规则；旧的跨场景私有结果不直接改标签放行，表达接入后须重新校验并生成新结果。

来源删除、记忆修订、权限收紧或授权撤销应使相关检索、选中证据和派生结果退出。数据恢复、重新授权和重启不激活旧证明。未受影响的场景和任务继续有效；任务并发、切换与迟到机制沿用阶段C。

| 部分 | 必须验证 | 状态 |
|---|---|---|
| D1 | 跨场景允许/拒绝、缓存隔离、撤销、版本变化、派生失效、迁移、重启 | 本机实现，见[D1验收](agent-memory-phase-d1.md) |
| D2 | 混合依赖、目标表达规则、干净重建、私有提示隔离 | 本机实现，见[D2验收](agent-memory-phase-d2.md)；本轮为脚本模型验证 |
| D3 | 发送前校验、目标绑定、迟到/重复、发送不确定状态 | 本机模拟实现，见[D3验收](agent-memory-phase-d3.md)；未接入真实QQ |

真实QQ、自动内部分析和服务器部署仍需后续明确接入。本阶段没有建立第二套模型循环或消息历史系统。

# 7C人格采用缺口的修复与复验方案

2026-10-26，依据第52项真实失败及三路独立AI检查制定。本文件是后续开发方案，尚未实施下述人格接口、迁移或评分改动；当前真实矩阵保持停止，原失败不改判。本轮并行监督、operator续测判断及其36项离线测试已经完成，不能与这里尚未开发的修复混称。

## 1. 已确认的问题与本轮处置

`B02-paraphrase-2`实际将一个value-application从proposed改为trial，再发布为adopted。来源与底色边界没有被绕过，但review到publish之间没有可核的试行后选择、反证检查或采用评审材料。原生接口没有质量分数，不能把此例描述为“自评分超过阈值”。adopted不自动等于永久稳定人格，但也不能继续称数据库状态仍为trial。

现有`real-boundary.ts`仅比较adopted集合前后是否相同，无法判断变化是否有依据；它需要修正，但删除此检查或按kind一律放宽会掩盖产品门槛缺口。因此本次保留failed，不增加B02的续测豁免，不重抽到通过。新候选完成以下工程条件和校准前，不继续付费运行旧候选。

证据见[实际写入链](reviews/7c-b02-persona-write-evidence.md)、[标准口径](reviews/7c-b02-criteria-review.md)、[产品门槛](reviews/7c-b02-growth-policy-review.md)。三者是AI诊断，不是人工最终验收。

## 2. 保持的人格设计

- 大肥鱼继续自主提出、试行、采用或撤下认识，不增加日常逐项真人审批或第二模型强制批准。
- 不以固定天数、固定次数或固定独立根数量机械判断成长；一次有分量的经历可以支持修订。
- 提出候选、试行中的当前选择、采用为阶段条目、认识成熟程度分开表达。采用不表示永久不变，试行也不应被迫先发布为adopted才能进入下一轮上下文。
- 虚构作品和假设材料可以支持范围明确的反思，不能变成真实亲历、已验证行为效果或全局事实。自述、摘要和反思不增加独立根。
- 爱世界的底色、权限、任务约定、来源隔离与撤回规则继续由程序保护。情绪、回避、反击或不同意见本身不构成污染。

## 3. 共同接口与数据流

在`contracts/persona.ts`和memory共同写入边界加入以下受版本控制的对象；工具的模型输入只提交引用与可见理由，身份、Run、范围、发生顺序和真实结果由core填充或核验，不能由模型自报。

| 对象 | 必需信息与约束 |
|---|---|
| TrialSelection | 候选精确ID／版本、当前scope、选择版本、适用条件及退出条件；只接受trial。与adopted选择分开，不提升阶段成熟度。 |
| TrialOutcome | 受信trial选择／装配记录、已结束的Run或操作、可见结果hash／合法来源引用、效果状态与覆盖缺口；不能仅引用propose/review/publish自己的回执或同一句自述当试行成功。 |
| AdoptionReview | 候选精确版本、trial结果引用、支持与反证引用、反证检查状态（已找到／未取得／未知及理由）、原动机、实际选择、结论范围、拟采用成熟度、局限、策略版本；不可变、可回查。 |
| AdoptionDecision | 评审ID／hash、当前依赖验证结果、允许／held及机器可解释原因、stage与selection版本。它证明资格检查，不能伪称程序已证明语义真实。 |

`PersonaProvider.prepare`与core Run清单显式区分trial投影和adopted投影；trial正文标为暂定，仍继承全部来源和表达限制，不授予指令权限。core只记录实际装配与结束结果；仅调用“开始试行”不产生完成证明。对于纯对话中的选择，以真实提交的可见输出和相应回合结束记录为依据，不保存内部思考。

采用前必须有真实发生顺序：trial选择／使用→已闭合结果→复核。不能用状态标签往返代替这个顺序；也不以“必须隔一天”或“必须另开固定数量会话”充当充分性判断。若某次操作已形成完整、可核的试行结果，可在合法范围内及时复核；当前未结束输出不能提前被引用为完成证据。

publish由共享`PersonaStore`核验review绑定、精确版本、来源当前有效性、范围、试行结果资格、动机、反证缺口和影响面，再原子写候选／stage／selection／幂等回执／outbox。没有合格评审则返回已分类的`PERSONA_ADOPTION_REVIEW_REQUIRED`或`PERSONA_TRIAL_EVIDENCE_REQUIRED`，保持原trial状态；不产生副作用unknown。过期评审或来源撤回拒绝采用，不能只重新发同一requestId绕过。

`PersonaMaterial`须携带受信来源性质、coverage、completeness和谱系，不能只有text及root数组。来源性质由存储／渠道适配器赋予，不从模型reason中的“真实”“虚构”关键词决定。未取得的音画仍未知；真实选择和现实效果分开，回执只证明它实际能证明的部分。

成熟度首版使用tentative／established及legacy-unclassified的显式语义，避免浮点置信分伪装可靠性概率。稳定关系和长期习惯需更充分、与范围相符的证据及反证说明；不能把一条partial虚构样本直接声明为既成长期亲历。程序校验资格与可追溯范围，语义是否充分仍需独立评阅，不能承诺用Schema完全解决模型幻觉。

原生persona和maintenance均调用同一个资格策略。任务动机是实际接触背景，不能被模型改写为自主探索；任务中可以学到东西，但受托立场或仅完成任务不直接证明自己的稳定偏好。maintenance已有的动机限制不能只存在于一个旁路入口；不要简单地让所有explicit-task候选一律不可提出或试行。

## 4. 迁移与兼容

当前主记忆库最高版本为11（`migrate-experience.ts`）；下一次迁移在实施时从核实的当前版本递增，计划新增trial选择／结果、采用复核／决定及依赖索引表。新增记录保持不可变；每次修改追加版本，不更新旧候选revision正文和hash。

既有schemaVersion1候选、stage和回执继续可读，原adopted和真实历史不得删除、回填虚假试行证据或自动提升成熟度。读取时明确其采用依据为legacy-unclassified；新采用、重采用或修订必须走新资格门槛。对当前场景的兼容投影仍执行原有来源验证和可见范围，不能因迁移放宽权限。无证据字段不默认为“已验证”。

新命令采用strict schema、expectedVersion和requestId。旧publish形状可以解析并返回明确的缺评审状态，不能静默按旧规则发布；旧幂等回执保留原意且不触发新的写入。旧读端口与新字段兼容需要契约测试，不通过新增全局开关绕过共同门槛。

只用本地虚构迁移库验证。正式7C库和95份封存attempt不迁移成新候选证据；新候选可以使用同一总账本追加新尝试，但必须新建独立profile／基线并保留原身份。服务器及其后续真实记忆不在本方案实施操作范围内。

源码实现、测试补充、证据／预算审查可以由不同子代理分工。相关离线文件由一个协调者单次构建后交现有受管driver并行执行，各子代理分别检查结果；不能多个入口竞争lib或清理锁。真实执行继续唯一账本，不把本修复顺带改造成双并发。

重点相关测试为persona-state、persona-foundation-migration、experience-persona-basis、memory-maintenance及其事件、core人格装配／执行和迁移测试；新增试行／采用契约的独立用例。依据实际改动选择文件，不默认全量回归。全量仍在部署／发布阶段。

## 6. 旧问题及复验标准

R1—R5不能冒充同时修复了B05、B07或H05。B05另需补齐实体材料、对齐真实任务识别、区分参数错误与材料退役并统一event/source引用；B07需把未完成部分与任务状态接通；H05需验证最终回答事实覆盖，不能误修已保留事实的压缩层。分别实施并留下独立候选／影响记录，避免混合改动后无法归因。

工程门槛：无合格复核材料的publish不落stage／selection；trial可实际使用且标记暂定；具有合法试行与复核的采用不被一律拒绝；同源反思不增票，虚构材料不变亲历，反证未知不写成不存在；两类入口一致；旧数据完整、撤回及时、幂等不重复、无权限扩张。

语义门槛：继续原底色、独立判断与任务执行边界；把“正在试行”“已采用但仍暂定”“稳定认识”说准确。程序检查和AI预审仍不代替人工确认。本次52项没有任何人工终判，不能宣称最终通过。

共享persona路径改变会影响所有B类及H03；若来源、投影或统一原生提示改变，应覆盖受影响的全部H，统一提示变化按原计划重新处理162项。现有H01／H05单文件scope证书不能用于新修改。不得把旧通过结果重新标成新候选已验，也不因原矩阵已跑部分而削减新候选所需检查。

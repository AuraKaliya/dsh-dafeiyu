# 本地开发、版本与部署约定

## 仓库与环境

本仓库独立于“蓝色大肥鱼管理中心”和服务器 `C:\DSH\DaFeiYu` 的既有Git历史。使用npm workspaces统一版本管理，main保持本地检查通过的版本；后续功能在功能分支开发，通过后合并并以发布标签标记部署版本。

依赖以package-lock锁定，不依赖本机另一个源码仓库中的未提交改动。DSH适配基线0.2.1-rc.2，Cordis4.0.5。Node开发基线24.13.0。更换DSH版本必须跑会话恢复和工具生命周期测试，不仅做类型检查。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test -- build-tests/qq.test.js build-tests/qq-cache.test.js
git diff --check
```

上例针对QQ缓存改动，实际测试文件按改动范围选择。测试与demo不使用API密钥。profiles/persona.test.md为可公开审阅的虚构样本。运行数据默认不入Git。首次真实模型验收要单独配置测试实例，不能将模拟结果当作真实模型验收。

2026-10-25按用户修订：**开发阶段只运行本次改动相关测试，部署／发布阶段才运行全量回归**。例如 `npm.cmd test -- build-tests/qq.test.js build-tests/qq-cache.test.js`；无文件参数的 `npm.cmd test`用于全量回归。记录实际选择的范围及未覆盖项，不能把定向通过写成全量通过。

开发检查包含新增／修改行为、直接调用方与接口兼容风险；此前已有的无关测试不重跑。受管入口仍执行类型构建，执行用例限定为所选文件。失败修复后只复测相关范围；已有检查通过且代码未再变化时不为凑次数重复运行。共享接口影响多个插件时，选择实际受影响的集成检查并说明原因。发布／部署前再运行完整用例集，真实模型和平台验收仍按已批准的范围、样本与预算单独进行。

测试仍必须通过上述受管入口。临时目录和子进程环境统一隔离到D盘 `.runtime/tests/`，成功自动清理，失败最多3次／72小时／合计1 GiB。直接运行依赖临时夹具的旧 `node --test` 命令会拒绝创建目录。清理失败会使本次入口失败；运行报告在 `.runtime/test-reports/`，正式验收材料另行保留。详见[测试临时文件治理](test-storage-governance.md)。

## 当前布局

`packages/*/src`源码；`packages/*/lib`构建输出；`tests`真实DSH服务集成测试；`build-tests`编译后的验收驱动；`scripts/demo.mjs`演示；`.runtime`本地运行数据；`docs`架构及验收记录。

接口变化优先在contracts中说明，并同时更新消费者。原始凭据不出现在插件参数样本、异常审计或Git提交中。接入真实外部服务时另行审查其原始会话日志脱敏与保留策略。

## 测试层级

1. 单模块：字段校验、去重、状态原子性、时序、占用。
2. 本地集成：真实DSH + 模拟模型 + 模拟渠道，包括工具执行及重启恢复。
3. 后续真实模型与QQ测试：独立账号、测试群、独立DSH数据目录。
4. 后续服务器候选环境：路径、权限、运行版本、健康状态与回退。

服务器上线前仍需环境验收。本机通过不等于服务器或QQ验收通过。

## 后续部署原则（本轮不执行）

- 从确定的Git提交生成部署包，附版本、依赖和文件校验值、测试记录。
- 核对服务器最新文件、Git差异和自主更新状态，禁止用本地旧快照覆盖。
- 继续利用已有更新守护，但先验证新插件组合和健康条件是否被支持。
- 旧、新入口不能同时消费并回复同一账号消息；切换前明确停用及回退路径。
- 私人记忆、聊天归档、登录凭据与运行状态不随代码回滚或初始化。
- 服务器现有Git保存运行与增量日志；新源码提交编号写入部署记录进行关联。
- 大肥鱼自主更新产生的有效修改，以提交或补丁回流源码仓库，避免双向覆盖。

远端仓库、CI服务与正式发布标签策略尚未选定。本轮只建立本地Git并提交第一阶段成果，不创建远端、不推送、不部署。

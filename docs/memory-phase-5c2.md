# M5C第二部分：独立分片、局部视图与简短引用

日期：2026-10-24。项目0.11.0，contracts/core/memory/timeline为0.8.0。只在本机使用虚构中文样本，未连接或修改服务器，也未接入真实QQ。本阶段没有开启跨检查点多代摘要合并。

## 分片的生成边界

主插件先按实际输入依赖和原轮次登记的任务划分连续输入组。不同依赖集合或不同任务不放入同一次摘要调用；每组独立使用DSH LLM通道。当前人格、工作任务、近期尾部、工具调用对、其他插件区域与已存在摘要仍受保护。

模型返回`fragments`数组，每项包含kind与text，一项表达一个完整事实、决定、约束、更正、待办、证据缺口或结果；不能拆掉条件、否定或不确定性。支持旧摘要器返回一个summary字段，将其作为单个保守片段处理。模型不能提供或缩小依赖字段。

同一输入组生成的所有片段继承该组全部实际依赖。语义上拆成两句话不等于证明依赖独立；混合输入中的A、B无法可靠分离时，两条分片仍一起依赖A、B。当前实现不声称已自动证明每句话的语义因果。

新增预算参数`maxFragmentGroups`默认8、最大8，`maxFragments`默认16、最大32。总文本仍受既有maxSummaryChars限制，均分给本次输入组；输入组数量还受每组至少64字的预算条件约束。超过分片数量、文本或证明容量会拒绝初始提交，不截断依赖。它们约束一次压缩工作量，不限制普通工具调用次数。

每个输入组最多一次辅助模型请求，顺序执行以控制资源。任一组失败或来源变化时，本次初始检查点不提交，保留仍有效原文并退出已失效内容。真实模型的摘要保真率、延迟及推理token预算仍需后续验收。

## 完整证明与模型视图分开

DSH日志保存两个新插件记录：

| 记录 | 内容 |
|---|---|
| summary-manifest | 会话、所有者、模型与策略版本、原文seq/哈希、输入组任务与完整依赖、稳定分片编号和正文 |
| summary-view | 视图版本、上一视图和上一检查点位置、当前有效分片编号、展示内容哈希 |

主模型只看到schemaVersion 3的简短内容：摘要包短引用，以及各片段的短引用、kind和text。原文哈希、完整依赖、作用域和版本集合不再自动放入新摘要的模型可见文本。

短引用采用`S…-….F…`形式，包含当前DSH会话与摘要身份派生的命名空间。完整证明仍在追加日志中，可按需回查；短引用不是权限凭证。每次使用都核对当前会话、来源状态、原文哈希、依赖并集和已提交视图链。

## 同一检查点内局部退出

来源变化时只筛掉受影响的有效分片编号。未受影响片段的编号、引用、kind和正文逐字保留，不调用模型重新摘要。视图版本只允许有效集合单调减少，不能通过新视图把旧编号重新加入。

这是活动视图的局部替换：底层DSH用户消息可以获得新消息id，但逻辑摘要包引用与保留片段引用不变。无效片段不会原位改成新事实；重新生成内容需要新合法输入与新身份，旧引用保持失效。来源恢复也不会自动恢复旧片段。

初始检查点仍使用DSH的compaction/start、summary、compact-checkpoint和end。后续局部退出使用compaction/prune与受控`dafeiyu-summary-view`消息，连接到原检查点，不冒充新的语义压缩事务。退出后的视图会在模型请求前flush；失败则阻止发送，不回退到包含失效内容的旧视图。

原生runtime区域、其他插件区域和人格不在替换范围内。工具配对保护、原文归档和不重放操作规则继续生效。整个包失效时保留一个无正文的空视图及原始证明，不物理删除数据。

## 短引用回查

沿用`dafeiyu_source_open`：传摘要包短引用可查看当前有效内容的证明，传带.F编号的引用只查看该片段及其输入组证明。返回原文来源链接，可继续使用同一工具回查。

返回值带视图revision及绑定该版本的ref（末尾`@版本`）。分页必须沿用返回ref与nextOffset；视图变化返回stale_reference，不能把新旧分页拼在一起。来源链接通过稳定的、会话内的派生索引事件产生，不因重复读取改变分页文本或哈希。

跨会话引用返回not_found；失效片段不通过正常短引用导出。旧整包DSH来源如果包含已失效内容，也不直接导出，使用当前短引用查看有效部分。证明回查是derived-only证据，仅供当轮使用，不自动形成新记忆或积累到后续聊天。

## 恢复与校验

读者只承认完整初始检查点及与实际替换消息绑定的视图更新。缺少替换消息的孤立视图记录会被忽略，恢复后重新校验权威来源；实际提交但违反父视图关系、内容哈希或单调退出规则的记录会使该包停止导出，不能猜测或退回旧视图。

完整输入证明仍由代码计算和核验。新的模型回答继承实际看到的全部有效分片依赖；模型只提到B，并不能让曾看到A+B的回答摆脱A依赖。退出A后，后续仅看到B的新回答只继承当前有效输入。

这次也补齐了DSH在接收本轮输入之前执行pre-step时的预算预留：阈值检查会计入尚未进入历史的当前输入，但该输入不会成为压缩材料。

## 兼容与剩余范围

v1/v2旧摘要继续按原规则验证，不自动猜测语义分片，原有完整证明暂时仍在旧视图中。新生成检查点才采用分离结构；旧格式的迁移和跨代合并不在本次范围。旧版插件二进制不保证理解新插件记录，不能把Git代码回退当作数据迁移。

本阶段没有新增图数据库或模型进程。证明索引保存在可重建的会话内缓存中，每个manifest最多8组、32片、单组4096项依赖且整个证明最多2MiB。日志规模、长会话性能与2GB部署预算尚需专项测试；主模型输入减少不等于磁盘证明也减少。

## 本机验收

新增19项专项测试覆盖：隔离输入、分片局部退出、稳定引用、删除/恢复、当前任务保护、跨会话拒绝、证明分页和过期引用、原文回查、其他插件区域、正常重启、孤立写入恢复、非法重加、证明缺失、flush失败、单轮证明视图、伪造上下文及输出预算拒绝。

`npm test`全量250项通过，原有`demo:compaction`和`demo:provenance`兼容演示也通过。

`npm run demo:fragments`的虚构样本将同一检查点的8片减为3片，无模型重算且保留部分的引用和正文不变。摘要区模型可见文本从等价C1内联证明形式的2,600字节降为838字节，减少67.8%；DSH启发式估算从620降为179 token。完整私有manifest为5,949字节，仍保留在日志。

这些数字只比较相同摘要正文的两种包装，不是整个会话的缩减比例或模型实际计费token；更不是实际摘要质量验收。结果见[memory-phase-5c2-results.json](memory-phase-5c2-results.json)。测试使用真实DSH装配、持久化和恢复机制，模型输出由脚本控制。

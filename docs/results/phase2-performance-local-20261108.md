## 实际修复

- DSH 归档与证明文件复用经过校验的解析结果。原来八条缓存遇到几十条交叉引用时会反复淘汰；现按每类 128 条、8 MiB 控制，并逐次检查文件身份、大小、时间戳和原摘要。归档发布仍保持 UTF-8、原子且不覆盖已有回执。
- 观察库只缓存不可变行，保留身份与范围隔离、实时验证器调用和外部提交失效检查。事务内的新读行不进入缓存，避免回滚后出现不存在的来源。公开返回值与内部缓存分离，调用方不能修改缓存。
- SDK 已冻结历史记录复用解码结果，减少重复 Zod 解析和垃圾回收；弱引用不延长 SDK 历史对象寿命。当前权限、撤权、过期及任务意图检查继续独立执行。
- 整段纯同步材料构建使用已有 `readSources` 批次，共同祖先在批次内复用已验证结果；不跨异步边界或发送动作缓存权限结论。发送前仍独立检查来源。
- 在材料准备、人格准备、发送队列等阶段之间让出事件循环；连续缓冲流按处理时间让出，使计时器和取消请求能够执行。恢复执行后重新检查，正常输出顺序和源异常保持，取消会关闭源迭代器。

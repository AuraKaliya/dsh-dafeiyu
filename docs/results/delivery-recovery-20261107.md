# 0.28.8 生成与核验阶段交付恢复验证

开发批次：2026-11-07。记录更新：2026-11-08（北京时间）。实现修订：`38d81f9c43b94db9ac22414ff250031f507ff51e`。版本 0.28.8 / API 8，runtime 存储仍为 v5。

**在原任务授权、材料版本及交付有效期仍有效的范围内，两条已复现的交付续办缺口已修复。** 生成中断后可用原材料继续生成；核验中断后复用同一候选和证据继续核验。Task、Run 和交付 ID 保持，已完成的业务读取不重做，确认送达后重启或重复请求不重发。

本轮仅进行本地确定性与隔离验证，没有启动付费模型测试、真实 QQ/B站外发或部署。过期授权续期、任意发送失败重试和整轮修正版验收不在本次通过范围内。

## 实现

- 增加共享恢复请求、回执及状态契约。管理中心使用交付版本提交 `resume-delivery`；主人已有任务的 `continue/retry` 和控制 `resume` 转到同一恢复入口。状态询问和普通重复交付仍不启动恢复。
- 恢复请求、开始、结算复用不可变运行事件，保留原错误和版本；不清空材料、锚点或候选，不新建业务任务。没有新增存储表或手改库版本，不需要本次结构迁移。
- 生成使用新的生成会话，避免复用已经存在的失败会话；核验按持久引用读回原候选。三稿计数和拒绝反馈跨恢复、跨重启保留，不能靠换 requestId 获得第四稿。
- 受理与执行分别校验当前任务和消息来源，模型调用和发送前继续校验材料。取消或撤权发生在受理之后也会阻止恢复。
- 尚未结算的已授权恢复可跨停机继续。已经批准且确定未开始发送的正文保留 `ready`；发送已开始则沿用原未知回执保护，不重新发送。
- 管理中心分开显示业务结果与交付；生成结果不被标成已核验或已送达。失败通知的请求归入 `feedback`，避免误算为结果生成。
- 发布源码快照同步包含新验收入口、夹具及恢复回归。没有本仓库 Git 元数据时，验收清单以内容摘要标识源码，修订为 null，不借用外层仓库修订。

完整条件及接口见[交付恢复契约](../plans/delivery-recovery-contract-20261107.md)。

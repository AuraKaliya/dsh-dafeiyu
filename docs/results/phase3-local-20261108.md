## 已复现缺口与修复

新增组合最初发现：生成和核验已完成、正文获准后，群退出能暂时拦住发送，但重新加入同一群后，旧证明仍可能通过，导致未发送部分继续外发。发送前撤权样本出现 2 条旧结果重新发送，分段间撤权样本出现旧第二段续发。这是运行代码缺口，不是模型误判。

QQ 观察证明现在使用提供方 v2 结构，将缓存证明与群授权代次共同绑定。成员信息的持久修订进入权限缓存标识，主人私聊中的跨群材料也能发现代次变化；无需逐群重复扫描生成代次列表。异步历史/转发读取在返回后核对开始时的代次，不能把跨越撤权窗口的响应绑定为新授权。

群媒体来源的不可变正文同样记录授权代次。退出重入后，旧引用及冻结导出仍失效；当前授权下的新接收/取得产生不同来源版本，旧版本不会随之恢复。媒体列表只提供当前有效引用。原始记录、历史和已确认发送均保留，没有回填授权或清库。

兼容边界：旧 v1 群文字证明只有在各消息的原代次可核对时才继续有效；缺少代次的旧群媒体引用不直接续发。源数据仍在，必要时需在当前授权下重新取得来源。结构版本未改变，不新增数据库迁移；旧程序遇到新证明会拒绝，回退仍应使用匹配的程序与备份。

## 组合链路

完整 C1 样本只读取一次群材料。先注入生成服务失败，重启后恢复生成；再注入核验服务失败，恢复时核验同一候选和证据。一次明确的事实拒绝才触发修稿，未批准正文没有进入渠道。获准的两段正文发送第一段后中断；重启和显式续发仅发送剩余段，不再生成或核验正文。同 Task、Run 和交付 ID 保持。

相邻分支分别验证：第二段回执未知后不重试；主人取消后旧恢复入口失效；主人修订后同 Task 的新代次只交付新结果；各撤权窗口及重新入群均不能使旧结果恢复；媒体首段确认后重启并撤销来源，剩余文件不外发、不重新获取，也不新增模型请求。

插话通过原渠道入站，控制通过任务工具执行。发送中断先释放原队列，再处理取消/修订，避免占有发送队列时等待同队列控制消息造成死锁。测试使用真实 Core、SDK、持久库及 QQ 分段发送器，平台发送由隔离回调替代。

## 修复范围

| 优先项 | 最终实现与验证 |
| --- | --- |
| 指定群发送表情 | 新增任务阶段external-write工具qq_sticker_send。由核心校验真实主人私聊任务；目标来自该条原文的群名/群号，或“那个群”所指的最近明确主人上文。歧义、冲突、否定指令和非主人来源拒绝执行。模型参数不能扩大目标。 |
| 表情使用范围 | 允许主人来源私聊中的表情在本次明确指令中发送到该群，保留conversation范围，不自动升级global。不借用其他会话的私有表情。一般任意文字群发送不在此新工具范围内。 |
| 发送效果与重复 | 发送前持久记录claim，原入站指令最多发送一次。返回实际群目标、表情ID、版本及平台回执；未知、崩溃中断或损坏账本保持未知，不因新requestId再次发送。群授权代次、源指令、表情版本与状态在发送前再次检查。 |
| 交付证据 | 最终材料保留表情目录、选择身份、当前目标及真实发送回执；阻断记录保留category、reason与actions，并标注为执行器判断。已选图片、私聊预览、群发送成功分别表达，缺少回执不写成成功。 |
| 图片理解到收录 | 同一QQ消息/转发中的不同图片来源可放进一次视觉请求。每张来源分别授权、保存和检查，观察记录绑定全部资产来源；撤销其中一个来源会使整组观察失效。用exposureId及imageIndex直接取得对应原图/GIF，单图images观察可省略序号，不必改用image重新识图。 |
| 错误反馈 | mode=image误传sources/assets时，明确指出字段和正确source/asset用法；批量观察漏填图片序号时提示复用原exposureId。图片分组/序号等输入错误不再建立30分钟资源暂停。 |
| 耗时 | 减少重复识图和纠错往返；核验优先选择模型明确支持的off档，其次low，未提供这些档位时沿用模型配置。事实核验、受限重试、撤权和失败恢复仍保留。 |

单次群发表情发送库内已核验原字节，不生成自由文本或任意媒体下载地址。群发送回执独立保存在实例QQ数据目录的 `direct-sends/`，需连同原数据库一起备份；最终给主人回报的私聊消息仍走原交付流程。

自有包与内部依赖统一升级为0.28.15，API升级为11以同步媒体收录序号契约，旧API模块不混装。SQLite结构版本保持：runtime v7、B站v6、QQ v8、Media/Activity v4。未修改既有用户库或账号设置。

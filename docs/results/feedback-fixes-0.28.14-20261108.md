# 0.28.14 实机反馈修复与回归

完成时间：2026-11-08 22:09（Asia/Shanghai），早于本轮23:50截止时间。

本轮按用户指定顺序修复群历史与合并转发读取、重复无效调用、连续消息处理、回复拆分。源码及独立发布包已完成；没有切换当前 DSH profile、修改本机实例配置、迁移在线数据或重启在线实例。真实模型和真实平台复验未执行。

## 修复结果

| 问题 | 本轮行为 |
| --- | --- |
| 群历史被24小时窗口全部过滤 | 主动 `qq_browse` 默认 `historyMode=latest`，按最近最多100条补取；缓存按实际消息时间分页。`recent` 模式才应用配置窗口，平台与缓存使用一致窗口。返回账号、会话、窗口和未来时间的分别计数。 |
| 新转发包含旧节点或缺失时间，无法读取 | 不以节点年龄或缺失时间拒绝材料；时间不明保持null，未来时间明确标记。按offset分页，默认8节点，保留原节点序号。index仅表示转发附件编号。 |
| 转发后续页丢图或使前面图片失效 | 每页最多暴露8个媒体段，额度不足时下一页从尚未处理的节点继续；不同节点的图片位置范围独立保留，撤回包装消息仍使全部来源失效。单个节点超出8个媒体段时报告mediaOmitted，不宣称完整读取。 |
| 多目标场景反复漏填target | 有真实入站来源时默认绑定当前聊天，跨群仍需明确target；合并消息中可定位实际转发原消息。没有唯一来源的任务仍要求明确目标。 |
| 同一转发重复请求 | 实际平台副本在60秒内复用；每次仍核对当前来源、账号状态、群授权代次，撤回和授权变化不会被缓存绕过。 |
| 评论续页重复携带aid导致本地拒绝 | 接受与存储游标一致的重复aid；冲突视频仍拒绝，续页位置由经过任务绑定校验的游标决定。 |
| 本地参数错误丢失细节、不计入重复失败 | 返回字段级修正提示和dispatched=false，并记入操作账本。相同无效只读参数即使更换requestId，也进入已有的短期重复失败抑制。 |
| 忙碌时连续补充逐条排队重做 | 前一轮执行或发送期间，同一发送者的后续消息继续持久合并，空闲后结合全部要求处理；原消息顺序、来源、撤回、分批容量和明确控制入口保持。 |
| 短回复被按句拆成多条 | 普通短正文保持一条；显式消息序列和超过800字符的传输拆分仍可用。已保存的发送计划与已确认回执不重新分段。默认表达提示同步改为一条简短消息。 |

修改了提供方、工具声明、主流程、管理字段说明、当前文档、测试及发布源文件清单。`npm run build` 已重新生成管理目录、提示词预览和管理客户端。根目录、自有15个包、内部依赖及依赖锁统一为0.28.14；API仍为10，数据库结构不变。

## 已实现的部分

- 新增TaskRepository适配器，复用原Task ID、version和epoch；Task请求与Run通过稳定请求ID跨库补齐。
- 新增原生执行端口，支持内部Task受理、状态、显式暂停／取消／续接、受信唤醒生产者及机会去重。TaskRef／RunRef和运行中的能力上下文使用内存身份校验。
- 任务输入使用DSH的`dafeiyu-execution`来源，不构造Conversation或PendingMessage，不自动发送结果。任务与聊天共享Agent开启、回合结束、持久化和结果核验的实现。
- v3结构化动作按明确策略开放；模型不能指定执行身份或来源范围。操作回执先入账，再处理取消或权限失效；续接不自动重做已确认的同一写入。
- managed聊天增加Run→Journal的结果投影；跨库丢确认时先核验DSH结果再补齐reply-ready，之后仍走原渠道交付流程。
- managed流过滤reasoning／opaque replay；完整可见块检查后才输出内容，已知敏感内容不会因跨delta拆分提前落盘。legacy旧历史不改写。
- 增加可选的内部Task事件读取适配，独立于旧conversation时间线；这一新适配尚需补齐专项验收。

DSH已安装版本仅支持部分JSON Schema关键词。现在注册时检查传输兼容性，把数值／长度等约束同时告知模型，并保留执行端Zod强校验；不通过移除执行端检查接受不合法参数。无法明确映射的结构在注册时拒绝。

# 记忆插件第三阶段：独立分析、候选与自动提交

日期：2026-10-23。项目0.6.0，记忆插件0.3.0。仅本机开发，全部测试材料为虚构中文样本；未连接或修改服务器，也未加载到本机真实QQ实例。

本轮落实方案v1.3中用户指定的第三阶段主体：独立分析任务、结构化结论、记忆候选、自动提交。模型循环继续使用DSH。没有自动上下文注入、关系图更新、定时扫描或压缩装配。

## 1. 运行边界

主插件从当前活动操作签发持久分析授权，绑定agent、会话route、原消息trace和独立operation。后台不保留已经结束的ActionContext。来源读取、模型调用前及提交前重新检查授权；完成或取消后撤销授权。调用者不能通过工具参数选择其它会话或模型。

每次分析尝试创建新的`memory-analysis-…` DSH会话，使用独立的AgentRegistry、Prompt、Tools、SessionStore、Projection和JSONL持久化。只代理宿主当前模型适配器，不继承人格提示词、主聊天历史或全局工具；没有QQ发送、命令执行和文件读取工具。后台使用单工作者，默认最多20项待处理任务，每项默认120秒超时，参数可配置。这是排队和时间预算，不是聊天工具调用次数上限。

当前路由从核心配置读取。真实验收启动前核对本机DSH desktop配置，实际为`deepseek-official / deepseek-flash / max`。持久任务记录该路由；恢复时路由变更则失败退出，避免悄悄换模型。服务绑定发生变化后应按DSH正常配置生命周期重载。

这里的“独立”指模型输入、工具集合、任务生命周期与会话存储隔离，暂时仍在同一个Node进程。方案中的独立操作系统工作进程尚未实现，也不宣称具备恶意插件沙箱隔离。

## 2. 输入与输出

提交参数：`requestId`、1到8个`sourceRefs`、可选0到8个`targetIds`。来源必须通过当前会话的时间线回查，或当前有效记忆引用取得；拒绝已删除、过期、派生分析/摘要/助手输出冒充的新证据。输入按完整来源分页读取并核对哈希，单来源上限12000字符，来源加目标正文合计24000字符；超限明确失败，不静默截断。

任务保存授权、模型路由、来源文本与哈希、来源记忆版本、目标版本、范围generation、任务状态和尝试次数。原始消息保留发言者身份；候选中的“我”不会脱离来源，自动保存时由程序加上陈述者标识。

结构化分析包含：

- `schemaVersion`、简短`overview`、证据缺口`gaps`。
- 最多12条`claims`，区分新增、更正、不更新，及经历/知识/偏好/流程。
- 主张类别：观察、自述、转述、推测；主题、候选正文、明确性、长期/临时/不确定。
- 支持与反证的`sourceId + quote`，以及歧义和更正目标。

严格校验JSON结构和字段范围。虚构来源编号、引用不属于输入原文、额外执行字段等使结果失败。程序决定权限和可写状态；模型不能指定route、放宽删除过滤或提交任意工具操作。引用核验只证明“原文确实包含该片段”，并不证明陈述在现实中为真。

模型流中的reasoning块与不透明replay数据在进入独立DSH会话前丢弃；仅保存公开的结构化结论和使用量，不保存内部思考。插件审计只含任务标识、状态、计数与因果关联，不复制分析正文或来源内容。

## 3. 自动提交规则：literal-evidence-v1

本版优先降低误写风险，自动保存的是带归属的原文自述。

| 条件 | 处理 |
|---|---|
| 单一原始用户来源，完整原文与支持引用及候选正文一致，明确、长期、无歧义/反证 | 可新增 |
| 同一发言者明确更正给定目标，主题同时出现在新旧正文，目标版本仍有效 | 新内容版本，保留旧版本和来源 |
| 正文已存在 | 标记duplicate，不新增 |
| 已有同主题记忆但未形成有效更正 | 留候选，要求比较，避免静默新增冲突 |
| 改写、片段截取、推测、工具观察、转述、多来源综合、时间/主体不确定 | needs_review，本版不自动提交 |
| 玩笑、假设、临时限制、不让记忆等已识别表述 | needs_review或模型不生成候选 |
| 引用伪造、来源不可见、来源删除、版本竞争 | 失败或stale，不写入 |

自述仅表示“该发言者这样说过”。没有外部独立核实由`self_report`表达，不强制要求每条自述先获外部证明。真实验收初次发现模型把这一点作为歧义、又在更正时删掉“更正：”前缀；随后明确了提示词，保持程序的完整原文校验规则不放宽。

自动规则并不能证明模型的所有语义分类正确；关键词过滤也不是完整语言理解。因此改写和复杂综合暂留候选，本版没有候选批准/编辑界面。需要调整时可重新提交新证据，或通过既有显式记忆更正接口处理，不要求用户批准每次符合规则的普通写入。

## 4. 版本、删除与恢复

任务基于当前会话记忆generation快照。分析期间任何该范围的记忆变化，都会保守地让旧任务发生版本冲突；当前不自动重新解释或合并。单任务多候选提交时只按自身提交回执递增基线，不能吸收并发外部变化。最终写入在SQLite事务内再次检查generation和目标expectedVersion。

逻辑删除仍保留正文、旧版本和专门查询/恢复能力。自动分析额外检查来源删除屏障：被删除记录及其派生依赖使用过的相同来源哈希，不能自动重新提炼；原来源档案仍然保留。这是分析资格限制，不是删除整条聊天档案。来源明确恢复后才解除对应限制；历史中的其它删除依赖仍然有效。

分析结果显式打开时再次验证来源、目标和已提交结果的删除状态，阻止从分析副本读出已删除内容。分析任务状态与计数仍可查询。完整被屏蔽分析报告目前没有额外的“已删除分析报告”查询工具；已删除长期记忆仍使用第一阶段专门接口。原文级删除覆盖和已有主聊天上下文回收继续属于后续范围。

## 5. 持久任务与故障恢复

`analysis.sqlite`保存队列、结构化结果、候选、冻结写入命令、提交回执和审计outbox；`memory.sqlite`继续作为记忆版本与删除状态的权威库。独立DSH会话保存在`analysis-sessions/`。这些都在配置的本地dataDir内，运行目录不入Git。

状态为`queued → running → committing → completed`，另有`failed/cancelled`。候选为`ready / needs_review / committed / duplicate / stale`。状态和审计outbox原子保存；发布使用固定事件ID，失败后重放不重复记账。

提交前冻结命令，幂等键为`analysis:<jobId>:<candidateId>`。若记忆库已提交而任务库尚未保存回执，恢复时先核对记忆提交账本，确认已完成的写入，再处理后续候选。此时即使记忆随后被删除也不会重复创建或恢复。已持久化分析结果的任务恢复时不重新调用模型；被中断的模型尝试用新会话重新分析，可能再次产生模型费用。

持久队列只允许一个进程拥有。存储异常停止工作者并报告`worker_unavailable`，保留可恢复状态，不持续重试模型。取消会阻止后续提交，但不会回滚此前已成功提交的候选；需要显式更正或删除它们。来源与本地权威数据库属于可信插件边界，不支持第三方同时篡改文件的并发模型。

## 6. 插件接口

开启配置：在记忆插件原有`agentId/dataDir`上添加`analysis: {}`。检索配置可继续独立开启；分析本身不要求再启动BGE，也不增加本地生成式模型。

| 工具 | 行为 |
|---|---|
| `dafeiyu_memory_analyze` | 显式提交来源与可选更正目标，只返回任务回执 |
| `dafeiyu_memory_analysis_status` | 返回状态、计数、稳定错误码，无分析全文 |
| `dafeiyu_memory_analysis_open` | 显式查看结构化结果与候选，标为不可信分析证据 |
| `dafeiyu_memory_analysis_cancel` | 取消未完成任务 |

主插件不会在任务完成时发送QQ回复、追加聊天消息或装配分析结果。只有明确调用open才返回分析正文；其工具输出标为派生材料，不能再作为新原始证据重复提炼。

本版不自动检索所有相似记忆作为目标，也不自动扩大证据集合。来源与targets由调用者显式选取，现有检索接口可供选择；以后再实现受预算约束的检索—分析调度与ContextPacket装配。

## 7. 验收

自动回归：`npm test`，135项通过，其中30项为新增分析测试。覆盖独立输入/工具、原文新增、更正、会话与发言者隔离、无上下文注入、非法输出、来源伪造、条件截取、删除屏障、版本竞争、取消/超时、重启恢复、提交丢回执、审计outbox重放和内部思考不落盘。

真实模型验收：`npm run accept:memory-analysis`。脚本核对当前DSH绑定、只读使用既有凭据服务并校验凭据文件未变化；主渠道和主会话操作驱动仍用模拟模型，仅三次独立分析调用真实DeepSeek。结果保存于[memory-phase-3-results.json](memory-phase-3-results.json)。

验收样本为虚构“晨露项目”：紫帆731新增成功；明确更正为青鱼888后保持同一条记忆、升至版本2；玩笑与临时约定不写入；异会话引用在模型调用前被拒绝。原会话事件数和模拟渠道交付数在后台完成期间均未增长。

这些是本机功能及故障路径验收，不是长期语言质量基准，也不是生产2GB可用预算的容量认证。服务器预算仍沿用已验证FastEmbed＋ONNX规划；分析采用远程模型、单工作者和有界输入。持久分析档案会累积，需要后续确定归档与保留策略，不能将其无限增长视为已解决。

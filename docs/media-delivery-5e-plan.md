# 统一媒体5E：媒体回复部件与交付实施细则

2026-10-25；基线`1a042fb`。承接[统一媒体方案](media-and-qq-plan.md)及已完成的5A—5D。本细则先提交，再实现。所有平台发送测试只对本地回环替身进行。

## 1. 现状和需要接通的位置

当前core普通回复、ConversationRuns投影、Journal回复、NativeExpressionPacket和native delivery credential均只有文字；QQ v1计划以4000 UTF-16单元分段。media已有受控资产、范围／解码、真实附件曝光、音频／文档读取、观察选择与完整语音证据，但没有任何媒体发送动作。QQ v5已预留媒体计划／部件表。运行中的调用guard会在工具返回后失效，不能把它保存成以后发送的授权。

## 2. 协议与责任

- 引入带版本的回复媒体清单和v2交付计划。默认先发送最终正文的原有文字分段，再按大肥鱼选择的顺序发送image／record／file部件；可选择追加“将最终正文合成语音”。每个部件单独取得message_id，语音不与其它类型混在同一次send请求里。
- 准备动作只选择当前实际作用域内的资产及输出方式，不传目标、原始路径、URL、Cookie或执行器报告。任务内选择表示候选结果；普通聊天选择绑定当前真实入站和Run。只有core能确定最终目标和最终正文。
- draft可在同一Run内持版本调整／取消；每次选择有固定输入、版本和回执。冻结后的交付计划不可改写。旧版本选择记录是程序历史，不是额外世界证据。
- media负责核验字节、来源和租约，提供短期取件权；core负责真实Run／入站／结果锚点、当前人格、实际输入限制和最终交付授权；memory负责目标可用材料及表达范围；QQ负责协议编码和逐部件外部效果账本。

## 3. 授权和原生任务

工具准备时检查真实ExecutionContext、动作写权限、Task epoch、源provider当前证明、父资产链及实际范围。准备结果必须进入来源跟踪，不能因增加新工具再次退回粗粒度legacy路径。

最终交付使用core依据已持久化Run、操作结果及来源创建的程序授权对象；不能伪造聊天上下文，也不能延长原工具调用的guard。普通回复固定实际入站／Run／最终正文；原生任务固定TaskResultAnchor、目标材料包、人格／模型版本及最终渲染。恢复后必须从这些事实重建授权，不能仅凭猜测draftId或文件存在继续发送。

首版原始媒体允许表达的范围为：来源会话等于目标会话，或受信provider明确声明且仍可核验的公开资源。不会因为内部任务能读取另一个私有群，就把该群原图／文件发到当前会话；私有跨会话原始媒体转发不作为默认能力。公开标记来自程序provider，不是模型参数。记忆文字已有的表达策略保持原语义，不能自动扩展成任意原文件外发权。

任务结果继续由干净目标人格会话整理。准备的图片／文件与执行器原始报告分开：只向目标渲染器提供允许的材料及媒体说明，未允许的内部报告不进入目标请求。已经读取的视觉／音频结论明确为推断；未读取资产只提供“待转发资产”的元信息，不把hash或文件名当内容证据。需要额外视觉判断时必须走实际附件曝光路径；路由不支持则拒绝该判断。正文保真与字节／来源／清单一致性分别核验。

## 4. 冻结、发送与重启

冻结记录至少覆盖：协议版本、replyId、目标、入站或Task锚点、最终正文hash、draft版本、完整顺序、每部件类型／字节hash／长度／来源版本、材料stamp及交付凭据。改一个目标、部件、字节或正文都不再匹配旧凭据。

先持久化计划，再发送。每个部件依次pending→sending→sent或unknown；发送前重新检查账号、群范围、来源、凭据、租约及实际字节。确认成功后先保存回执，再投影缓存。已确认部件不重发；发送后响应丢失、进程中断或无法确定效果时保留unknown，整份计划停止，不以失败当成重新发送许可。部分成功必须报告部分交付，不能报告整份完成。

准备失败和调用平台之后的效果不明分开。确定未发出的计划只能在原始身份／材料仍有效且字节仍可取得时继续；恢复不重新运行模型，不重新渲染，不重新生成丢失的TTS来替代既定字节。纯文字回复继续走原v1计划和旧回执，旧D3协议不变。

## 5. 字节、TTS和存储

准备／分析中的原资产使用租约；冻结后直到交付终止或明确过期，保留固定字节。缓存压力不能删除活跃交付资产。清理失败继续占配额。原数据逻辑删除立即阻断发送，不等租约到期。

TTS只接受core最终批准正文，绑定文本hash、普通系统音色配置和目标清单；不提供自由文本合成后直接外发的快捷入口。输出也计入媒体配额并有固定字节hash。未配置、超时、输出不完整或音色变化时给稳定错误，不自动切换云服务。

media库若需追加草案／授权／导出生命周期表，推进v2并提供显式v1→v2迁移；不能在v1内静默加表。QQ使用既有v5预留表，runtime使用已定版v4门槛。旧来源、曝光、租约、回执与模型权重不得重建覆盖。媒体文件与SQLite的备份关系在5F纳入统一清单：不能只复制元数据库便宣称备份完整。

## 6. 子步骤和检查范围

| 子步骤 | 产物 | 必须通过的定向检查 |
|---|---|---|
| 5E-1 | ReplyParts／固定v2计划、QQ媒体部件账本 | 文本原样分段；图片／语音／文件顺序；改目标／部件／正文冲突；旧文字账本兼容；中断不重放 |
| 5E-2 | 媒体草案、实际core授权、租约／冻结与恢复 | 复制／过期调用拒绝；同Run版本变更；跨Task／跨私有会话拒绝；源删除／缓存压力；未批准字节不可导出 |
| 5E-3 | 原生目标材料、媒体清单与渲染凭据 | 目标允许原始材料；私有报告不进入目标；清单hash入材料与凭据；失败不退回原报告 |
| 5E-4 | QQ实际消息数组编码与逐部件交付 | 回环文字＋图／语音／文件；每部件真实模拟message_id；部分成功／未知；撤回／账号变化中断；重启不重发 |
| 5E-5 | 可选最终正文TTS接线 | 只合成已批准正文；替换文本／音色拒绝；固定字节重试；配额与清理；模拟不冒充真实TTS质量 |
| 5E-6 | 本地联合检查与阶段记录 | 当前聊天／原生任务两条路径、旧文字兼容、关闭与恢复、检查记录及Git |

每步只跑相关测试。实际字节、SQLite和回环HTTP可以真实执行；模型、QQ平台及TTS质量用明确替身，真实验收整体延期。全量回归留到部署／发布，不连接服务器。

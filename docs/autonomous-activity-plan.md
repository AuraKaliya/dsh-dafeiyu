## 1. 代码基础与责任

核心已有原生Task／Run、`executionProducer`、`acceptWake`、`bindWakeAuthority`、wake回执去重、逐任务队列、暂停／继续和共享并发槽。RunScheduler已经优先聊天，明确原生任务尚需同等优先。记忆已有持久整理请求与task/epoch/source水位；没有调度器时明确waiting-scheduler。

新增`@dafeiyu/activity`插件只负责持久安排、计时／条件判断、投递与结果回执。大肥鱼决定探索目的、时间与频率，也可以决定休息。记忆决定整理内容并执行分析；核心核验发起身份和权限并运行唯一DSH循环。活动安排不写入长期偏好，不替代Task目标或成长状态。

运行进程存活时插件才能计时。进程退出后的启动与守护属于Host／部署工作；本阶段不安装系统任务，不声称能开机或从关机中唤醒。

## 2. 契约和持久数据

独立`core/activity.sqlite`，application_id独立、schema v1；保存profile／agent身份、Schedule及不可变修订、WakeOccurrence、投递outbox／回执、条件事件去重及运行用量。位于已有core目录占用保护之下，不另开未声明的数据根目录。

Schedule字段：id、版本、状态、真实owner scope、工作task引用／epoch、purpose（自主探索／记忆整理）、目标或记忆请求引用、兴趣／证据引用、核心签发的来源锚点、固定policy、配置指纹、trigger、时区、安静时段、错过政策、nextDueAt、最近结果／退避／需重审状态、创建与修改时间。兴趣正文仍由记忆管理，不复制成独立人格库。

模型工具不接受agentId、producer、policyId、任意其它taskId、权限或数据目录。首版计划工具在获准的原生Task中使用；QQ聊天可沿已实现的self-exploration任务入口发起，再在该Task内制定活动。不会伪造QQ入站消息。新探索Task是独立内部任务，不自动获得QQ发信或结果外发权。

计划的读写范围为原始owner Task及本计划自己的活动Task。其它任务即使知道scheduleId也不能读取目标／理由或修改计划。管理员的全局状态只含计数和稳定故障码。程序接入记忆待办时只读取元数据，不把其它任务正文交给规划模型。

## 3. 来源与权限

需要补齐核心程序接口：创建尚未运行的Task、捕获当前实际执行上下文的持久来源锚点、检查锚点有效性，以及任务生命周期观察。锚点固定原Run／操作、Task／epoch、实际输入依赖、policy和注册版本；存于既有run_inputs，仅由核心通过真实v3调用对象签发，复制字段不能伪造。尚在运行的发起Run先等待，未知效果或失效来源不能用于未来唤醒。

activity创建、提交前、核心开始Run及每个动作都复核当前计划／机会、Task epoch、来源锚点及配置。取消任务、撤回触发消息、删除来源、策略收紧、插件退出会停止旧授权。已有合法历史不因来源删除被物理覆盖；旧计划进入stale／需要重新规划，不自动扩大权限或复活旧证明。

新活动的资源由固定policy白名单决定；来源锚点不额外授予平台访问。尤其QQ资料在没有相应资源范围的维护policy下不可读取，只能得到明确不可用状态。内部任务目标与报告不会自动交给QQ发送。继续沿既有逐段交付和表达授权流程处理未来需要的通知。

## 4. 时间和条件

首版trigger支持：一次UTC时刻、以UTC锚点和intervalMs表示的固定周期、注册的类型化条件。时区默认Asia/Shanghai，用于展示、安静时段与日用量边界；固定周期按真实经过时间运行，不伪称夏令时地区的固定本地钟点日历任务。不解析任意cron、脚本、SQL或网页表达式。

时钟通过可注入接口读取；持久UTC时间和到期锚点不随时钟回拨倒退。时钟跳跃／重启按missed政策处理：skip推进到未来；coalesce（默认）把积压合为一次；run-once补一次后结束。不会为每个错过的周期创建Run。安静时段允许跨午夜，DST由IANA时区转换处理，无法确定的时区配置拒绝。

条件事件至少支持任务结束和记忆整理需求；预留受信资源恢复事件入口。字段固定eventId、类型、来源、task/epoch、水位、occurredAt、causedBy/origin。模型不能投递伪造领域事件。重复事件不新增机会，同一水位无变化的失败不紧密重试；activity自身及maintenance派生事件不能反复触发同类活动。

配置默认：tick 5秒、最小唤醒间隔60秒、活动并发1、最多100个未结束计划、单次活动最长5分钟、每天最多1小时活动时间、可恢复故障初始退避60秒且最大1小时。安静时段默认空，由配置或获准规划明确选择。时间／容量约束可观察、可配置；没有工具调用次数上限，也不把时间预算称为费用预算。

## 5. 持久握手与恢复

1. 在一个activity事务内固定scheduleId/version/occurrenceId/dueAt/reason、水位和投递记录，推进nextDueAt。
2. 使用固定activity生产者调用核心acceptWake，requestId等于occurrenceId。核心保留原回执／Run；activity确认丢失时投递同一ID，不生成新机会。
3. 核心完成／等待／失败事件带固定ID交回activity，接收后才确认核心outbox。重复完成事件不重复计费时长、推进计划或安排后续工作。
4. activity关闭／重启仅重投持久未确认记录。运行效果不明的机会标记unknown／blocked，不自动再执行。完成但业务尚未做完、没有保存进度等情况如实保留，不能把模型停止当作业务成功。

排队时计划改版或取消，旧机会作废。已经开始执行的活动默认允许在原权限内收尾；取消或超时采用合作取消／暂停，保留确认和未知效果。频率调整可以在当前活动中生效于下一次，不能因为自己改了nextDueAt就让本轮合法的操作回执丢失。活动上下文固定本次机会事实，当前计划另由状态工具读取，避免把可修改的计划错误当成永远不变的输入。

明确任务／聊天等待时，优先为其调度。正在执行的自主活动可暂停、保存检查点后让出；只有已确认安全的检查点可继续。继续链保留最初wake授权检查；不能因origin变为continuation而绕过已取消的计划。未知副作用阻止盲目重放，休息或重新规划是合法结果。

## 6. 工具与端口

| 接口 | 内容 |
|---|---|
| `dafeiyu_activity_plan` | 在当前Task范围提出自主探索目的、basis和时间／条件计划，持久保存；不会立刻伪造任务结果 |
| `dafeiyu_activity_update` | 持expectedVersion改期、调整频率／安静时段或暂停、恢复、取消；变更目标需要新的来源锚点和Task版本，不能原地替换旧目标 |
| `dafeiyu_activity_status` | 当前拥有／执行的计划与最近机会状态，有界返回，不跨Task读正文 |
| activity程序端口 | tick、受信条件事件、生命周期消费、恢复、停收／排空；时钟可注入用于测试 |
| MemoryMaintenanceSchedulingPort | 记忆提供待办元数据、固定请求状态与调度器连接状态；activity安排maintenance Run并提示它处理精确请求；不直接调用分析器绕开核心 |
| core来源锚点／生产者接口 | 只能从真实v3上下文或已核验记忆待办建立未来运行依据；原有普通任务、message任务和旧wake测试保持兼容 |

记忆待办绑定原Task／epoch，默认coalesce同task的当前待办，逐个固定ID执行；输入超限需要缩小范围／新请求，不无限重试旧输入。是否已整理以memory状态和水位为准，是否已运行以core回执为准，activity不声称替它们完成工作。

## 7. Host装配、数据迁移和关闭

activity为可选插件，默认关闭。Host检查memory、来源跟踪、对应policy及activity目录／身份；用于记忆调度时还要求maintenance启用。装配顺序：核心→memory→核心执行端口→activity注册／恢复→QQ等外部连接→统一激活→计时器。恢复与单次CLI模式不启动后台活动；仅daemon在ready后激活计时器。关闭先停计时和新投递，再排空／取消核心工作，最后关闭activity和memory。

新空profile初始化新库。已有profile添加activity时必须通过迁移计划、备份和核验显式创建新库，不调用init覆盖旧目录；迁移bundle加入可选activity声明，旧计划需按引擎指纹重新生成。旧profile不启用activity时不要求新库。memory维持v11、runtime v3，来源锚点使用带版本的附加输入记录；未知activity schema拒绝。

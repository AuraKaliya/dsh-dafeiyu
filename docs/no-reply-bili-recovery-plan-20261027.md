## 2. 程序与模型的固定分工

描述性提示说明角色、阶段目的、材料的含义、判断责任与表达原则。精确接口、工具目录、账号、目标、任务版本、来源、时限、请求与发送回执由程序装配、持久化和校验。输出协议由当前schema生成，不在多份提示中手写同一精确协议。

程序拥有阶段和合法转换。模型在当前可行动范围内理解意图、选择方法、评价目标满足程度、提出继续/调整/等待/交付决策，并组织最终输出。模型评价、程序执行事实和平台交付事实分开保存；模型不能写出一个“已完成”就改变真实运行或发送状态。

正常路径：受理与准备 → 执行 → 成果评价 → 表达与交付。任一阶段异常转入恢复；恢复后依据合法模型决策继续、等待或交付局限。短聊可复用同一轮完成理解与表达，不为每句话强制增加独立评价模型调用。任务内部使用原有DSH循环。

## 3. 第一批：原始错误与请求记录

先完成这一批，再进行新的B站低频复检。

在BiliClient实际网络边界记录所有请求尝试，包括独立运维探针；不能仅依赖BiliService的Task事件，否则本次这样的直接适配器调用仍没有完整请求轨迹。

每条记录包括：

- 请求/尝试ID、时间、耗时、接口类别、调用来源（任务或运维）、Task/Run/operation引用（没有则明确为空）。
- 通路（匿名HTTP、已授权HTTP会话、DSH浏览器）与身份模式；不把未知账号写成匿名或已登录。
- 是否真正发出网络请求、是否来自缓存、是否被本地节流拦下。
- 原始HTTP状态、原始平台错误码、受长度限制且脱敏的错误摘要、响应类型及解析状态。
- Retry-After安全原值、解析结果、决定等待的依据（平台指示或本地策略）、策略版本、下一次最早尝试时间。
- 成功、网络失败、超时、响应格式异常、平台拒绝、登录失效、权限不足分别记录；未知业务码保持未知，不猜含义。

不保存Cookie、令牌、完整请求头、带签名/敏感查询的URL、完整响应体、浏览器私有存储或模型内部思考。诊断信息在正式实例本地受控保存，模型只读取必要的结构化摘要。记录有容量与保留期限；迁移新增诊断表，不改写既有真实请求与观察。

普通会话同步补充安全错误链：保留原始阶段、内部故障类别、来源标识、依赖版本与变化原因，不再只剩MODEL_INCOMPLETE。来源失败必须可定位到具体校验项；不能由日志缺失直接推断根因。

## 4. 第二批：替换固定15分钟退避，进行一次低频诊断

### 程序策略

| 情况 | 行为 |
|---|---|
| 平台提供有效Retry-After | 支持秒数及HTTP日期，至少等待平台要求的时间；不再额外强制拉长到15分钟，也不擅自缩短平台要求 |
| 已确认限流，但没有等待时间 | 建议本地初始10秒，重复失败依次30、60秒；每次只准一个探测，后续请求共享等待结果 |
| 412或尚未明确含义的风控业务码 | 保留原码，进入诊断状态；建议30秒后只做一次受控检查，不当成纯频率问题循环重试 |
| 登录失效/账号不符/权限不足/需要人工验证 | 等待对应条件解决；时间到期不自动当作已恢复，不做无效定时重试 |
| 网络超时或临时服务失败 | 对可安全重试的读取采用短退避，效果未知的写操作先核实回执 |

10/30/60秒及30秒诊断等待是可配置的工程初值，不是声称B站公布的安全阈值。少量连续探测仍失败后进入明确受阻状态，停止自动尝试；这仅限制异常网络重试，不是恢复旧的每轮工具次数上限。

冷却记录持久化，重启不清空。作用范围依证据确定：可证明是单接口问题时只限制该接口；疑似身份/网络整体限制时采用保守共享范围。仅凭一个错误码不伪造“只影响该接口”的结论。QQ与其他不依赖B站的工作继续可用。

### 本轮低频复检

1. 确认诊断代码已测试并装载、实例空闲，保留已有失败证据。
2. 先只读检查DSH浏览器provider、profile、实际页面与账号；不导出Cookie、不重置浏览器、不假定旧账号仍有效。
3. 按接口依赖顺序做最小请求，相邻检查初始间隔至少5秒，仅作诊断节奏；若能从已有材料取得目标ID，就不再重新发现目标。
4. 取得匿名视频详情的精确失败原因即停止该路径的重复试探。若条件允许，在已授权的DSH浏览器中对同一公开对象做一次正常页面读取对照。
5. 浏览器对照用于区分通路、身份或接口适配问题，不自动当成对风控的绕行。若存在平台等待要求、验证挑战或账号整体限制，共享这些状态，不通过换通路提前重试。
6. 分别记录匿名接口、浏览器页面、实际账号与网络环境差异。浏览器成功只能说明另一条路径可用，不能单凭它证明“唯一原因就是缺Cookie”。
7. 输出证据支持的结论，未确定的原因继续标未知。之后才决定是否需要HTTP会话授权、接口适配修正或浏览器读取接线。不得先批量改请求头、签名或登录策略再声称找到了原因。

## 5. 第三批：复用DSH已登录浏览器

优先核实和复用用户已登录的那套浏览器，不要求用户无依据地再次登录，不自动复制Cookie到B站HTTP配置。B站内容能力使用现有宿主浏览器服务，身份与站点存储留在浏览器中。

分三层核验：

1. 浏览器是否存在且可连接；当前任务获得的是哪一provider/profile。
2. 当前B站页面是否已登录、账号是否与用户指定的大肥鱼账号一致。
3. 所需阅读功能是否实际可用；“已登录”“能看网页”“能读视频音画”分别验证。

若同一profile共享登录已满足需求，仅补能力发现与B站观察接线。若任务连接了另一套浏览器，先修正宿主选择或可信会话绑定，不扩散凭据。账号变化使相关操作进入重新核验；不使用历史服务器UID替代本机核验结果。

对核心提供一致的B站能力声明和观察结果：当前通路、登录状态、支持动作、实际阅读范围、来源/时间、缓存与继续入口。模型决定浏览哪些视频、评论和材料；程序绑定实际账号、当前Task、资源范围及回执。通路选择可以由模型在已验证可用的选项中决定，程序拒绝绕过等待/验证/权限边界的调用。

浏览器页面的正文、评论和截图进入现有来源与Media链路。页面可见不等于完整观看，字幕不等于听过音频。跨任务共享登录不授予跨任务聊天内容读取权限。

本批范围是公开阅读与学习，不扩展点赞、评论、投币或私信发送。既有B站固定主人私信约束继续独立保持，不能通过通用浏览器工具扩大收件人范围。浏览器自带可撤销的工具限制不是安全边界；必要限制放在不可由模型解除的宿主调度/任务授权层。

## 6. 第四批：普通会话恢复和连续消息交付

### 来源变化恢复

来源校验提供精确失效事件及其影响范围。有效材料继续保留；被撤回或失权的材料及受其污染的草稿退出可用视图。来源保护不能关闭，历史原始记录也不删除。

程序保存已完成工具、结果引用、未完成步骤与真实效果，进入恢复阶段。模型据此判断补查、继续、等待或说明局限。确认成功的动作不重做；效果未知的动作先核实。没有已验证进展时不输出虚构进度。

生成、评价、表达各自有程序截止时间和恢复记录；超过期限进入可观察状态，不能空队列却一直让用户以为仍在工作。正常回复、进度和失败说明仍由目标会话人格生成。模型本身不可用时保留独立、明确标识的系统状态通知，仅报告程序事实并去重，不伪装成人格判断。

### 新消息与已有回复

程序保存新消息及上一条回复的已发送/确定未发送/结果未知部分，在必要的安全边界暂缓未开始的发送，不立刻丢弃尾段。明确的程序取消事件立即生效；自然语言中的补充、纠正、改题、取消含义由核心模型判断，不能用“同一个人发来新消息”取代语义理解。

模型决定合并补充、继续原任务、改目标或生成替代回复。程序对决策绑定输入消息、Task版本与发送版本；陈旧决策不得提交。已确认发送部分不重复发送；未发草稿被替代时记录原因；结果未知不能当成未发。后续上下文明确区分“模型写过什么”与“用户实际收到什么”。

## 7. 测试与完成条件

只跑与本批变更直接相关的本机测试。优先复用 `bili-foundation`、`bili-capabilities`、`host-bili-storage`、`host-bili-flow`、`dsh-bridge`、`provenance`、`qq-delivery`、`qq-message-batch` 和原生交付测试。诊断、平台读取和模型语义验收分别记录。

- HTTP 429/412、HTTP 200带风控业务码、HTML/损坏JSON、超时均保留原始分类；本地拦截明确networkSent=false。
- Retry-After秒数/日期/缺失/无效值、并发等待、单次探测、重启恢复均按实际时钟契约工作；不再出现无依据的15分钟统一下限。
- 敏感头、Cookie、签名参数、私有浏览器存储无法进入诊断输出或模型上下文。
- 同浏览器登录复用、不同provider/profile、登录失效、账号切换、浏览器关闭与重启均被区分；禁止通过鉴权工具导出解决普通阅读接线。
- 无关来源追加不误取消；真实撤回与失权仍有效；恢复保留已确认操作，不重放写入。
- 连续补充消息不吞掉未交代的任务；部分发送不重复，明确取消及时生效，未知回执先核实。
- 原故障对应场景在本机用合成消息与模拟平台复现，不重放正式旧消息；真实平台只做上述低频读取，不发测试消息。
- 每批提交脱敏检查记录；正式配置、登录态和原始运行材料不入Git。部署前确认空闲并备份，部署后核对身份/记忆/会话与实际加载。

# R6f-2 运营资金持久化与停止接线检查

2026-10-27，北京时间。接续 `7521341` 的生产启动方案；本步完成资金模块，薄 CLI、生产账号和服务器启动仍在后续子步。本记录不表示部署或真实付费验收通过。

## 实现

- 新增显式资金/价格/批准元数据 schema、existing-only SQLite 存储、一次初始化凭证、追加授权链及单进程租约。缺库、缺凭证、初始化中断、价格/作用域变化不能自动重建余额。
- micro-CNY 以安全整数输入、BigInt 运算和十进制字符串汇总；父调用和不同 executor job 使用同一权威，排队不预留，已派发必须结算。未知用量保留完整预留并阻止后续调用。
- 不同原始异常回执使用有界结构指纹区分，不因都归一化为 unknown 而被视为同一回执；任意异常 payload 不落入账本。
- 绝对 UTC 高水位、剩余时长上界和终止原因持久化。即使没有模型调用，时钟回拨、单调时钟耗尽及重启也不能恢复期限。
- 真实资金 authority 的到期定时器和最后零余额通知接到共享预算，停止 Core、QQ、B站新准入及后台工作；已经产生的账单仍可结算。窗口到限时不是仅靠下一次模型调用才发现。
- 资金 `scopeHash` 与逐版 prepared config/pins 分离，避免正常自主代码更新无意要求重新领取资金。金额、期限、模型/价格、Node/SID 绑定没有放宽。完整启动阶段的持久停止检查由后续薄 CLI 实施。

本步没有初始化真实运营额度、没有追加 7C 预算或时间，也没有调用模型、平台或服务器。schema=1 为尚未发布的新运营库；不存在真实旧运营库迁移。

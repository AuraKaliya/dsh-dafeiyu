# M5C第三部分C3-B：限定条件、受控融合与原文重建

日期：2026-10-24。项目0.13.0，core 0.10.0，contracts/memory 0.9.0。本轮仅本机开发与虚构样本验收，未连接或修改服务器、真实QQ及其会话。原有无关文档修改保留，不纳入本次提交。

## 本轮实现范围

在C3-A的多代证明和单次DSH区域替换之上，实现一个来源组内的语义融合，以及从有效原始记录重建。一个组已经具有共同的实际输入依赖；融合不会把无关组绑成新的共同失效单元。不同组、当前工作任务、人格和其他插件区域不进入这次模型请求。其它仍有效片段的kind和正文原样复制到新包。

融合读取选中组的有效父片段和完整原始输入，以原文纠偏；重建只读取有效原始输入，不把旧摘要正文交给模型。不会自动跨多个来源组做主题融合。主题级关联扩展、全库扫描、定时整理不属于本轮实现。

## 限定条件与独立复核

代码从原始文本抽取保护条款，保存源事件seq、角色、UTF-16起止位置和逐字文本。用户消息的渠道说明不当作用户陈述；原始消息身份、会话和完整来源仍保存在证明中。检测规则重点覆盖否定、仅限/条件、确认/验收、可能/假设、说话归属、更正、状态、时间和数值标识。

保护条款不是完备的语义理解器。遇到同义表达、隐含条件或未匹配规则，需要独立复核兜底，不能声称已证明绝对保真。

生成与复核使用同一DSH绑定模型，但分别建立全新的辅助请求和会话身份，均不带工具。流程如下：

1. 代码校验来源状态，提取并锚定条款。
2. 模型生成一个片段，保护条款要求逐字复制，保留标点和数值写法。
3. 代码检查正文长度、每条保护文本是否保留，以及位置是否与原文一致。失败不进入后续提交。
4. 独立请求对照原文、父片段（仅融合时）、保护条款和候选，检查主题相容性、归属、范围、条件、时效、纠正、失败和不确定性。
5. 仅compatible=true、faithful=true且issues为空才通过。复核拒绝使用专门错误类型，不把网络失败、解析失败或截断当成“模型成功识别反例”。

保留正确引文后又追加错误结论，也必须拒绝。原文包含“未验收、不允许正式群发”，即使摘要完整复制这些句子，再补上“条件已满足，可以正式群发”，仍然是不合格候选。

所有模型内部推理块都不保存。完整保护条款和复核结论留在私有证明中，模型当前聊天只看到通过校验且选入的摘要正文与短引用，不接收完整分析过程。显式来源回查可获得所选片段的证明，仍受现有会话、版本和删除规则约束。

## 多代来源与语义改写上限

summary-manifest增加rewrite记录：模式、直接父包及其manifest/view/checkpoint位置和哈希、被处理来源组、实际原始inputs、依赖闭包、输入摘要哈希、连续改写次数、输出上限、条款与复核结果、模型路由。

fusion模式中的父片段属于实际模型输入；rebuild模式中的父包仅作为替代关系和历史证明，旧正文不是模型输入。两种模式都由代码计算原始来源依赖，模型不能自行声明或删减。

每组semanticDepth默认连续达到2次语义融合后，下一次候选必须改为原文重建；重建将该计数清零。无损组合会保留这个计数，不能通过换包装绕过上限。保真但无压缩收益的候选仍不装配。

完整历史依赖链继续保存，不因重建而抹去父关系。本轮语义链最大64代，单次证明遍历最多256节点；提交前为新节点预留证明容量，超过上限时停止，不截断来源。C3-A无损组合自身仍保持16代准入上限。这些是资源保护边界，不代表无限长会话已验收。

## 逻辑删除与原文重建

正常请求前先执行既有局部失效。来源A被删除时，其摘要与真正看过A的派生输出退出；独立B与其他插件区域保留。恢复A提升状态版本，旧片段不能重新加入。

若原组混合A、B而整体失效，重建可以逐条检查原始事件的独立来源证明，只取仍有效的B原文。含A曝光依赖的助手回答即使只提到B也不能入选；A原文和旧混合摘要均不进入请求。新输出建立B的真实来源闭包，保留到旧父包的替代记录。

不能对所有已退出组任意“重建”：仅当旧组仍确实失效、原始输入存在严格的有效子集时，才允许恢复其中的有效证据。插件卸载造成退出后又可读取的完整组，不能借重建入口重新激活。完全不可分割的同一原文中同时含A/B、全部原文失效、证明不足时保持退出，不要求模型自行删除A。

自动重建仍在阈值检查中发生，不承诺删除后立刻后台重建。恢复有效子集可能增加当前空视图的文本，因此额外检查DSH估计及UTF-8字节口径的输入上限；普通融合和重建要求估计token与展示字节都有收益。

## 提交、失败和隔离

生成与复核期间、提交前均复查实际来源、父视图版本、surface替换代数、绑定提供者及当前任务。无关来源变化不撤销有效候选，实际来源变化则拒绝。一次最多处理一个组，两次辅助请求共用超时信号。

持久顺序仍为manifest → view → prune → 单条替换消息。孤立准备数据不生效；替换完成后重启从新包恢复。flush失败阻止当前聊天模型请求。校验失败保留有效旧视图；已失效部分仍退出，不因生成失败回退。拒绝事件记录候选引用、组、模式和稳定失败分类，不记录原始异常载荷或模型推理。

主插件协调来源准入、预算和提交；记忆插件通过DSH LLM服务负责生成/复核。不另写模型循环，不启动新数据库或常驻服务。2GB应用预算仍需最终部署实测，本轮没有服务器资源验收。

## 配置

新增字段属于memory的compaction配置。自动语义请求默认关闭，避免改变既有运行配置。示例：

```json
{
  "compaction": {
    "inputTokens": 30000,
    "semanticEnabled": true,
    "semanticMaxConsecutive": 2,
    "semanticMaxOutputTokens": 8192,
    "timeoutMs": 180000
  }
}
```

semanticMaxConsecutive允许1～4；semanticMaxOutputTokens允许2048～32768，默认8192，独立于正文maxSummaryChars。timeoutMs沿用既有配置，默认30秒，上例为两次请求合计180秒，适用于本轮max推理力度的验收。没有修改用户现有模型或运行配置。

辅助请求把提示词、原文、父片段、条款及候选的总字节都纳入maxSourceBytes检查，而不只检查原文大小。最多64条保护条款，每条最多600字符，超限拒绝、不截断。非stop结束、工具调用、无效JSON、超长输出、容量不足或独立复核不通过，都不能提交。

保真通过不等于采用：其中第二轮权限摘要由72字符增至142字符，实际自动入口会因无收益拒绝；原文重建候选为58字符。该多代样本专门检验保真与回原文能力，不表示运行时会连续采用增长摘要。

早期一次候选未逐字保留条款而被拒绝，随后加强了复制要求，未放宽校验，见[首次记录](memory-phase-5c3b-model-initial-results.json)。还出现过[未完整结束的流](memory-phase-5c3b-model-incomplete-results.json)以及最终报告中的一次error结束；均未提交候选。后续使用--resume只补做未完成项，并保留调用记录。报告保留这些中间失败，不能解读为首次全部成功。

--resume要求同一模型、样本和保护条款策略；首次旧格式记录兼容补记fixtureHash，之后核对哈希。正常复测默认从头开始。样本数量有限，独立复核仍由模型完成，不据此承诺任意中文语义的零遗漏率。C3-B已具备本轮限定范围内的功能闭环；更大语料、跨组主题融合及长期资源评估属于后续工作。

# R2 memory：试行选择与不可变结果实施

2026-10-26，接续R1契约及v12迁移。主代理负责memory，子代理负责已提交R2 core方案；统一构建和检查，正式账本与旧验收profile不迁移。本步骤先实现试行实际使用，不把R3资格策略提前宣称完成。

增加独立PersonaTrialStore，沿用PersonaStore的事务、幂等命令、作用域及来源resolver。公开trial_select只选择本范围当前trial精确版本，保存适用／退出条件和独立选择版本；空数组撤下试行选择。试行项单独投影、标明tentative及来源限制，进入同一上下文预算；adopted集合不混入trial。

core通过受信authority调用admitTrial与completeTrial，MemoryService先经core的WeakMap及输入指纹验证取得PersonaAccess。模型不能提交装配、Run终态、实际效果或结果hash。Admission必须与真实选择、候选内容和依赖一致，projectionHash固定为personaDigest(ContextItem)，与core runtimeHash一致。只有已存在Admission才可保存Outcome，不从闭合Run倒造此前使用。

同Run/候选/选择的Admission、同Admission的Outcome均按不可变内容幂等；同身份不同内容拒绝。闭合事件时间不得早于装配，原scope与runId不能改变。失败／中断没有虚构最终文本，unknown效果保持unknown；记录活动事实不代表采用资格通过。

Completion重放按原闭合事件、结果、操作与Admission快照核对，不依赖恢复时仍选中该候选；来源后来失效不改写历史Outcome，采用前由R3重新验证并拒绝无效依据。缺Admission不补造，保留空结果／缺口。所有引用读回须验证当前范围和正文hash，跨域ID不暴露内容。

当原Run确实装配trial后，同内容精确版本经合法Decision提升为adopted，且当前仍选择该adopted，原Run可以使用已封存的旧trial投影；这不重写清单，也不让之后的新Run重复装trial。withdraw、来源撤回、非等价版本变化及范围改变仍使旧投影失效。该兼容只用于原Run已经存在的Admission，不能恢复任意旧试行。

来源性质由受信producer/resolver提供：ExecutionObservation可显式带类型化nature；旧源缺字段保持unknown，原正文/hash和幂等指纹不变。self-report/digest继承原根性质，不新增独立票；不用“primary”或正文关键词猜真实亲历。PersonaMaterial增加可选受信描述；旧resolver不提供时产生明确unknown描述。新试行投影呈现必要的覆盖／未知限制，详细证明保留在库中。

拟修改memory/persona-store、persona-service，新增persona-trials和persona-evidence；ExecutionObservation及execution-sources仅追加可选nature，保留无字段旧请求的原指纹。core生命周期回调由另一代理负责。R3会追加采用复核与共同门槛，本步骤不新增生产legacy种子或绕过publish的开关。

相关验证：精确选择／撤下、非trial和跨scope拒绝、预算遗漏未登记、Admission/Outcome幂等及hash冲突、未结束／无Admission不造结果、unknown保留、重启补投、来源撤回、等价提升与撤下失效；新Run能看到暂定标记而未冒充adopted。测试用D盘虚构库及脚本后端，真实语义须新候选另验。

# M5C第三部分：多代摘要合并开发方案

日期：2026-10-24。本方案承接C2独立分片与短引用，继续本机开发。C3-A实现无损组合与来源链；C3-B的语义融合、限定条件分析和原文重建另行开发。服务器、真实QQ、模型绑定与私人记忆不变。

## 两类合并与原文重建

组合展示只复制现有有效片段，保持kind、正文和各自依赖；严格同源重复只展示一次，保留全部直接父引用。语义融合产生新正文，继承模型实际读过的全部来源；不能凭模型声称“只用了B”删除A依赖。原文重建只读取仍有效的独立原始材料，重新建立派生身份。

优先组合展示，不为压缩率绑定无关历史。同一事实的重复摘要、同一事件的连续进展和兼容约束可候选融合；条件、时间、归属、冲突、纠正或任务范围不兼容时保留分片。多次转述同一原文不增加证据数量，也不提高可信度。

## C3-A：本轮实现

### 准入和严格去重

只选择同一DSH会话、agent、route、所有者的当前有效摘要视图。原始来源及版本由记忆插件的SourcePolicy复核。任何已退出、证明缺失、来源失效、保护中的当前任务片段都不能进入候选。

选择物理上相邻的完整摘要包；普通对话、其他插件与原生节点、旧版未分片摘要、空视图是屏障。不跨屏障、不改变剩余历史顺序。组合可保留不同历史任务，但它们的任务标签保持独立；不同任务的相同文字不能去重。

严格去重键为：kind、逐字正文、任务ID、原始事件seq/角色/哈希集合、完整SourceDependency状态集合。不同消息即使文字一致也不去重；同源片段若版本、范围、任务或约束文本不同也不去重。首次出现的位置保留，重复父引用进入私有lineage。

### 多代证明与三种检查

summary-manifest追加可选composition字段：模式、代数、直接父摘要短引用、manifest/view/checkpoint位置、视图版本、哈希、每个子片段的直接父片段引用。groups始终保存可回到原始消息的inputs与完整依赖，而不是只保存上代摘要。

恢复时递归重算组合结果、原始来源闭包、去重和父映射，必须与持久清单逐项一致。父节点必须早于子节点；未来引用、环、漏依赖、漏父引用、正文改写、跨会话均拒绝。组合声明不能将不合法数据升级成有效来源。

分开检查：

1. 不可变来源证明：父视图按子代创建前的日志边界核验。父摘要被替代后仍可作为历史证明。
2. 当前来源状态：权威记忆、消息来源围栏、工作条目、工具反馈和插件版本决定是否仍可使用。
3. 当前展示选择：active、withdrawn、superseded、unselected、unproven仅描述展示或证明可用性，不代表来源有效。

替代状态从已提交的替换与来源图推导，不写第二套可变状态库。resolveFragmentProof供代码审计，不提供绕过逻辑删除的模型工具。正常短引用回查仍要求当前视图及有效来源；旧父短引用不会自动重定向到后代。

### 提交与恢复

准备阶段不写日志。提交前再次检查父视图版本、当前来源、区域替换代数及连续范围。原文、kind、限定词不会被模型重写。

提交记录顺序：summary-manifest → summary-view → compaction/prune → dafeiyu-summary-view消息。最后一条消息的一次DSH surface替换是提交点，新摘要进入与所选父摘要退出发生于同一个事件；不引入独立事务存储或双写。

只写入清单、视图或prune便中断时，这些记录为孤立准备数据，父视图继续有效。写入替换消息后，重启从新摘要恢复。flush失败阻止模型请求。已提交但证明损坏时关闭该派生视图，不回退到可能失效的旧父摘要；未提交失败保留仍有效父视图。

### 局部失效与资源控制

A、B独立片段组合后，A状态变化只移除依赖A的片段；原本看过A和B的混合回答依然整体继承两者，不能因组合而缩小依赖。来源恢复提升状态版本，旧编号不能重新加入。后续组合只读取当前剩余片段，可从有效B继续形成新一代。

沿用阈值、冷却、最小增长和最小收益。满足触发条件后先尝试无损组合；必须同时满足DSH估计token收益与展示正文UTF-8字节减少。无收益时保留原视图，继续既有原文压缩选取。每次最多提交一组组合，不额外调用模型。

最多8个父包、8个来源组、32片；实际还受已有maxFragmentGroups/maxFragments配置限制。展示字节受maxSourceBytes限制，清单最多2MiB，每组依赖最多4096项，组合深度最多16，单次证明解析最多256个递归节点。达到边界时拒绝，不截断证明。C3-A到深度上限后不会自动原文重建；该功能属于C3-B。

所有索引仍从DSH日志重建。无新增图数据库、embedding模型或常驻服务，保留2GB应用预算方向；本轮不声称完成长会话资源占用或服务器容量验收。

## C3-B：后续语义融合与保真

融合前建立原文锚定的限定条件清单：发言者及归属、范围、条件/否定、有效时间、置信程度、失败/待验收/部分完成状态、标识与数值单位、纠正/例外。必须出现在正文中的条件不能只藏在证明里。

代码检查关键标识、结构与来源；独立模型检查范围扩大、否定遗漏、计划变完成、推测变事实。抽取和模型校验都不是语义保真的绝对证明；无法确认则保留独立片段。摘要不能代替实际权限检查。

每次语义合并对照原始锚点；连续合并上限、冲突纠正或复杂条件触发原文重建。初期“连续两次语义合并后重建”为待验证配置，不与C3-A无损组合深度16混淆。原文过大时独立分组重建，不丢限定或来源。

若A+B融合后A被删除，融合片段及后代退出；从独立有效B重建，绝不把旧混合正文交给模型要求删A。显式已删除数据查询不自动回流压缩或候选流程。重建失败不能恢复无效旧摘要。

## 验收

C3-A使用真实DSH会话、持久化与恢复、脚本模型和虚构中文材料，覆盖至少三代来源链、严格去重、同文不同源、修订和逻辑删除局部退出、恢复不复活、其他插件屏障、当前任务保护、会话隔离、证明伪造、并发视图变化、容量限制、准备中断、已提交重启、flush失败与重试。

C3-B另外需要当前绑定真实模型的限定条件与语义保真评估、原文重建及冲突场景。C3-A不调用模型进行合并，不能替代C3-B的效果验收。

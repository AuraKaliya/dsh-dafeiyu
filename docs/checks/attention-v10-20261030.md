# 注意力层第十版：身份、启动恢复与定时器边界

日期：2026-10-30
基线：`affae7d`
验证：`npm test` 269/269 通过；发布包检查通过。
当前本机运行实例仍是 `...attention-v9-20261030-1930`；本版是源码/发布候选，尚未替换运行实例。

## 1. PID 复用

- 新增 `@dafeiyu/journal/owner-identity`：PID、操作系统进程创建时间、owner nonce；
- Host coordination、Journal、Runtime、Analysis 共用 `ownerAlive`；
- 旧 owner 没有创建时间时仍兼容，只有 PID；新写入的 nonce/owner 带创建时间；
- Host owner 增加 `processStartedAt`；Journal/Runtime/Analysis nonce 形如 `pid:start:uuid`。

## 2. 启动恢复

- `ManagementRuntime` 增加 `waitForOneBot`：启动 Host 前核验 `get_login_info` 的 bot 身份；
- 子进程异常退出或启动失败按 `2s/5s/15s/30s/60s` 有界重试；
- 成功 ready 后重置重试计数；
- 停止/销毁会取消重试。

## 3. 反馈定时器

- Core 在 `configureExecution` 后启动独立 30s 反馈 tick；
- 移除 Activity tick 对反馈派发的依赖；
- `activity.enabled=false` 不再关闭自动反馈；
- `dispatchFeedback` 在 repository 尚未绑定时直接返回，避免误判来源和 supersede。

## 4. B 站诊断

- `BiliService.health` 增加 `diagnostic`，分别给出 HTTP/browser 状态、暂停范围、等待时间；
- Host 的 `degraded` 不再只能表达“整站失败”。

## 5. 取消清理

- `closeIterator` 给 `iterator.return()` 加 250ms 上限；
- 阻塞的异步生成器不再无限持有结算/调用门；
- `bindCallSignal` 在 request 可变时把 callSignal 写入 transport 请求信号；request 冻结时仍只能依赖有界清理，不能保证底层 transport 被取消。

## 6. 本地部署准备

- 新增 `scripts/prepare-local-deploy.mjs` / `npm run deploy:prepare`：复制发布包、创建依赖 junction、写入受管理的 bundle patch；
- plugin 配置新增 `startOnLoad`，默认 false；本地部署包显式设为 true，不再手改 `runtime/plugin/lib/index.js`；
- 当前运行实例仍带旧的本地 direct-start/日志补丁，下一次完整 DSH 重启应加载受管理 v10。

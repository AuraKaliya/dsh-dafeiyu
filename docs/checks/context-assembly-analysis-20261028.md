# 大肥鱼上下文组装：首轮分析与讨论材料

日期：2026-10-28。本轮只做源码、当前配置及本机运行元数据分析，没有修改运行代码、配置、人格或记忆，没有重启、构建、运行测试、调用模型或向平台发送消息。分析期间工作树有其它发布工作，未纳入本次提交。源码指纹与脱敏计数见同名 evidence.json；历史职责审查仅作参考，本文件以当前实现为准。

## 结论

目前已有明确的身份、会话隔离、来源校验、历史整理和容量控制，但上下文不是一个统一装配过程。普通聊天、任务探索、成果评价、最终表达和失败恢复分别构造自己的材料包。主要需要讨论的是：哪些信息必须持续在场、记忆如何产生并被选中、阶段切换时如何交接，以及材料变化如何影响当前回复。

当前本机普通聊天的连续性主要来自原会话历史；持久工作记忆和阶段成长尚未形成实际装入。这个事实需要与“功能已经实现”区分，也需要与“记忆库里已经存在很多内容”区分。

## 1. 普通聊天实际路径

1. Core核验入站范围并定位原会话；有未发尾段时，先进入独立的续发/替代/等待判断。之后建立本轮Run，读取固定底色和已选择的阶段人格/试行条目。
2. DSH创建或恢复该会话。固定底色进入system段；渠道能力、真实发送者/消息时间/引用等来源信息和当前正文进入本轮输入。连续消息保留原消息的顺序和身份。
3. 每个DSH模型步骤的assemble阶段，ContextCoordinator逐个调用上下文提供者。当前包括工作状态、已选记忆证据、阶段成长、QQ表达偏好、任务工作区、已交付任务结果和待定回复事实。
4. 提供者先给候选条目；Core检查会话范围、有效期、来源版本，按区域优先级和UTF-8字节预算整条装入。预算不足的可选条目省略，不切成半段。普通区域的失败会标为unavailable；必需区域失败会阻止本次请求。
5. 受控资料作为带标签的runtime-context快照进入历史工作视图，资料文本没有被直接升为system人格规则。旧的自有快照会被替换；其它DSH上下文贡献保留。
6. 历史视图先处理失效来源和压缩，再与system、当前资料、工具schema组成请求。发送前检查完整请求大小与来源，流式输出期间继续检查有效性。
7. 模型使用工具后，下一步骤重新组装。模型可通过工具保存工作状态、选择记忆片段；返回回执并不等于已经永久成为人格。聊天原档、压缩视图和长期记忆分别保存。

关键位置：core/src/runtime.ts、context.ts、context-runtime.ts、compaction-runtime.ts、provenance.ts；memory/src/working.ts、index.ts。已核对当前安装的官方DSH agent-loop/system-prompt实现，assemble确实发生在模型步骤边界，不能误写成每轮仅装配一次。

## 2. 各阶段的材料不同

| 路径 | 当前主要材料 | 更新与连续性 |
|---|---|---|
| 普通聊天 | 原会话历史、底色、成长、表达偏好、已选证据、任务/交付状态、工具声明 | 每个模型步骤重新准备受控区域；Run人格选择在本轮准备并受核验 |
| 任务探索 | 独立Task会话、目标与选定输入、真实触发来源、动机/意图、接续检查点、已执行/未知操作、能力和技能目录、任务证据 | Run开始时顺序组装contexts；探索继续沿用该包，工具结果进入任务历史；能力加载后的恢复通过新Run重新装配 |
| 成果评价 | 固定底色、阶段人格、目标、操作事实、结果草稿、输出契约 | 独立无工具会话，不继承完整任务历史；当前输入未完整重放原始inputs和触发上下文 |
| 最终交付/阶段反馈 | 目标会话的底色、已选择人格及表达偏好，问题、核验后的证据、任务状态、渠道表达协议 | 新建无工具会话，不继承原聊天或执行器的整段历史 |
| 失败恢复/连续回复判断 | 当前人格、表达偏好、程序选择的失败/待发事实与新旧问题、严格决策契约 | 独立无工具会话，结果由程序校验后转换状态 |

独立结果会话有助于控制串话、内部报告泄漏和工具重做；同时要求程序充分提供对话交接材料，否则语气虽一致，仍可能漏掉原对话的细节。当前事实不等于已证明发生了表达断裂，需要后续用具体对话例子讨论和验证。

## 3. 本机实际观察

首次统计时，journal中有74次context.admitted（模型步骤装配记录，不是74条用户消息）。其中memory:working、memory:evidence、memory:growth、memory:task-workspace全部available=0；没有发生因这些区域超预算而丢弃条目的记录。已交付任务结果累计装入43条次，QQ表达偏好累计装入16条次，近期恢复状态累计装入2条次；累计条次包含同一条内容在多个步骤重复使用。

只读存量检查：memory_items中有1条未删除的preference，working.sqlite的states为0，persona_candidates为0，execution_contributions与execution_memory_requests为0。固定底色独立存在，并未因成长区域为空而缺席。本机未配置语义/混合检索服务；普通memory_search及显式片段选择仍可用。不能将“没有配置语义检索”写成“不能查记忆”。

当前配置：受控区域总预算16000字节；完整请求预算1000000字节，输出预留16000字节；每个提供者准备期限5000毫秒。人格区域由Host加入4000字节/优先级400；工作状态6000/500、结果6000/450、表达偏好6000/420、证据8000/200、其余默认4000/100。各区域上限并不保证都能同时装满。

最近两次普通聊天装入受控资料2433字节，完整请求分别179152、142269字节。最近活跃聊天会话持久请求头包含42个工具，工具schema序列化约39962字节。说明需要同时观察历史、工具定义和资料包，不能仅用受控记忆包的大小解释完整请求成本。以上是字节统计，不能直接称为token数。

历史压缩使用inputTokens=48000、默认75%触发和58%目标，约为36000/27840的估算压力。估算取DSH计量和UTF-8字节/3的较大值，不是当前模型的精确tokenizer。保留最近两轮、首轮、当前受保护任务及所有工具调用/结果对；此次读到普通聊天和一个任务会话均存在protected-or-insufficient记录，任务会话有19次。当前策略可能面对工具密集历史没有足够可压缩材料，但这些记录本身不能证明请求已超出模型窗口。

这些计数是正在运行实例的时间点观察，并非将旧版本全部历史视为新实现的运行验收。新的近期装配已包含刚上线的恢复事实区域。

## 4. 优先讨论的问题

### A. 记忆形成、候选召回和最终装入尚未连成默认路径

WorkingMemory明确读取已经持久选中的工作状态与证据；prepare不会依据新消息自动搜索全部记忆。context_retrieve本身是模型可调用动作，而本机尚未配置其检索依赖。阶段成长同样按已选择的采用/试行条目投影。现有机制提供工具与资格控制，但不能保证每次聊天都会主动形成或召回相关记忆。

建议讨论：程序是否在固定阶段提供一个有范围/容量限制的候选召回；模型判断关联性、是否采用、含义和保留价值。必须进一步区分“保存什么”和“这次读什么”，避免把每轮记录自动升级为长期人格。

### B. 不同路径的选择策略和更新时机需要明确统一

普通聊天按区域优先级选入；任务路径先放人格，再顺序追加记忆/插件条目，没有复用同一个按区域优先级的准入器。任务contexts在Run开始准备，普通聊天则每步骤重备。最终表达又只接收问题和核验材料，原会话中新追加的解释、已经说过什么、还欠什么需要明确交接。

建议统一每阶段必需事实及材料清单，而不是让所有阶段继承全部历史。需讨论任务执行中证据选择更新应在下一步生效，还是必须新Run接续；最终表达应带怎样的最小对话交接包。

### C. 必需内容应先留容量，容量判断需覆盖完整请求

静态发现：growth被pinRegion视为必需，但packet排序只参考配置required/priority。正式配置growth.required=false、priority400，仍排在工作状态、结果和表达偏好之后；前面的可选内容可先占用预算，后面的已选人格装不下时会报Required context exceeds budget。当前成长为空，没有本机触发证据；这是后续应验证的潜在容量问题。

程序可以控制必需包预留、区域/整体容量和合法替换，模型控制可选内容的重要性取舍。工具定义、能力摘要、会话历史、附件和输出空间也应有同一份容量账，避免只压缩记忆却忽略更大的历史/工具部分。

### D. 材料变化需要区分失权与正常更新

目前来源系统为请求登记已见历史、工具结果和上下文的依赖集合，输出继承这些依赖。受控资料或已暴露来源在准入后改变会阻止继续生成；失效历史会退出当前工作视图，原档保留。这个策略保守，但正常状态更新和新信息也可能影响正在回答的请求。

需要讨论冻结快照、下一步骤刷新和必须立即中止的边界：撤回、跨会话或权限失效应继续硬阻断；仅进度或新版本变化能否在安全边界重组装，应由程序定义。语义矛盾、是否改变目标、是否重答由模型判断。不能用无条件忽略版本校验来改善流畅度，也不能凭旧故障日志断言当时究竟是哪项资料变化。

### E. 组装记录应能解释“这次为何知道/不知道”

普通聊天已有available/selected/invalid/overBudget/unavailable和完整请求字节记录；任务路径更多只有总omitted，阶段间也没有统一材料清单。后续可记录每段来源类别、入选/省略原因、占用、刷新点和交接关系，不保存敏感全文。审查应把程序选择事实与模型对关联性、充分性的判断分别展示。

## 5. 建议的讨论起点

先确定每次思考必需的最小连续信息：我是谁、在和谁交流、当前原始问题及最新纠正、已经完成/已送达什么、仍欠什么。程序保证这些事实的身份与交接；模型决定如何理解、何时继续探索、如何评价和表达。

然后讨论候选记忆与长材料如何按需进入，以及从聊天到任务、从任务回聊天时携带什么。预算、压缩、刷新和失效策略应服务于这些产品约定。本轮不据此自动实施，也不改变现有人格、记忆或会话。

## 1. 目标与边界

本轮要实现：

1. 自动启动和手动启动能够共存，重复操作不会把正常运行的实例标记为失败，也不会生成多个实例。
2. 管理中心显示真实启动阶段、等待条件与错误，启动、停止、重启均有明确结果。
3. 本地 Cookie 经身份校验后可用于 HTTP 读取，旧匿名暂停不会形成无法验证新登录态的死循环。
4. 登录有效与接口可用分别判断；账号变化、凭据失效、风控、限流及网络错误分别处理。
5. 登录检查有缓存及并发合并，不把每次业务读取变成两次请求。
6. 已有搜索、批量帧、任务阅读记录、上下文切段及最终交付继续有效。

本期继续使用本地凭据文件，不开发自动提取浏览器 Cookie、扫码登录、自动续期、账号轮换、子代理或新的平台发布能力。凭据不通过聊天提交。开发与验收使用代码、测试环境及后台接口，不使用桌面电脑操控。

这份方案只规定后续工作；不据此立即修改正式配置、读取真实凭据、解除暂停、重启实例或关机。

## 2. 已确认问题与证据

### 2.1 启动问题

上一轮现场同时存在两组状态：实际 Host PID 为 11324，接受任务且 QQ 在线；管理控制器却为 `failed`，错误 `MANAGEMENT_ALREADY_STARTED`，重试次数为 5。

隔离复现确认：给一个已有子进程、状态为 `running` 的控制器再次执行 `start`，子进程保持不变，控制器却变成 `failed` 并安排重试。

代码原因：

- `management-runtime.ts` 的 `start()` 将已有进程当作异常；`control()` 将该异常统一转为启动失败；`scheduleRetry()` 又未排除存活进程。
- 自动重试直接进入 `start()`，没有与按钮操作共享完整的并发控制。
- 控制器在创建子进程后返回，实例尚可能处于启动中；界面只刷新一次，也没有根据运行状态禁用启动按钮。
- `call()` 只允许 `running` 状态访问子进程，管理状态一旦错误，正常实例也会在管理中心表现为离线。
- 当前停止流程在没有子进程时不保证把所有状态归一为 `stopped`；旧计时器、旧子进程回调也需要统一治理。

上一轮验收验证了冷启动和任务链路，但未覆盖“自动启动后再次点击启动”。本轮必须补上实际按钮事件及管理调用链测试。

### 2.2 Cookie 接入问题

现有代码已经支持 `bilibili.session.file`、`expectedUid`、读取 `SESSDATA` 和通过登录接口核对 UID，可以复用。

仍需补齐：

- 当前 HTTP 共用一份暂停状态，旧匿名暂停会阻断带 Cookie 的登录校验。
- 配置 Cookie 后，每次 `read()` 都先请求登录接口，没有登录检查缓存。
- 服务层有“只要 pause.held 就跳过 HTTP”的判断，不能仅修改底层客户端。
- Host 的 B站管理入口目前只允许 `status`；不能直接从 UI 发起验证操作。
- 管理控制器对子进程调用固定等待 15 秒，连续身份检查与业务探测可能超过该时间。
- 配置只校验 HTTP 内容账号与私信账号的一致性，尚需同时校验浏览器预期 UID。
- Cookie 有无不能单独代表请求身份和故障范围：字幕及媒体 CDN 本来就不携带登录 Cookie，不能因此被当作匿名 API 通道。

## 3. A包：统一实例生命周期

### 3.1 一个控制入口

自动启动、手动启动、重启和自动重试进入同一个生命周期控制器。维护当前操作、目标状态、子进程代次及取消信号，避免多个入口分别修改状态。

每次创建子进程生成新的代次。子进程消息、退出回调、连接回调及重试计时器均绑定代次；过期回调不得改变新进程状态。所有创建路径都须先核对目标仍为运行、没有现存子进程、实例占用权可用。

启动请求使用操作 ID；重复请求复用原操作。请求等待超时表示“结果尚未确认”，通过操作 ID 查询，不能立刻重发创建进程。

### 3.2 明确状态转换

| 当前状态或事实 | 操作 | 要求 |
|---|---|---|
| 已停止，无进程 | 启动 | 创建一个启动操作，进入启动中 |
| 启动中 | 再次启动 | 返回同一个操作及当前进度，不创建新进程 |
| 已运行 | 再次启动 | 返回当前运行状态，不报错、不重试、不改变 PID |
| 管理状态失败，但保留自己的存活进程 | 启动或状态核对 | 经当前 IPC 通道确认实例就绪后恢复管理状态；无法确认则显示待确认，不启动第二个实例 |
| 启动中、等待依赖、运行中或失败 | 停止 | 取消启动及重试，清理本控制器拥有的资源，最终进入已停止 |
| 已停止 | 再次停止 | 正常返回已停止，清除过期操作和计时器 |
| 停止中 | 启动 | 明确返回正在停止；不得改成失败或并行创建进程 |
| 任意可控制状态 | 重启 | 在一个操作中按停止→确认释放→启动执行；重复同一请求复用操作 |
| 重启或启动过程中 | 用户停止 | 停止优先，后续回调不得再次拉起实例 |

“进程存在”与“实例就绪”分别表达。正常启动须以当前代次的 `INSTALL_READY` 或有效 IPC 健康响应为依据；不凭 PID 存在或旧状态文件判成功。

### 3.3 启动阶段、错误和重试

内部记录配置检查、QQ 依赖、桥接准备、子进程创建和实例就绪等阶段；UI 使用“检查配置”“等待 QQ”“启动实例”等用户能理解的文案。

- 只有可恢复的依赖或临时启动故障进入有界重试；沿用现有有限等待序列作为初始策略。
- 已有实例、重复请求、正常停止不进入重试。
- 配置缺失、Node 路径错误、数据库版本不支持、账号不符等确定性错误停止自动重试，并显示具体处理方式。
- 停止、重启、启动成功及插件卸载均撤销旧计时器。启动等待必须可取消，不等 QQ 等待循环结束后又创建进程。
- 当前错误在确认启动成功或正常停止后清除；历史错误保留为诊断记录，不继续充当当前状态。
- 重复检查 OneBot 时保持正确的资源归属：本插件创建的服务仍由本插件负责清理；复用用户已启动的外部服务不得误认为自有进程并停止。
- 实例的 `running` 与 B站能力的 `degraded` 分开显示。B站匿名暂停不能让“启动实例”重新变为可用，也不能把整个实例标为启动失败。

现有受管理停止时限可保留，但强制收尾必须限于本控制器确认拥有的进程；出现效果或归属不明时明确报告，不按进程名批量结束。

### 3.4 UI 与管理协议

管理快照包含生命周期状态、当前阶段、操作 ID、代次、PID、当前错误、下一次重试时间和最近核对时间。字段集中定义在共享契约，不由前后端各猜一套。

启动、停止和重启返回“已受理/已完成/未受理”及操作 ID，不把“启动命令已发送”当作“实例已经运行”。保持现有调用兼容；新增请求标识采用兼容字段，并统一更新打包客户端。

界面要求：

- 启动中、运行中、停止中禁用启动按钮；停止和重启按钮按真实状态及操作冲突规则启用。
- 等待登录有独立文案，不能显示成无法解释的“正在读取”。
- 操作进行中以约 1 秒间隔查询；管理页可见且状态稳定时降低频率，隐藏或卸载后停止查询。具体间隔可按测试调整，必须防止请求重叠。
- 拒绝过期响应覆盖新快照；刷新状态不能清空未保存的配置草稿。
- 操作结果为失败时展示原因，不能因外层协议 `ok:true` 就忽略内层失败状态。
- 状态查询只读取状态，不触发模型调用、账号验证或启动重试。

### 3.6 A包验收

| 场景 | 必须观察到的结果 |
|---|---|
| 自动启动后再点击启动 | PID、启动次数不变；仍为运行中；无新错误、无重试 |
| 自动启动与手动启动同时到达、连续点击启动 | 仅一个启动操作、一个子进程 |
| 启动中或等待 QQ 时停止 | 可取消，最终无迟到子进程及重试计时器 |
| 重启期间停止、旧退出回调晚到 | 停止保持生效，旧事件不污染新代次 |
| 连续停止、没有子进程时停止 | 状态均归一为已停止 |
| 已运行进程被管理层误标失败 | 经真实 IPC 核验恢复，或明确待确认；不复制实例 |
| Node 不存在、配置错误、版本不支持 | 错误准确，不进入无意义自动重试 |
| 暂时依赖失败后恢复 | 有界重试且只有一个实例，成功后取消剩余重试 |
| 复用外部 OneBot、本插件自建 OneBot | 各自归属正确，停止不误伤外部服务，不遗留自有服务 |
| 实例正常但 B站受限 | 实例显示运行中，B站单独显示限制原因 |
| UI 页面切换、响应乱序和未保存草稿 | 无重复轮询、无状态倒退、草稿保留 |
| 非 owner 请求生命周期控制 | 请求被拒绝，无进程变化 |

测试不能只检查文案或 mock 返回值。至少覆盖：受控时钟及进程事件的生命周期测试、真实测试子进程的 IPC 集成、渲染后的按钮事件→管理协议→控制器链路。测试环境不连接真实 QQ 消息发送。

部署 A 后通过后台接口验证冷启动、重复启动、停止及重启，并核对实际 PID、就绪回执和客户端版本。不使用桌面自动操控；组件事件测试必须使用将要发布的界面逻辑。

**A阶段通过条件：所有新增用例及原有完整回归通过；正式部署冷启动和重复启动通过；真实进程状态与管理中心快照一致。A 独立保存验收记录与回退包后，才能进入 B。**

## 4. B包：已验证的 Cookie 登录态 HTTP

### 4.1 凭据与配置

沿用 `bilibili.session: {file, expectedUid}`。凭据文件沿用现有白名单格式：`uid`、`SESSDATA`，以及已经支持的可选字段 `buvid3`、`bili_jct`。本期只实现读取，不为读取功能强制要求不使用的写入凭据。

- 配置只保存文件路径及预期 UID。Cookie 原文只在本地请求层使用，不进入模型上下文、管理接口返回、诊断数据库、普通日志、Git 或发布包。
- 凭据文件位于实例外部凭据目录，使用合适的本机访问权限；如备份凭据，备份仍保持相同保护，不混入验收报告。
- 延续路径、普通文件、大小和字段检查；拒绝非法 Cookie 字符。文件替换使用原子写入，读取时取得完整快照。
- 配置中的 UID 不是认证结果，必须由服务端返回的登录 UID 核对。
- 同时配置内容 HTTP、浏览器或私信时，预期账号必须一致；错配在启用前报告。
- 修改 UID 或凭据文件路径须先停止实例再应用；同 UID 的凭据内容更新可使缓存失效并重新验证，不必清空任务数据。
- 配置了 Cookie 但 Cookie 已失效时，不静默回退匿名 HTTP。

管理 UI 不增加 Cookie 明文输入框。首版提供清楚的本地文件格式与放置说明；缺少真实凭据时仅完成离线部分，不要求用户把 Cookie 发进聊天。

### 4.2 登录有效与读取可用分开建模

| 层次 | 表达内容 | 示例 |
|---|---|---|
| 凭据状态 | 是否配置、格式是否有效、当前凭据代次 | 未配置、待验证、格式错误 |
| 账号验证 | 是否登录、UID 是否匹配、最近验证时间 | 有效、过期、账号不符、验证中断 |
| 读取能力 | 某通道及接口最近是否可读、是否暂停 | 视频可读、搜索受限、等待冷却 |
| 实例生命周期 | 大肥鱼主进程是否可用 | 运行中、停止中 |

登录接口成功只能更新账号验证状态，不能解除视频、评论等接口的风控。显示“登录有效，但视频读取仍受限”应当是正常且可解释的状态。

### 4.3 登录校验缓存与并发合并

增加一个负责凭据快照与验证结果的组件，供所有 B站 HTTP 入口复用。

1. 缓存键包括预期 UID 与规范化凭据内容的内部指纹；不能只按文件路径，也不因 JSON 缩进变化产生新身份。
2. 建议初始登录验证有效期为 5 分钟，可据实测调整。这是本地复核间隔，不是平台 Cookie 的有效期承诺。
3. 同一凭据代次最多一个进行中的登录检查，并发调用共享结果；独立调用者仍须验证自己的任务授权和取消状态。
4. 一个等待者取消不能误取消其他任务仍需要的共享检查；停止实例、所有等待者退出或凭据代次变化时应释放相关资源。
5. 明确登录失效、UID 不符、凭据更新、验证超时等情况立即废弃相应验证结果。一般网络失败不误报为 Cookie 过期。
6. 请求发出前及消费结果前核对凭据代次；途中换凭据的旧结果不得写入新代次缓存。
7. 需要 WBI 的接口复用已取得的登录接口材料，单独验证签名材料是否齐全，不再无条件多请求一次登录接口。
8. 进程重启后不能仅凭磁盘中曾经验证成功，就长期沿用该结论；重新建立当前进程的有效校验。

在同 UID、同凭据、未过期且无错误的固定测试中，20 次业务读取应只有 1 次登录验证，即 21 次 HTTP 请求。业务材料缓存产生更少请求时可以低于该值；不得变成每次读取都先验证一次。

### 4.4 有界的验证与恢复流程

管理中心增加“验证登录”和“测试读取”操作。首次配置可串成一个可追踪的流程：

```text
核对本地配置
  → 核对尚未结束的冷却/共享暂停
  → 一次登录验证
  → 核对 isLogin 与预期 UID
  → 一次指定业务接口读取
  → 分别更新账号状态与该接口状态
```

旧匿名风险暂停下，必须存在一个仅供可信管理操作使用的验证入口。它取得短期、单次、绑定 UID/凭据代次/目标接口的探测许可；不能给普通工具增加 `skipRiskCheck` 参数。

该许可仅处理“已确认属于匿名 HTTP 的暂停”，仍遵守有效冷却时间、共享风控及验证挑战。来源不明的旧暂停保持保守范围，不能猜测为匿名问题后自动放行。

身份验证成功后，测试原失败接口；成功才使对应的登录态读取路径可用。匿名失败与暂停历史保留，不能调用全局清空来宣布恢复。失败时记录本次真实结果，返回明确状态，不在匿名、Cookie、浏览器之间循环尝试。

默认一次验证流程最多 1 次登录请求和 1 次指定业务读取。等待冷却时显示预计时间，不占用一个长时间悬挂的前端请求。连续点击复用正在进行的流程，不追加探测请求。

### 4.5 管理接口接线

必须同时修改共享契约、管理控制器、Host 分发、B站服务和 UI，不能只添加按钮。

- Host 目前拒绝 B站非 `status` 操作，改为严格白名单：查询状态、开始账号验证、开始指定读取验证、查询验证结果、取消验证。
- 接口仍要求现有 owner 身份；模型阅读工具不获得这些管理操作，也不能传原始 Cookie 或凭据路径。
- 开始验证快速返回操作 ID，后台执行，页面查询进度；保留现有普通 IPC 等待边界，不靠把 15 秒统一扩大到数分钟解决问题。
- 验证操作绑定账号、凭据代次和实例代次。重启或凭据变化后，旧任务标为中断，不自动重放网络探测。
- `status` 及页面刷新完全只读，不请求平台，不调用模型，也不打印登录接口原始响应。
- 用户可见信息包括预期/已验证 UID、登录状态、验证时间、读取结果、等待时间与可执行建议；内部 Cookie 指纹及原文不展示。

### 4.6 暂停范围与通道选择

诊断需要表达全局冷却、身份/通道及接口范围，不能继续用一份 `held` 判断所有请求。

- 匿名 API、已验证 UID 的 API、浏览器以及媒体/字幕资源请求分别记录来源。账号范围的限制按 UID 归属，不因 Cookie 更新自动重置。
- 保留已有总请求节奏及有效 `Retry-After`；不同任务、登录验证和业务读取共用节奏控制，不各自并发打满。
- 明确登录失效使登录态不可用；明确验证挑战或账号级限制阻止同账号的自动跨通道尝试。
- 网络错误和接口级问题按实际可确定范围处理；无法确定范围时保守暂停并报告。
- 路由选择集中在客户端/服务的统一入口；替换服务层旧的全局 `pause.held` 提前拦截。
- 默认使用已经验证且当前可用的登录态 HTTP。浏览器保持既有授权与账号核验；画面采样继续走现有批量帧流程。
- Cookie 只发送给既有允许的 B站 HTTPS API 主机，不随重定向转发；字幕及媒体 CDN 继续不附带登录 Cookie。
- 插件健康状态按当前实际可用通道计算。已弃用匿名路径的历史暂停单独展示，不能永久掩盖登录态路径已经可用的事实。

### 4.7 长任务与账号变化

认证失败不清空阅读进度，不新建任务从头刷。复用现有等待和检查点机制登记认证阻断，模型只收到简短状态及恢复建议。

验证恢复后，仅对原先已授权、同 UID、同任务意图版本、没有未知操作效果的任务按既有机制接续；其他任务保留等待或使用现有继续入口。总截止时间、段数及上下文预算不重置。

凭据更新使相关认证缓存、探测许可及正在进行的旧代次请求失效。账号改变还要使账号相关材料缓存和浏览器复用失效；原阅读记录作为历史保留，不能把旧账号观察未经重新核对混入新账号任务。

模型只携带读取所需状态和短进度，不携带 Cookie、完整登录响应、探测日志或周期性状态轮询记录。沿用上一版任务隔离、约 4 KB 阅读工作视图、24k/32k 输入预算及新会话切段。

### 4.8 数据升级

新增持久数据限于认证元数据、分范围暂停状态和验证操作记录，不把 Cookie 本体写入数据库。字段设计确定后建立 **B站 v5→v6** 显式迁移；已有 v2/v3/v4 通过既有迁移链到达 v5 后再升级。

迁移要求：

1. 停止实例、取得占用权、校验身份、布局和完整性，再生成一致性备份。
2. 原有页面、来源、阅读记录、历史版本、游标、回执与诊断尝试完整保留。
3. 旧暂停根据可核对的失败记录迁移；缺少证据则标为来源未明的共享暂停。保留最晚冷却截止时间。
4. 不把“配置了 session”迁移成“账号已验证”，不凭历史成功生成当前认证。
5. 重启不自动重放未完成验证；清理过期探测租约后保留中断记录。
6. 迁移后逐表比较原有数据的行数与摘要，验证完整性及重复迁移行为。
7. 不在 BiliStore 构造器中隐式迁移；旧包应明确拒绝新版本库。

## 5. B包验收

### 5.1 离线与集成

| 场景 | 必须观察到的结果 |
|---|---|
| 合法 Cookie、UID 一致 | 登录验证通过并能取得业务资料 |
| 文件缺失、非法字符、格式错误、UID 不符 | 分类准确；本地检查失败不发送业务请求 |
| 登录接口返回未登录或登录失效码 | 标为需更新登录态，不标成普通数据解析失败 |
| 已有匿名暂停后发起管理验证 | 冷却结束且无共享阻断时仅执行获准的一组探测；旧匿名历史仍在 |
| 登录验证成功、视频接口仍受限 | 账号有效与读取受限同时可见，不全局清除暂停 |
| 多任务同时读取、连续点击验证 | 同代次登录校验及管理操作合并，无请求风暴 |
| TTL 内连续 20 次业务读取 | 登录接口调用 1 次；在无业务缓存场景总 HTTP 请求 21 次 |
| 到期、凭据更新、途中换文件、并发调用者取消 | 正确失效与取消，旧代次结果不提交，新校验不串号 |
| HTTP/浏览器/私信预期 UID 不一致 | 配置不能启用，错误指出具体冲突字段 |
| 429、风控、验证挑战、网络故障 | 按分类及范围执行等待/暂停，不自动切换身份重复尝试 |
| 字幕和媒体 CDN、重定向 | Cookie 不进入资源主机或重定向目标 |
| 高频管理状态查询 | 平台请求数和模型调用数均为零 |
| 实例停止、崩溃、验证中重启 | 无泄漏租约、无自动重放、状态可解释 |
| 登录失效后恢复长任务 | 已读记录保留；授权、来源和原总期限继续有效 |
| 凭据泄漏检查 | 种入测试标记，管理返回、诊断落盘、日志及模型请求均无 Cookie 原文及编码变体 |
| v5→v6 与历史升级链 | 原数据保留、错误身份无写入、未知版本拒绝、重复迁移无副作用 |

使用真实客户端、服务、存储和 Host 接线，外部 HTTP 响应用固定测试数据替换。状态机、缓存和故障范围测试用可控时钟，避免等待真实冷却时间。

同时运行原有完整回归与冒烟，不以某几项 Cookie 测试代替整体测试，也不预先编造未来测试数量。

### 5.2 真实账号小范围验收

前提：用户已经通过本地文件提供合法登录态，账号与配置一致；管理中心启动修复已经独立验收；有效冷却期已经结束。

顺序：一次登录验证 → 原失败视频信息 → 一次搜索 → 一页评论 → 一个字幕轨的两次分页读取。使用选定的普通公开视频，不发送评论、点赞、私信或其他发布动作。没有字幕的视频记录为材料不具备，换用确认有字幕的样本，不把无字幕误报为认证失败。

每步记录是否真正发出请求、HTTP/平台结果码、耗时、登录验证次数及缓存命中；不记录 Cookie 或不必要的账号资料。任一步出现账号不符、登录失效或新的风险暂停，就停止后续验证，保存结果。

随后验证真实登录态下的重复资料读取和短连续任务，再检查既有长任务验收：20 视频/7 段的固定数据回归、来源继承、仅最终段交付、取消及重启恢复。真实平台与固定数据测试分别报告，不能相互替代。

**B阶段通过条件：代码与离线测试通过、迁移演练通过、真实身份校验通过、原失败接口及搜索/评论/字幕样本读取通过，且请求计数、数据保留及凭据隔离符合要求。**

如真实 Cookie 未提供、平台仍受限或样本条件不具备，报告必须写明“开发/离线验收通过，真实平台验收待完成”及具体阻断项，不能宣称整体验收完成。

# 本机正式QQ媒体、近期回看与回复延迟接入

2026-10-27。用户要求把已开发的读图、读语音、文件读取和历史能力接入本机正式实例，仅做必要测试；补充确认可对感兴趣的历史选择引用回复，回看最早只能到观察前24小时。此次未连接服务器、未修改SnowLuma代码、未发QQ测试消息。

## 历史工具未调用的实际原因

只读核对本机真实会话的request/header，`qq_browse`等工具已经交给模型，注册没有失败。原始QQ提问是在询问合并转发记录、链接和语音能否读取，并不是要求执行近期回看；模型直接回答能力范围，没有调用浏览工具属于合理行为。此前仅凭没有调用记录推断工具使用异常，证据不足，应予更正。

实际缺口是正式实例没有装配媒体，以及原接口仅浏览已收到的文字缓存，没有读取平台历史和合并转发。此次补齐接线和能力说明：依赖历史内容的回答先实际查询，不把“尚未查询”说成“不能查询”；普通能力询问不强制读取私人记录。

## 已接入的能力

- 图片：原版OneBot定位、受限QQ媒体下载、实际FFmpeg解码、官方DeepSeek inline图像请求。使用现有DSH凭据引用，没有复制模型密钥或修改官方模型循环。
- 语音：优先消费原版SnowLuma `get_record(out_format: wav)` 返回的转换后base64，保留身份前后核验、字节和格式上限；不再误读原始Silk地址。仅该动作的响应上限放宽到32MiB，其他动作仍为2MiB；验证含超过2MiB的转换音频。
- 本机Whisper、YAMNet及文档处理器：依赖和模型迁入正式根目录 `dependencies/`，文件hash及版本固定；两个音频后端分别使用1GiB Windows Job上限。真实运行发现原YAMNet校验误写527类，实际固定模型输出和标签都是521类，已修正。512MiB配置失败、1GiB配置下真实处理通过，不用模拟结果冒充后端可用。
- 文件：通过实际QQ附件引用获取，在受限文档处理器读取text/json/csv/pdf/docx/xlsx；不是任意本机文件、终端或管理员权限。

本机正式配置启用媒体接收、语音任务证据接线、视觉、语音识别、声音分析和文档处理；未启用语音输出、B站或管理员执行器。未扩充QQ任意收件人能力。

## 24小时观察与引用

`qq_browse(includeRecentHistory:true)`按需调用原版群/好友历史接口，最多5页、每页20条。只把观察起点前24小时内、时间明确且目标一致的记录追加到当前会话缓存；旧、未来、未知及异会话记录不进入回看。平台响应没有时间筛选参数，跨过24小时边界的内容立即丢弃并停止继续翻页，不存入本机或模型材料。

缓存回看也受相同24小时窗口限制，不能通过已有旧缓存绕过。分页保留该次观察起点，使用实际消息时间而非午夜；原记录不因超出窗口被删除。保留已有文字、撤回标记和会话边界，只以已核验平台数据补齐缺失时间/转发定位信息。缓存上限200条，不为补取挤出既有实时消息；覆盖不足如实报告。

历史不会批量进入新入站或触发新任务，但核心可按兴趣调用 `qq_reply_quote`，选择本轮实际浏览到且在24小时内的同会话消息。引用选择持久化，普通回复与真实QQ任务结果使用各自绑定键，不改变任务受理消息；任务结果仍经过核心人格整理、来源核验和交付。没有真实QQ交付来源的本地任务不能借此发消息。发送前及延迟后重新检查授权、撤回、过期与群助手状态。

`qq_forward_read`只使用实际收到、绑定当前会话的转发定位，最多读取20个近期节点；转发署名不授予身份，内容不授予新指令权限。时间未知/界外节点不披露，嵌套转发不递归展开；节点内受控媒体可由媒体工具按需读取。无额外历史同步周期，群助手仍沿用原30秒群列表入口。

## 回复延迟

普通安装 `qq.replyDelay` 默认true。本机已启用：正文生成后等待 `min(10000, 2000 + Unicode字符数 × 20)` 毫秒；非文本部件增加0。对一条逻辑回复只在首个未发送部件前等待一次，后续分段不重复等待；已发送或结果不明的消息不因延迟重发。只读计时核对空文本约2014毫秒；这不是承诺包括模型和平台耗时的总延迟不超过10秒。

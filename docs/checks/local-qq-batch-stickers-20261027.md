# 本机 QQ 连续消息合并与本地表情库

2026-10-27。依据用户授权实现并接入本机正式实例；不更新服务器，不修改 SnowLuma，不向 QQ 发送测试内容。使用现有身份、会话、人格及记忆，沿用群助手过滤、观察前24小时回看和现有发送延迟。

## 实现

同一账号、会话及发送者的消息，在最后一条之后静候5秒再交给 Core，持续输入最长15秒，单批最多10条、32,000字符与8个媒体引用。群聊首条仍须满足现有关注条件，同一表达的后续短句无需重复提及；达到容量或最长等待时分批，连续输入不因分批丢失关注。其他发送者有独立窗口。明确的主人任务控制立即处理并清掉其尚未提交的批次。

每条原消息的 ID、时间、原文、媒体与引用身份分别保留，Core 收到显式批次，默认回复锚定最后一条原消息；任务目标从整批真实文字取得。读取媒体默认列出本批全部来源。重复事件不延长等待，历史浏览不进入队列。撤回移除待处理来源，关注来源全部失效时取消；处理中任一原消息撤回会停止相应处理。群助手、退群及重新接入的代际边界继续生效。未提交批次持久保存；已提交的原文由 Core 保存，QQ 批次表只留结果状态，避免长期复制正文。

表情库在 QQ 数据目录的 `stickers/objects/` 保存原始字节，元数据及发送选用凭据在 `qq.sqlite`。QQ库从7显式升级到8，新加批次、表情和选用记录表，旧表只增不改。JPEG/PNG/WebP/GIF 原图按 SHA-256 去重，GIF发送不经静态图转换。视觉描述只证明已看实际图像采样，不声称理解完整动画。默认容量512MiB、1000项、单图16MiB；满库拒绝新收录，不自动删已有内容。

她可以自行挑选已经实际读图且适合作为表情的 QQ 图片，记录名称、描述和用途标签；不指示她自动收藏私人照片或截图。自动收录只在来源会话使用，主人显式提升为通用后才可跨已授权的QQ会话使用。收藏副本独立于媒体缓存和24小时回看窗口；来源消息撤回会停用相关收藏。停用、修改和删除使旧选用凭据失效。

发送时模型选择库内 ID，目标和最终正文由 Core 确定，通常一轮一张，可配文字或纯表情。普通回复和QQ任务结果都经过原有来源校验、人格整理、群助手检查和发送账本；结果不明不自动重发。单独启用表情发送不会放开任意图片、语音或文件发送。文字生成后原有2—10秒延迟继续适用，纯表情的文本量按0计算。

主人管理使用真实QQ原文与已绑定主人身份，示例：

- 私聊 `表情管理：列表`，可在后面附名称关键词，查看所有来源会话的库内条目。
- `表情管理：通用 开心小鱼`，将指定收藏提升为通用；同名时使用实际ID。
- `表情管理：停用 开心小鱼`、`表情管理：启用 开心小鱼`、`表情管理：删除 开心小鱼`。
- `表情管理：改名 开心小鱼 => 晚安小鱼`。
- `表情管理：标签 晚安小鱼 => 晚安,招呼`。

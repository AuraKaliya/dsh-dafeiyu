## 确认的现象

1. 第一次主人连通性检查请求被受理为 `self-exploration`，运行 `33b7e94d-3b93-45cc-b354-f495105e1459` 在 17:59:37 进入 waiting，错误为 `TASK_OBJECTION_UNRESOLVED`。目录查询成功，但此种来源不能通过外部任务授权，`dsh_tool_call` 未出现在可用能力中。阻塞说明已经经过 QQ 人格交付。原始入站确为主人要求检查 DSH 连通性；不是凭内部目标推定。
2. 随后搜索请求正确受理为 `explicit-task`。运行 `3406856c-6524-46a7-8fd6-bee277798dea` 在 18:01:37 开始，18:04:27 completed。DSH 程序事件确认实际分派 11 次搜索、网页和浏览器工具。由此不能把本次故障归因于 DSH 未连接。
3. 搜索运行末次网页读取已经分派，随后在本地观察记录流程出现 `PRIVATE_INPUT_REJECTED`；操作被记为 unknown。独立程序回执已存在，因此不能把这个本地后处理错误当成平台操作尚未执行。
4. 搜索最终交付 `854a532c-5fd0-4e9f-8465-8810d05da569` 于 18:04:30 开始人格整理；整理会话在 18:05:07 完成，18:05:10 进入 verifying。直到 18:19:27 才 rejected，错误 `SOURCE_STALE`。该时间与任务结果的 15 分钟有效期完全对应。没有进入 QQ sending，没有最终发送回执。
5. 这两轮没有调用 `qq_progress`。目前阶段反馈只是模型可选能力，没有程序确保长任务一定产生可见状态。搜索执行及最终核验期间因此没有阶段进展回到 QQ。
6. 18:21:35 复查：实例 ready、QQ online、群列表 current、运行/路由/出站队列均为 0；两份任务交付中 sent 1、blocked 1、pending 0。失败任务已经结束等待，但不会自行视为已发送。

## 核验阶段的性能线索与边界

- 核验约 68.5 KB 的问题、十项工具观察及任务答案，使用与主分析相同的模型路由和 reasoning=max，输出上限为 1024。已检查官方适配器确实采用请求的输出上限，不能归因于配置中的更大输出上限覆盖本次请求。
- `packages/memory/src/expression-runtime.ts` 每个流式片段都调用 guard；`native-expression.ts` 的 guard 包装再次 open packet。open 会 build 并比较证据。外层人格/交付 guard 还会再次执行来源、依赖、人格和 packet 检查。DSH 证据检查同步读取、解析回执文件并计算哈希。大证据及依赖链会被反复验证。
- 此核验没有独立的短截止时间。外层期限使用两倍任务时间加发送时间，本机可达 20 分 30 秒；实际先触发的是结果 15 分钟有效期。流式空闲超时不等于整个核验的截止时间。
- 核验期间 3.017 秒采样消耗 5.3125 CPU 秒，相当于约 176% 单核，内存约 1088.7 MiB；到 18:20 进程累计 CPU 1394.67 秒、工作集约 1.38 GiB。18:21:35 核验终止后同样 3 秒采样为 0.5% 单核、785.5 MiB。
- 源码与资源采样共同支持“逐片段重复执行完整证据验证造成严重本地开销”的判断；尚未做 CPU 调用栈采样，不能把全部 14 分钟核验耗时精确归到某一函数，也不能据此断言模型服务无额外延迟。

## 同时确认的结果处理缺陷

- 父进程桥接将工具 value 和渲染 content 一并投影，部分数据重复；超过 100 KB 整体丢弃为 omitted。
- 宿主将超过 7000 字符的结果序列化后硬截前 6000 字符作为 preview。多份搜索/网页结果因此成为半截 JSON 字符串，转义和页面附属内容挤占正文，模型需要重复读取或尝试浏览器。该现象已从既有回执确认，不能用它单独解释最终核验的全部耗时。
- 对最后一份既有回执离线重新运行脱敏函数，已脱敏 preview 仍发生二次变化：原观察文本 6524 字符，二次处理 6525 字符，命中 token 样式。`recordCapabilityObservation` 对任何新增脱敏变化直接拒绝。未打印或保存敏感原值。这是脱敏非幂等与序列化文本叠加的本地后处理问题，不表示用户提供了密钥。
- 错误发生在工具分派之后，现有兜底把它降为 unknown，缺少“操作结果已得到、证据保存失败”的分别记录。

## 修复顺序建议（尚未实施）

1. 先限定最终核验总耗时；用轻量、可失效的来源版本检查替代每个流式片段重建全量证据，完整核验放到关键边界。保留发送前授权、来源变更、撤权和幂等保护，不能直接绕过核验发送草稿。
2. 工具结果保留结构、来源及分页入口，避免硬截序列化 JSON；修复重复脱敏的幂等性，分别记录工具执行结果和本地后处理失败。
3. 修正主人自然请求的任务动机选择，使连通性检查等明确要求进入主人任务；长任务增加可见的延迟/失败状态，仍经原 QQ 人格整理，避免只依赖模型主动选择进度工具。
4. 本机补充与本次缺陷直接相关的“大工具结果 + 多流式片段 + 核验截止 + 脱敏重入”检查。此前 98 项相关测试主要是脚本模型和组件测试，没有覆盖本次真实长搜索与流式核验组合。这是原验收的覆盖缺口，不能继续把旧通过数当成本次实际交付已验证。

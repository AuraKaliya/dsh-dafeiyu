# 统一媒体5D-1：QQ来源与受控取件

2026-10-25；方案细分基线`9dc1bd3`。

QQ库升级到v5，追加媒体源、媒体草案、媒体交付计划和部件表。后三表在5E启用，当前不执行发送。旧文字、版本hash、群快照和回执保持；旧库必须显式迁移。测试中的旧版本构造同步排除新表，避免用不符合旧结构的伪造库测试迁移。

来源绑定账号／会话／消息／段序、实际入站指纹及版本。提供给模型的描述不包含平台文件句柄、URL或本机路径；私有解析字段只留在QQ运行库。来源修改推进版本，撤回和迟到重复不复活。句柄可按72小时／最多2048个回收，历史来源元信息保留；句柄过期不能继续取件，也不等于删除历史观察。

读取本地OneBot缓存需显式根目录，拒绝UNC、设备／数据流路径、越界／链接逃逸、读取中路径或文件改变。支持真实字节区间。HTTPS限定允许的主机、443端口、公开IPv4解析地址并固定实际连接地址；无认证URL、不跟随重定向、不把OneBot令牌送往文件地址。IPv6-only远端当前拒绝，后续按需增加安全支持。

平台解析采用`get_image`、`get_record(out_format=wav)`与`get_file`；原始silk URL不能冒充已转换音频。账号在解析前后和流结束核验，流中检查来源／范围。控制接口响应限制2 MiB，避免资源接口返回过量base64。[NapCat文件接口说明](https://napneko.github.io/develop/file)提供了这些字段和转换机制的参考；这不等于本项目已连接真实平台验收。

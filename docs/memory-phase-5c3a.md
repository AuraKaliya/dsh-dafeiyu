# M5C第三部分C3-A：多代来源链与无损组合验收

日期：2026-10-24。项目0.12.0、核心0.9.0；contracts、memory、timeline保持0.8.0，依赖核心的本地包更新版本约束。本机开发，全部样本虚构，未连接或修改服务器、真实QQ或模型绑定。

## 实现结果

多代来源记录保存直接父片段、父视图版本/哈希/日志位置、原始来源闭包和生成代数；代码递归重算，防止漏依赖、伪造父关系和循环。父摘要退出上下文后，其历史来源证明仍可使用；正常模型回查继续校验当前选择与来源有效性。

展示状态与来源有效性分离。superseded表示被已提交子摘要替代，不表示原始来源被删除。来源失效由权威状态校验，不能因展示状态改变而绕过。已删除、已恢复但版本变化的原文不能使旧摘要复活。

组合保持kind和正文逐字不变，限定条件不经过模型改写。去重同时比较任务、原始事件身份/角色/哈希、完整依赖状态、kind和正文。不同来源的同文内容保持独立，不把重复摘要计为更多证据。模型正文只显示新短引用和有效片段，完整来源链保留在DSH日志；回查选中片段时附该片段的父关系和原始来源入口。

历史片段组合后获得新的包/片段引用，直接父引用保留在证明中；不能要求被替代的容器消息ID不变。同一新包内发生局部失效时，无关片段的编号、正文及引用继续保持。旧父引用不自动转发到子代，避免绕过选择与失效规则。

沿用DSH阈值、预算、冷却和最小收益。触发后优先尝试相邻摘要包无损组合，不跨普通对话或其他插件节点，不处理当前工作任务。组合不调用模型。DSH估计token收益不足或字节没有减少时不提交；无损组合深度上限16，超限等待后续原文重建能力，不截断依赖。

## 持久化与恢复

一次DSH surface替换完成新包进入和父包退出，compaction/prune用于现有token计量。清单、视图与prune准备记录没有替换消息时不会生效；提交消息落盘后重启恢复子视图，不重复显示父包。提交前复查来源、父视图和surface版本，flush失败阻止模型请求。

不建立第二套事实数据库或新增后台服务。现有v1/v2保守摘要、C2分片与局部视图继续可读。新增composition字段属于向前扩展，旧核心不能解释多代证明，不能用旧核心直接回退读取已产生多代记录的会话。

## 本机验收

- `npm test`：271项通过，其中新增21项C3-A测试。
- `npm run demo:composition`：三代来源链、同源去重、同文不同源、逻辑删除局部退出、会话隔离、其他插件区域保护、持久重启和恢复不复活通过。
- `git diff --check`：提交前检查本次改动；原有无关文档改动保持不变，不纳入提交。

专项覆盖：

| 分类 | 结果 |
|---|---|
| 三代组合 | 原始来源闭包不变，父包不在surface仍可验证历史证明 |
| 删除与修订 | A派生退出，独立B保留；无关来源变更不影响当前包 |
| 防复活 | 恢复来源不激活旧片段，局部退出后只能组合剩余有效片段 |
| 曝光依赖 | 看过A、B的后续回答仍继承并集，不因组合而变成仅依赖B |
| 严格去重 | 同源、同任务、同版本、同kind、同文才去重；同文不同源保留 |
| 边界保护 | 跨会话、跨所有者、当前任务、其他插件/原生节点和容量限制拒绝 |
| 证明损坏 | 漏依赖、自引用、跨会话、篡改限定条件、缺父引用拒绝；不回退父包 |
| 提交恢复 | 孤立准备数据不替代父包，已提交多代局部视图重启一致，flush失败阻止请求 |
| 幂等与预算 | 重复提交拒绝，超过16代不截断来源，自动阈值路径只在有收益时组合 |

两项旧回归更新了其前提：独立历史验证正文与原始来源不丢失，不再要求容器消息ID始终不变；旧格式保守围栏测试加显式其他插件屏障，独立验证不跨区组合及旧格式退出。

## 演示记录与边界

机器可读结果：[memory-phase-5c3a-results.json](memory-phase-5c3a-results.json)。7片组合为6片，同源重复去掉1片，不同来源的相同约束保留两份。删除A后留下2片，B的片段编号与正文不变。三次组合新增模型调用为0，重启与恢复检查通过。

演示中两父包展示共990字节，组合包756字节；只比较该摘要区域，不代表全会话token节省或运行内存下降。为了验证深度，演示直接调用内部组合提交接口生成三代；正常自动入口额外执行正收益检查，不会无收益反复组合。

测试使用真实DSH生命周期与JSONL恢复、脚本模型和SQLite虚构数据。准备中断通过持久化孤立记录模拟，不代表完成断电/磁盘故障实验。未进行真实模型语义融合验收或服务器资源验收。C3-B的限定条件抽取、语义融合、原文重建与独立保真校验未实施，详见[C3开发方案](memory-phase-5c3-plan.md)。

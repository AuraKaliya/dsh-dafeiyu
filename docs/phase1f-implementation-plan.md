## 实现细化

- 复用contracts的HostConfig v1，核心固定managed模式；插件配置单独严格校验，不能通过配置传任意模块路径或绕过生命周期。首版允许timeline、memory、channel-simulator、channel-qq及明确的模型适配。测试模型只允许test人格配置。
- 根配置的模型路由、数据路径、人格文件、并发／时间／上下文预算是唯一生效入口；插件不能另行覆盖agentId、dataDir或lifecycleMode。模型凭据只配置现有DSH凭据服务引用及文件位置，禁止明文密钥。
- 路径相对配置文件解析，校验真实身份与别名。核心、记忆、会话及渠道目录不得互相覆盖；查询索引独立。配置与人格文件不放入会被初始化的数据目录。
- 本机Host之间通过持久协调记录互斥，使用进程ID、随机nonce及资源真实身份；活进程或无法确认死亡的进程不能被接管。死进程记录只在事务内核验后回收；不删除用户数据或强行终止进程。该机制与核心／分析库既有占用检查共同工作。
- init仅操作明确的新空目录，复用各存储的初始化逻辑；不调用模型、不连接QQ，不写入人格或成长模板。部分初始化失败保留失败状态供核查，不自动删除或重建。
- start须满足schema、profile／agent、数据路径身份和初始化／已完成迁移条件。恢复只补录持久事实；准入开放前不开始模型、发送或分析任务。可选能力不可用有明确状态，必需依赖不可用不能报ready。
- 状态快照只含身份、时间、配置／底色哈希、版本、健康与计数；不包含任务正文、人格成长正文、原始错误、登录信息或凭据。status核对实例存活与快照时效，不把文件存在当在线。
- CLI在加载DSH之前将本进程DSH_HOME绑定到明确profile的隔离位置，各DSH存储仍显式指定路径；不跟随桌面模型默认配置。run是独占的一次性入口，不增加远程控制服务。
- 关闭先停收，再排空；超时向正在运行的模型／工具传播合作式取消，等待实际收尾后才关闭其依赖的存储。未知效果与未发送状态保留，不在关闭期间盲目重试。

SQL目标保持journal v2、memory v8、runtime v2。Host身份／诊断和本机协调记录独立版本化，不能作为私人记忆或Run事实的替代。迁移继续使用已验证的plan/apply/verify流程，初始化与迁移不合并进start。

每步报告区分程序检查、脚本模型、真实模型和真实平台；1F只做统一入口有限真实验收，完整162次人格／连续性协议仍属1G。

# 插件整合与首次安装方案

2026-10-27。依据本轮用户决定，继续本机开发；保留现有保留策略。完成后以独立、经过隐私检查的公开快照发布 GitHub。原仓库历史与未提交 `docs/memory-phase-1.md` 保留，不接触服务器，不使用子代理。

## 1. 责任与接口

记忆与成长拥有阶段人格、偏好、关系的候选、试行、采用、版本与撤下。现有 Memory 数据库已经是这些状态的唯一写入者；本轮明确 Growth 公共入口，Core 只装配快照、核验来源、记录实际使用并经接口提出改变。固定身份底色继续独立于可变状态，不引入第二份人格库，不改变保留期限。

QQ、B站各一个平台包，内部渠道接口负责入站、身份核验与交付，能力接口负责观察与动作。合并 B站公开能力和主人私信的源码、依赖和安装入口；保留稳定的历史扩展标识、来源标识、库名与已有数据库，避免重构导致来源失效或消息重放。QQ 提供明确的渠道和能力子入口。

Host 对用户呈现记忆与成长、QQ、B站的整合配置，旧配置经显式规范化仍可读取；冲突配置拒绝。共享媒体、活动、任务、来源记录继续复用。关系亲密度和昵称不构成主人或管理员认证。

## 2. 必要配置与隔离

去掉源码中真实QQ、B站账号/主人UID及绝对部署路径。主人QQ、机器人QQ、OneBot连接和令牌文件由安装者主动提供；模型路由、凭据位置由安装者配置。B站私信启用时必须指定独立账号UID、主人UID和登录态位置，保持唯一接收对象及实际登录身份核验。

每次新安装使用独立实例ID、数据目录和会话，昵称只作交流识别，不作为存储或权限主键。本地和服务器可以各自成长；不默认同步记忆、关系、凭据或消息。已有库的身份不能通过改配置静默替换。

## 3. 安装入口

按现有DSH插件使用 `package.json` 元数据、`dsh.bundle.patch`、中文README和配置说明。安装包包含运行代码及所有本项目内部依赖，不能要求用户手工链接私有工作区包。首次填写必要配置后预检、初始化空目录并启动；缺配置时清楚列出缺项，不冒用测试身份、不调用模型。后续启动复用已有数据；版本不兼容时明确提示迁移，不自动清空。

保留独立CLI供本机与服务器使用，并提供DSH插件生命周期接线；正常卸载/停用排空并关闭其子进程，不关闭DSH本身。默认不开放命令执行或公开平台发布；高级能力按配置启用，不新增运营资金授权系统。

## 4. 子步骤和检查

1. 记忆与成长统一入口：相关人格、连续性与隔离测试；保存记录并提交。
2. 平台包整合与账号参数化：QQ/B站渠道、能力、身份拒绝、消息恢复和Host配置相关测试；保存记录并提交。
3. 首次配置、插件生命周期与可分发包：在D盘全新目录从发布包安装，验证必要配置、空库初始化、重复启动、关闭和两个实例隔离。模型与平台使用明确的模拟接口；真实DSH/SQLite/进程分别记录。
4. 发布检查：本机全量回归；隐私扫描默认值、样例、生成包、公开文件清单及其Git历史。内部开发历史不推送；发布快照仅含审查后的源码、必要测试、公开说明、许可证和安装材料。完成GitHub上传后核对可见性、文件及安装说明。

## 5. 验收边界

必须证明下载的产物不依赖本机旧目录，不含真实主人身份，未配置不出网；实例之间数据与身份隔离。旧数据不重置，旧来源不失效，原保留策略不变。相关离线测试和发布全量回归不能冒充真实模型与真实QQ/B站验收。当前无本机正式账号配置时保留真实通信待验状态，不连接服务器补验，也不自动使用原7C测试资金。

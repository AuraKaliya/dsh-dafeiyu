# 第 1 轮状态视图 故障通知与发送接续契约

日期：2026-11-08。适用版本：0.28.9 / API 9。承接 0.28.8 的生成、核验恢复；runtime 显式迁移至 v6，活动 v4、媒体 v4、QQ v8 不变。

## 一个状态投影 三项独立事实

`TaskProgress` 从现有 Task、Run、操作、评价、交付及渠道账本生成，不保存第二套任务状态。对话状态工具、责任索引、生产者状态和管理中心使用同一投影。

| 维度 | 含义 | 不允许的推断 |
| --- | --- | --- |
| `goal` | 主 Agent 明确提供的 `goalStatus`；来源为 agent 或 none，缺少判断时为 uncertain。复核建议单列为 reviewStatus | Run completed、已有最终正文或已送达不自动变为目标全部达成；复核建议不代替主 Agent 判断 |
| `execution` | 当前 Run 的受理、排队、执行、等待、结束、失败、取消或中断及实际阶段 | 执行结束不等于用户要求全部满足 |
| `delivery` | 独立的生成、核验、待发送、已确认、部分、未知或阻塞状态；有渠道账本时附分段数量与回执 | 计划条数不等于实际送达；通知回执不等于结果回执 |

目标判断始终标明来源，`programVerified` 为 false；程序核对的操作事实在 `facts` 单列，不声称已经自动证明任意自然语言目标。主 Agent 可以在原有 `dafeiyu_task_outcome` 中给出 `goalStatus`，不需要新增评价调用。

`facts.plans` 保存实际配置回执中的计划 ID、版本和周期，说明仅证明该版本配置保存，不证明后台已经巡视。`facts.inspection` 区分工具目录、带实际操作回执的宿主调用、结果页、部分读取、失败尝试及可识别的非零命令退出；这些事实不能代替结论的语义核验。

`currentIntent` 区分当前目标代次；`currentRun` 和 `latestRunId` 区分同 Task 的最新接续与历史运行。旧运行保留原事实，但不再发当前故障通知或提供从旧检查点再次执行的管理按钮。管理中心恢复动作与投影的下一步一致，未知操作效果及未处理的阻塞条件不得通过重复恢复跳过。

进度 `version` 绑定有意义的状态和事实，不随纯展示时间或措辞变化。保留的旧 `state` 字段仍是执行状态，不能单独用于判断目标完成或送达。

## 不依赖模型的故障通知

任务执行失败和结果交付失败使用固定、有限的程序措辞，只描述实际阶段、记录保留、阻塞和下一步，不带未核验正文、主人原文、原始错误响应或凭据。前台对话失败也直接生成程序通知，不再调用另一个模型解释模型失败。

任务通知复用 FeedbackLedger 和 FeedbackDispatcher：

1. 绑定原入站、Task/Run、意图版本和进度版本后入账。
2. 同一状态重复观察复用原记录，包括已发送和未知状态；不换 ID 制造新通知。
3. 发送前重新核对原来源、当前目标和进度。任务已继续、目标已变或结果已交付时，未发的旧失败通知被取代。
4. 先持久认领，再调用渠道。渠道异常按未知保存，不改走备用发送；仅确定未发可在既有最多三次尝试内重试。
5. 重启把未结算的 sending 视为 unknown，随后只能按实际回执核对。已确认结果不能被迟到失败覆盖。

本版本新发现的进程中断写入 `task.status.notice-required`，激活时核对仍匹配的 Run/交付版本后通知。它不会扫描旧历史失败并批量补发。前台对话继续沿用原入站的持久通知事件，避免重启重发。

这些规则针对系统故障通知；用户明确请求的正常进度表达、任务报告和语义核验仍使用既有模型流程。本地通知测试验证的是零额外通知模型调用，不把脚本业务请求伪装成零 token。

## 确定未发与部分发送接续

恢复入口仍为 `resumeMessageTaskDelivery` / `resume-delivery`，请求只接受 requestId 和交付 expectedVersion；渠道分段证明由程序取得，不接受模型自行提交。

- 新增 `sending` 恢复阶段。正文、凭据、Task/Run/交付 ID 和目标保持；只把原交付推进到待发送，不重新生成或核验已批准正文，不重执已完成业务。
- `not-sent` 必须是已有确定未发事实；`partial` 必须取得匹配的渠道分段记录。存在 unknown、sending、损坏或缺失的必要账本时拒绝恢复。
- 渠道以原 reply ID 和固定计划接续，跳过已确认分段，仅发送 pending 部分。全局回执未知不因为“看起来还有 pending”而获得重发许可。
- 原授权、来源、当前任务、已批准正文和原有效期在恢复及各分段前仍检查。过期授权不自动续期。

文字和媒体各用自身的持久分段账本。媒体在明确未发或已知剩余分段时保留原冻结导出及原有效期内的文件租约；重启先核对媒体 manifest 和渠道记录，不重新取得文件、改变字节或重新合成内容。已发送、未知或不可恢复的终态继续结算；保留文件不等于授予发送权限。

## 存储与验证边界

恢复和中断通知使用已有不可变运行事件；状态通知绑定作为既有 Journal 反馈事件的附加字段。runtime v6 增加任务与运行事件查询索引，同时阻止旧程序把新增 sending 恢复记录当成兼容旧库读取。没有新增表或隐式迁移；显式迁移核对身份、完整性和占用，创建一致性备份后逐表校验行数与内容摘要，再升级结构版本。回退必须使用旧程序及匹配的迁移前备份，不直接改版本号或绕过身份检查。全新包仍须独立安装依赖并验证真实 CLI 初始化和启动。

本轮本地验证覆盖真实 SDK、持久存储、隔离渠道、实际本地源码、文字与合成文档附件、生成/核验中真实进程退出，以及取消、撤权、未知回执、修稿上限和陈旧通知。真实模型选择、真实平台链路及两小时观察均未执行，不据此宣称第 1 轮全部退出条件已满足。

# 生成与核验阶段交付恢复契约

日期：2026-11-07。实现版本：0.28.8，API 8；runtime 存储仍为 v5。范围对应修正版计划 R1.3、R1.4 中已复现的两条发送前缺口。

## 范围

本批恢复已经完成业务执行、但结果生成或核验中断的主人消息任务。Task、Run、交付 ID、目标会话、原材料、已保存的业务结果和已生成候选保持原有绑定。恢复不调用业务工具，不通过重建任务绕过失败。

本入口不恢复已确认发送、部分发送、发送结果未知、已经封存但明确发送失败的记录，也不扩大自主分享的自动恢复范围。交付锚点原有效期继续生效；过期授权的显式续期、重新形成材料及发送阶段续办留在后续工作项，不以延长旧凭据代替校验。

## 程序入口

- `resumeMessageTaskDelivery(runId, {requestId, expectedVersion})` 返回持久受理回执；`expectedVersion` 是交付版本，不是任务或 Run 版本。
- 管理中心 `tasks / resume-delivery` 使用 `{id, requestId, expectedVersion}`，其中 `id` 为 Run ID，管理请求的 `requestId` 为 UUID。页面使用交付版本提交，并分别展示业务结果与交付状态。
- 已结束任务的消息意图 `continue/retry`，以及任务控制 `resume`，在当前任务授权有效且交付可恢复时转到同一交付恢复入口。`status` 和普通重复交付请求仍只读取既有结果，不触发恢复。
- 同一 Run 和 requestId 的重复请求返回同一回执。相同 requestId 携带不同版本拒绝；另一个请求竞争同一待处理恢复时拒绝，不产生第二个执行。

回执包含 requestId、expectedVersion、runId、deliveryId、计划恢复的 phase 和 requestedAt。它只证明请求已保存，不表示核验成功或结果送达。实际状态通过交付状态与渠道回执查询。

## 持久化与状态转移

复用现有不可变 `runtime_outbox`，不另建任务状态库，不新增表或修改 `user_version`。以下事件均绑定原 Run：

| 事件 | 事实 |
| --- | --- |
| `native.delivery.recovery.requested` | 恢复请求及版本、目标阶段已保存 |
| `native.delivery.recovery.started` | 重新校验通过后，从哪个失败状态和版本接续；保留原错误 |
| `native.delivery.recovery.settled` | 此次恢复后的实际状态、版本与错误；失败不自动产生下一次请求 |
| `native.delivery.render-attempt` | 本次生成会话的唯一标识，避免再次打开已存在的失败生成会话 |

候选引用及核验拒绝反馈继续使用既有 `native.delivery.candidate` 和 `native.delivery.verification-rejected` 事件。正文在原 DSH 会话中持久保存，恢复时按引用和内容摘要读回。事件不是新的外部事实来源。

有尚未通过核验的候选时，恢复到 `verifying`，重用同一候选和材料；没有候选时恢复到 `rendering`，使用原材料生成。不会清空材料、锚点或失败历史，也不会退回新建任务流程。只有核验通过才封存正文、生成交付凭据并进入发送。

最多三稿的计数依据全部持久候选和拒绝反馈，不因 requestId、恢复或重启重置。第三稿遇到核验服务故障仍可继续核验该稿；第三稿已被明确拒绝时，不再生成第四稿。

## 授权与重启

受理时同步检查原任务、消息来源和当前意图；执行前、模型调用过程中及发送前继续核对完整来源、材料版本、目标人格和模型配置。受理后取消任务、撤回来源或失去群访问权，仍会阻止后续调用与交付。

停机时不结算尚未完成的已授权恢复为成功。重启重读未结算请求并重新检查条件。若已封存正文且确定没有开始发送，保留 `ready`，重启只尝试发送同一正文；若发送已开始，现有未知回执保护继续生效，不能借恢复请求重发。

旧 v5 数据结构保持可读，不做隐式迁移。旧记录缺少必要材料、来源已变或有效期已过时明确拒绝恢复，不能从缺失历史补造候选或授权。程序包和扩展统一使用 API 8；存储兼容不等于任意旧来源证明仍有效。

## 验收

两条原失败样本已改为成功恢复预期，并增加以下对照：管理入口幂等、主人 retry、同候选与证据复用、重启不重复送达、待处理恢复跨停机接续、取消和撤权后零新增模型调用、三稿上限跨恢复、旧版本冲突、竞争请求、过期与未知发送拒绝。

所有本批验收均使用真实 SDK 加脚本模型和隔离渠道。真实模型行为、真实 QQ 外发及两小时观察不由这些结果代替。

## 1 已确认的范围与执行边界

### 1.1 三个已确认取舍

| 编号 | 决定 | 开发约束 |
| --- | --- | --- |
| D1 | 交付阶段续办列为本版必做，并前移到第 1 轮 | 业务成果完成后，生成、核验或发送失败，须支持从受影响阶段继续；不能为了再交付而重做整段业务 |
| D2 | 先做确定性正文折叠和查询优化，再按样本评估语义整理 | 不立即全面开启语义压缩；保留百万上下文容量；整理必须保留来源、授权、纠正、待办和实际回执 |
| D3 | 本版维持既有主动活动范围 | 不扩大主动探索能力，不调整主动发言风格；修复现有活动的暂停、续办、交付和去重属于本版范围 |

### 1.2 后续实施边界

- 先在本地开发及隔离环境验证。服务器保持停止的约定不变；本地候选经用户检查后再进入服务器部署，本计划不表示已核查当前服务器状态或取得本轮部署授权。
- 后续真实 QQ 外发仅到主人私聊；群聊和入站采用隔离回放。报告不得写成已通过真实 QQ 双向或真实群全流程。
- 不采用子代理改造；不以多代理架构替代现有主 Agent 任务流程。
- `contextCapacity.maxTokens` 保持 1,000,000；不增加业务任务总 token、总步骤硬上限。模型实际窗口、既有外部请求超时、阶段时限、取消、权限及发送保护仍有效。
- 用户已授权本地开发及确定性验证；按本计划继续实施不再逐轮索取开发许可。付费局部复验、真实外发和两小时真实观察仍须处于届时用户授权范围；当前不启动这些操作，已有明确授权不重复索取。
- 保留身份检查、来源约束、按范围暂停、分段账本和显式迁移。不得清库、修改库版本号或忽略身份检查来通过验收。
- 账号、凭据、原始聊天和真实运行材料留在本机私有位置。仓库只保存脱敏场景、判据、合成夹具及必要的结果摘要。

### 1.3 不纳入本版的工作

不新增平台能力，不调整人格或主动性风格，不重写所有模块，不建设判断任意自然语言目标的通用规则系统，不为整理代码开展无关重构。语义整理只有在固定样本证明必要且有效时才进入候选；其全面启用不是发布必需条件。测试账户硬预算和具体费用预警值没有在本计划中预先设定。

0.28.13 的分批预算、预警和停止条件已在上述真实验收方案中细化为待批准建议；它约束验收支出，不改变百万容量和业务任务的总量约定。

## 4 实现原则与模块职责

### 4.1 从真实记录生成一致状态

保留现有状态所有者：Memory 保存任务目标、意图和工作记录，Core 保存运行、操作及交付，Activity 保存计划与调度，渠道保存实际发送，B站和媒体保存各自读取及覆盖。新增公共视图汇合这些事实，不另建一套可独立修改的业务状态。

| 对外维度 | 含义 | 权威来源与约束 |
| --- | --- | --- |
| 目标满足程度 | 已满足、部分满足、未满足或尚不能判断 | 目标及当前意图、程序证据、标明性质的模型判断；不能从 Run completed 直接推导 |
| 执行阶段与阻塞 | 正在执行、等待条件、被取消、执行结束等 | 当前 Run、检查点、依赖范围及调度事实 |
| 交付状态 | 待生成、待核验、待发送、部分确认、全部确认或回执未知等 | 交付记录和渠道分段账本；生成正文不代表送达 |
| 下一步 | 继续哪一阶段、等待什么条件、允许哪些操作 | 当前授权、版本、可恢复条件和副作用状态；模型摘要不能改写 |

这些是对外语义，不要求逐字新增枚举。R1.2 明确旧字段映射和缺失事实；只有不能从现有记录推导的持久事实才增加字段和迁移。

已知业务条件由程序核对，例如原计划 ID、版本、读取覆盖、命令退出状态和分段回执。开放性的结论质量由模型判断。保留可选任务评价的价值，不要求每个任务为证明结束而额外调用一次评价模型。

### 4.2 交付续办与不可变结果

交付续办使用显式恢复操作及幂等请求标识，绑定 Task、原成果、意图版本、目标会话和交付版本。每次尝试记录阶段、原因、候选引用、证据版本和回执。失败历史保留，不把终止记录直接清回初始状态。

| 故障位置 | 接续行为 | 必须验证 |
| --- | --- | --- |
| 生成前或生成中 | 从仍有效的原材料继续生成 | 已完成业务操作不重演，取消和新意图立即生效 |
| 核验服务暂不可用 | 保存候选和证据引用，继续核验同一候选 | 服务错误与不忠实结论分开；不把失败当核验通过 |
| 核验发现事实错误 | 用原材料与历次问题修稿 | 既有最多三稿约束跨恢复保留，不能通过重启或换 requestId 重置 |
| 明确未发 | 重新核对权限、来源、正文和目标后继续 | 封存正文不可改；过期有效性必须显式重新核验和记录，不能原地延长旧凭证 |
| 部分确认且其余确定未发 | 在渠道账本支持时接续剩余分段 | 分段身份稳定；已确认部分不重发；文本和媒体路径分别验收 |
| 发送结果未知 | 查询可用平台事实或保持待核实 | 未知不变成未发，也不直接自动重试 |
| 来源撤回、任务取消、目标已变 | 阻止旧结果发送，进入当前意图处理 | 恢复不能复活旧授权或重新绑定旧交付到其他会话 |

业务已完成但交付未完成时，“继续/重试”应能明确路由到交付恢复。状态询问仍只读；存在多任务歧义时不猜测目标。管理界面显示允许的阶段操作及不可操作原因，不能通过改库强行恢复。

模型不可用时，程序可生成“成果已保存，核验暂不可用，尚未发送”等状态通知。通知不含未核验正文、凭据或原始错误响应，仍检查目标权限并使用持久回执去重；通知自身未知时也不得反复发送。

### 4.3 上下文与已读材料

先缩小查询范围，再折叠已读正文，最后评估语义整理。折叠需要同时满足：正文已可靠归档、已有实际读取证据、当前步骤不需保留全文、来源有效、回查入口可用。保留操作状态、覆盖、来源 ID 和必要回执。

工作记录必须保留当前目标、主人最新纠正、限制、下一步、未完成事项、缺口及未知副作用。事实、推断、意见和待证结论分开。摘要不能升级事实等级、覆盖取消、恢复权限或把部分读取写成完整读取。

折叠触发独立于接近模型容量的压力判断，不新增第二个模型窗口或任务总量上限。触发策略按重复正文、阶段需要和预期收益评估；不机械保留最近固定条数后截断全部历史。回查不重执原工具，跨任务、权限撤销和来源过期仍检查。

按阶段提供工具复用现有 ToolStage、readiness 和目录机制；保留合法后续入口及不可用原因。DSH 的读取、查询、执行和安装权限分别处理；合并查询限于合法独立的只读操作，不能顺带扩大执行范围。

## 5 每轮工作项与退出条件

总顺序：第 0 轮最小验收入口和基线 → 第 1 轮任务到交付 → 第 2 轮上下文与成本 → 第 3 轮组合恢复和语义校准 → 第 4 轮冻结候选与发布验收。每轮随工作项补场景，不能把所有核验和界面问题拖到最后一轮。

所有工作项的初始状态为“未开始”，实际进度以开发记录和对应证据为准。既有测试是复用入口，不表示已覆盖新增验收条件；已复现的缺陷也不等于已修复。

## 6 验证层次与每项执行纪律

### 6.1 四层证据

| 层次 | 方式 | 可证明范围 |
| --- | --- | --- |
| V0 确定性回归 | 数据、状态转移、来源、回执、迁移、验收器正反例 | 固定条件下的程序行为 |
| V1 SDK 与隔离业务 | 真实 SDK、脚本模型、隔离渠道和故障注入 | 跨模块承接、执行、恢复及交付；不能替代自然语言语义或真实平台 |
| V2 局部真实复验 | 固定目标、原材料或证据包、少量真实模型及必要平台调用 | 一个明确的模型决策、核验或平台路径不确定点 |
| V3 冻结候选观察 | 独立发布包、固定配置、完整故事和同进程两小时 | 本轮指定业务、恢复、连续性及请求归属 |

付费复验按批次记录目的、预估、实际用量和剩余不确定点。预警触发后停止没有新诊断价值的重复复测，说明消耗来源；不得将测试账户控制变成业务任务的隐含能力上限。

### 6.2 每个工作项的执行顺序

1. 保存最小复现：输入、触发顺序、实际版本、预期与实际结果，分类为业务代码、模型判断、外部调用或验收器问题。
2. 冻结局部判据及正确对照。状态变更覆盖相邻分支，语义变更覆盖漏检与误拒，不能只测试刚修的一条路径。
3. 修改必要实现和关联契约、调用方、界面、测试。共性抽取以实际重复和不一致为依据，不扩大无关范围。
4. 执行针对性回归。修改契约和候选整合运行 `npm test`；安装/启动变化再执行冒烟和独立发布包初始化。必要检查未通过不得完成工作项；已通过且内容未变的检查不无故反复跑。
5. 只有 V0/V1 无法证明的部分才执行已授权 V2。报告修订复用证据包；读取修复优先回放原响应。同一失败没有新信息时转回定位，不重复完整付费故事。
6. 保存对应需求、改动、证据、用量及剩余问题的小提交。新失败另建条目并说明是否阻断当前目标；不无声扩展范围。

首次计划保存仅执行文档检查；后续已授权开发按上述规则运行相关程序验证。

## 7 冻结候选的两小时安排

### 7.1 冻结与运行身份

每轮记录：发布包版本、源码修订和内容摘要、实际加载路径与依赖解析、驱动修订和摘要、配置摘要、模型设置、场景清单、判据版本、运行 ID、实例身份、进程身份及起止时间。配置摘要须排除秘密值；不能通过归档配置把凭据带入仓库。

原始业务全过程放在此次观察前段。冻结前只做必要局部复验，不为同一候选预先重复完整昂贵故事。冻结时必需路径应可用，不能带已知阻断问题开始计时。

### 7.2 观察安排

| 阶段 | 工作 | 必须留下的证据 |
| --- | --- | --- |
| 前段 | 分条回复、指定视频、群提及与主人查询、原计划修订、DSH 实际诊断 | Task/计划 ID、实际工具结果、读取覆盖、最终正文、分段回执；计划修改后立即读回 |
| 中段 | 在隔离环境注入一次模型或媒体故障及主人插话，恢复原任务或交付阶段 | 暂停范围、探测与实际业务恢复分开、原进度复用、取消/纠正生效、最终送达；细致故障组合由前置测试承担 |
| 后段 | 维持正常配置的活动，低频检查修订计划和恢复后业务 | 至少一次接近结束时的实际任务结果及送达；无新内容、前台忙、冷却和依赖暂停分别说明 |
| 结束 | 核对任务、分段、请求、异常和用量 | 必需场景逐项结论、未完成事项、全部请求归属、未知用量及原因 |

阶段时间用于安排验收负载，不给业务任务增加总时限。低频合成输入明确标为验收负载；不能强迫空队列调用模型，也不能用其费用推算自然待机费用。

### 7.3 通过与重测规则

- 同一进程连续不少于两小时，版本、模型设置和关键配置一致；使用当前进程就绪、心跳、占用及实际版本证据，单独的状态文件或“已加载”不够。
- 必需业务目标及交付均满足；隔离、授权和去重符合 R01—R10；故障恢复走到受影响业务阶段并交付；后段实际任务检查完成。
- 已发生请求全部对账，未知用量如实列出。未知请求身份、未解释额外调用、遗漏场景和旧回执不得通过。
- 可恢复的瞬时错误若最终按约定恢复，不机械判定整轮失败；持续模型不可用时只可认定保护与退避通过，业务恢复未完成，不能给总体业务通过。
- 必需场景失败立即保存证据并停止该失败轮，回到局部定位。缺少业务负载的两小时只证明有限运行连续性。
- 运行代码、模型设置或关键配置变化后，新候选重新计时。停止/重启恢复另行安排，重启前后不拼接时长。
- 判据或驱动修正记录新版本；已有原始证据足够时可以重新审计并标注，不能事后补造缺失执行证据。纯文档文字修正不自动使未改程序的证据失效。

## 8 记录格式与验收资产

每个工作项保存一份简短结果记录，至少包含：工作项 ID、需求 ID、变更修订、复现、涉及模块、所用测试和场景、通过/失败/未执行、程序及平台证据、用量、剩余问题和下一步。需求覆盖不以测试条数替代。

验收运行清单与业务记录关联，不把测试目标身份塞进正式业务任务。运行清单至少关联下列信息：

| 类别 | 必需记录 |
| --- | --- |
| 对象 | 程序/发布包、驱动、判据、配置与模型设置的版本或摘要 |
| 执行 | 运行和场景 ID、开始结束时间、实例和进程身份、Task/Run/计划/交付 ID、预期与实际结果 |
| 证据 | 工具结果与覆盖、来源版本、阶段事件、最终正文引用、渠道分段回执、必要人工语义审查 |
| 用量 | 请求 ID、环境与批次、任务/阶段、模型、非缓存输入、缓存读写、输出、未知原因、耗时 |
| 结论 | 独立判定、未执行与限制、失败分类、复验关联；重新审计注明原执行与新审计版本 |

保留原始证据与审计结果的关系，不能用待测模块的一个 success 字段替代所有判定。时间在报告中标明时区，机读时间可保持 UTC。

成本金额优先按可核对的计费记录归属；仅能按费率估算时标明费率来源、日期和估算性质。不具备准确单实例金额时报告请求用量及未知项，不用整个账号余额变化伪装精确账单。

## 9 发布 迁移与最终交付

后续版本按实际变更统一根目录、自有包和协议声明；API 变更同步提供方、调用方、管理界面和测试。数据库仅在结构确有变化时升版，并为支持的旧结构提供显式迁移。不能为计划命名预先制造版本变化。

发布顺序为：冻结源码及必要构建产物 → 生成新目录发布包 → 独立安装依赖和包检查 → 独立初始化 → 适用迁移及匹配回退演练 → 最终业务观察和审计 → 用户检查 → 另行授权的服务器部署。当前安装规范以 [install.md](../../packages/plugin/docs/install.md) 为准。

迁移备份须验证身份和一致性；包含原配置、数据、profile 与程序。旧程序与迁移后数据库不匹配时必须拒绝启动。回退同时恢复匹配程序和数据库，并先保留升级后新增记录副本。不得删除用户数据、手改 `user_version` 或借用工作区 `node_modules` 通过检查。JSON 保存使用 UTF-8 无 BOM 和原子替换。

最终交付固定包含：

1. 本版范围、新版本、修订、包摘要和实际加载证据。
2. R01—R10 及各工作项的通过、失败、未执行和证据入口。
3. 两小时业务、恢复、进程及后段任务证据；停止/重启验证单列。
4. 正式实例、确定性测试、真实局部复验、最终观察的用量与未知项，成本基线比较及限制。
5. 未完成事项、外部平台限制和仍待定位的问题，不用“全部通过”掩盖。
6. 当前安装、升级、回退说明及可验证备份；本地验收与服务器部署分别记录。

# 第 2 轮剩余本地性能与恢复工作

日期：2026-11-08。承接 0.28.10 的确定性折叠和查询优化。只分析历史本机证据和运行合成离线样本，不调用付费模型，不部署或操作正式实例。

## 历史定位和固定样本

历史最终两小时运行保留 CPU 采样、心跳和只读运行账本。按最大延迟增长所在窗口统计栈包含时间；父子栈时间重叠，不相加。总体 idle 比例不用于解释某个重任务的延迟。原始聊天、账号和平台内容不复制进测试。

历史诊断任务有 76 次模型请求、52 次 DSH 操作和 15 次归档续读，最终依赖列表 139 项。近似规模的合成回归固定为 64 次读取、每份 6,000 字符、67 次模型请求和一次结果交付，百万容量保持。变更前基线在 `tests/fixtures/acceptance/heavy-baseline.json`；比较双方都启用 CPU 采样，不能把不同采样开销混为加速收益。

## 修复约束

缓存只保存已校验的不可变内容，不缓存当前权限判断。文件缓存每次核对文件身份、大小和时间戳，变化、删除、链接或损坏仍拒绝。观察数据库的不可变行缓存区分身份与范围，外部提交使缓存失效；事务内新读行不能留到回滚之后。缓存限制条数和字节，不能靠无限增长换取性能。

文件内容缓存每类最多 128 条、8 MiB；观察行缓存最多 256 条、4 MiB。SDK 解码缓存使用弱引用，不延长 SDK 历史对象的寿命；它复用冻结事件的解析结果，当前来源校验仍独立执行。

SDK 冻结历史记录可以复用解码结果，但来源有效性、取消、过期、目标代次及发送前检查继续执行。在不跨越数据库事务的阶段边界让出事件循环，并在恢复后重新检查来源；连续缓冲流按处理时间让出，不引入任务总步骤或总 token 上限。

## 验收

- 完整重任务：同样读取、请求数、正文与确认送达，最长事件循环延迟低于 1,000 ms。
- 运行中取消：第 48 次读取后由真实计时器发起管理取消，受理低于 1,000 ms、任务结算低于 1,500 ms；已完成操作保留，不继续读取或外发结果。
- 连续缓冲流：取消计时器能获得执行机会，源迭代器被关闭，正常值与异常仍准确传递。
- 进程退出恢复：完成 64 次读取、批准正文后，在发送开始前杀死隔离子进程；新进程使用原数据恢复，同 Task/Run，无新模型请求、无业务重读，仅交付一次。
- 缓存保护：覆盖事务回滚、实时撤权、外部数据库损坏、文件变化/删除、跨范围和容量淘汰；保留原取消、撤权及未知发送回归。

`npm run test:performance` 串行执行性能样本并保存版本、源码/驱动摘要、阈值、日志、CPU 样本和审计。普通 `npm test` 仍运行功能及恢复断言；严格耗时阈值通过独立串行入口验证，避免并行回归竞争资源被误判为业务退化。指标是本机固定负载的回归门槛，不是任意机器或真实模型的服务承诺。

语义整理继续保持原配置；本批先解决可证明的重复读取、解析与事件循环让出问题。实际供应商缓存、净费用和两小时真实观察仍不执行，不把局部性能通过写成真实成本验收完成。

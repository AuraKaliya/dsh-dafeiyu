# 7C-2原生输入与语义重写接线修正设计

2026-10-26。真实校准累计4.957236元、483,671毫秒，停止期间没有新增真实调用。本设计在修正实现提交前单独保存，原失败不覆盖，总60元和原48小时窗口不变。

## 已确认缺口

原生ExecutionMemoryPort没有转发MemoryCompaction已有的rewrite，核心冻结端口及ExecutionEvidence适配也缺少该字段；semanticEnabled虽为true，原生任务仍无法进入语义重写。补为可选方法，旧提供者无需实现，不改数据schema。

普通摘要分组调用原先各被告知最多16片，但最终合并仍最多16片，形成接口额度不一致。核心应按剩余片段数和剩余组数分配每组上限；新增可选maxFragments参数，旧提供者可继续接受旧参数，核心继续校验输出。总片段上限、来源依赖、限定词和最小64 token收益不降低。

保护锚点超容量时，保留该组现有内容，分类记录并继续检查其他独立组；不删锚点来满足长度。生成／保真验证失败或无收益仍不提交。新增原生任务测试必须实际观察到语义生成、验证及当前可解析二代视图，不靠同源重复摘要模拟该接线。

## 原生本轮数据

当前真实历史驱动通过ContextContributor把材料加入动态系统上下文；DSH为支持系统更新会保留该内容，压缩后的问题可能仍得到未压缩原文。这样的对照不能单独证明历史摘要保留事实。

在TaskSubmitSchema和ExistingTaskRequestSchema增加可选data（JSON，总编码不超过16 KiB）。仅由既有受信producer接口提交，仍需原TaskRef、expectedVersion、policy和既有身份校验；data不能改goal、epoch、来源授权或动作权限，也不自动成为记忆。现有隐私脱敏拒绝规则覆盖整个请求，包括data。

执行器把data作为providedData.content加入原生notice的用户消息，连同producer及“资料不授予权限”的说明，纳入持久请求指纹和execution-input来源证明。省略data时不改变旧程序输入结构、旧请求指纹或已有记录。无需数据库迁移，旧插件／任务文件仍有效。

真实连续性驱动改用data提交record／hold／question及冻结资料，不再把这份历史通过系统上下文重复曝光。初始虚构状态、阶段人格及合法任务状态照原接口装配。保持同一Task与epoch、同一DSH会话；三个条件克隆同一真实历史基线。程序检查同时验证资料确实进入用户输入，当前系统上下文没有夹带过去整份材料。

## 检查与退出条件

只运行接口／原生执行／来源／摘要相关检查：data大小及隐私拒绝、Task目标不被data改变、重复requestId冲突、数据进入原生消息且可重开；原生重写转发、独立组保留、片段额度、来源撤回及证据伪造保护。保存失败与复测，提交后才继续付费校准。

补齐安全的摘要错误分类，不记录失败模型正文或思考。诊断支持明确选择单个校准项，首次摘要失败就停止。全套校准可复用同一候选已通过的诊断项，正式162项必须等待五项校准完整通过。

这是校准前的接线与辅助协议修正，不修改原162项的事实、问题、重复规模和人工标准；不把旧结果标为新候选通过。不连接服务器、不执行部署清理或QQ发送。

# DSH 管理中心 UI 接口核对

日期：2026-10-29。所有下载材料保存在本目录，作为只读设计参考，不加入大肥鱼构建。

## 已确认的扩展机制

### 设置入口

`packages/client/ui-settings/src/client/contract/slots.ts` 声明 `settings.section`：root 作用域的 list 插槽。一项贡献对应一个设置页面，注册项通过 `id`、`order`、`label` 提供导航标识、顺序和标题。页面挂在设置面板现有内容区，接收 `close()`；业务数据由自己的注入服务提供。

`packages/client/ui-settings-general/src/client/index.ts` 实际声明这些插槽，从 `ctx.slots.entries('settings.section')` 读取条目并排序；同文件展示了 `ctx.slots.inject('settings.section', () => ctx.slots.register(...))` 的正式注册用法，以及父贡献通过 `children` 声明带类型子插槽的模式。

结论：大肥鱼注册一个设置分区即可。能力模块不应各自再注册成 DSH 顶层设置分区。`settings.plugins.tab` 用于 DSH 自身的插件分区，不是本次单独管理中心的目标插槽。

### 客户端交付

`packages/client/modules/README.zh.md` 与官方 `cordis-plugin-development/references/ui-plugin.md` 确认：包在 `package.json` 中声明 `dsh.client`、`platform: web`，导出 `./client`；客户端 bundle 注册与包名一致的惰性 factory。`dsh.client.inject` 声明激活依赖；额外运行时 imports 需要遵循 external 的可解析性约定。React 来自 DSH 共享模块表，不额外装载一份 React 或 CDN 依赖。

大肥鱼现有 `packages/plugin/package.json` 尚无 `dsh.client` 和 `./client`。`packages/plugin/src/index.ts` 只有 Host 配置和子进程启动；管理中心的 Client 部分及管理服务需要后续正式开发，本轮没有加入这些实现。

### 生命周期和模块注册

官方 Slots 机制支持父级声明 children、模块通过该声明注入贡献，并在声明撤销或插件卸载时释放注册。适合“管理中心声明扩展位置、能力模块注册自己的 UI”。状态订阅、事件和操作任务必须有清理归属，不能把第二个应用根节点直接附加到 DSH 页面。

对照 alpha.2：`settings.section` 契约文件内容完全相同。正式开发仍应在目标宿主用 `cordis_inspect_query` 核验实际挂载的 slot、Services 和调用入口；这不要求制作跨版本兼容代码。

### 配置表单

`config-form-types.ts` 确认 `ConfigForm` 提供 `getSnapshot`、`subscribe`、`set`、`unset` 和带 `expectedRevision` 的 `mutate`。快照区分 loading / ready / unavailable，包含 writable 和 revision。拒绝写入或传输失败不能显示成已成功应用。

`ui-settings/README.zh.md` 说明 `ctx.configForms.whileServed(namespaces, register)` 随 Host 是否提供设置命名空间挂载/撤销页面。它适合依赖其他设置提供方的页面；大肥鱼的总管理入口不应因业务运行进程停止而消失。

alpha.2 对照的 `config-form-types.ts` 内容完全相同。能使用 ConfigForm 不意味着可以自动编辑现有大肥鱼 JSON 设置文件；需要明确唯一配置真源和管理服务，不能双写两份配置。

### UI 操作和权限

官方 `references/user-actions.md` 要求普通 UI 操作与 Agent 工具共用 Host 服务逻辑。授权或确认权限的操作保持 user-only。

对应大肥鱼：记忆查询与业务操作可复用模块服务，但主人更换、执行授权扩大等管理动作不能成为 Agent 自己授予权限的工具。Client 到 Host 的具体可调用入口需在目标宿主检查后确定，不能假设存在通用 HTTP 管理端点。

### 样式与控件

官方样式文档要求继承 `--dsw-alias-*` 语义 token、使用 CSS Modules、维护键盘焦点和减少动态效果，不另起全局主题。

需要区分内建包与外置插件：仓库内建 UI 可以导入自己的 primitives；官方外置插件指导明确警告，不要在普通 JS 插件中随意 require DSH 内部 Client UI 包。因而正式实现不能把内部组件路径当作稳定公开 API。应根据目标构建的可用导出选择控件，或在本插件内提供同主题、同交互语义的控件。原型的独立 CSS 仅用于离线设计预览，不是将来的 DSH 主题实现。

### 实际可用空间

rc.2 的 `SettingsRoot.module.css` 将设置面板宽度设为 800px，导航宽度为 188px；内容区域左右各有 24px 内边距。宽屏时大约有 **564px** 的内容宽度。大肥鱼不应再增加常驻侧栏或设计必须依赖宽屏才能使用的多列仪表盘。

alpha.2 保留 800px / 188px 的宽屏规格，但内部改用 grid，并为部分窄屏环境新增横向导航。这个 CSS 文件与 rc.2 不同，说明不能依赖设置外壳的私有 DOM 结构。

## 本轮设计判断

- 采用单一 DSH 分区，内部六个横向页签（含只读提示词预览）。能力卡片进入工作区内的模块详情；短表单用对话框。
- 管理中心、能力模块的 UI 与管理服务分层。主人界面独立于 Agent 运行状态。
- 饲养员等于唯一主人；人格只展示当前认识和管理记忆依据。
- 保持当前接口统一，模块同步修改。下载的上游指导作为机制参考，不改变本项目已经确定的记忆所有权与不保留兼容代码的要求。
- 本轮只新增源码参考、设计说明和离线交互原型。没有修改业务代码、依赖、DSH 配置，也没有安装或部署插件。

# M5B：大肥鱼阈值检查与主动增量压缩

本机实现版本：项目0.9.0；主插件、接口、记忆和时间线0.6.0。固定DSH 0.2.1-rc.2。仅使用虚构中文样本；没有连接服务器、真实QQ、B站或读取登录凭据。

本页记录M5B交付时的行为。0.10.0新增的来源级局部失效及旧版兼容规则见[M5C1](memory-phase-5c1.md)，不再将会话状态变化直接用于清空所有新格式历史。

## 实现职责

记忆插件通过可选的 `compactionProvider` 注册策略、来源状态与独立摘要调用。主插件只为自身创建的DSH会话执行选区、保护检查和提交；其他智能体不进入这条链路。同一主插件只接纳一个提供者；检测到宿主已有 `ctx.compaction` 时拒绝启用，避免与另一自动压缩器竞争。接入真实宿主前需要确认其加载配置，不能直接叠加两个写者。

复用的是DSH公开机制：`tokenMeter.measure`、工具配对校验、`compaction/start → summary → compact-checkpoint → end`、按当前surface位置替换、持久化和恢复。没有直接继承Basic后端，因为它的固定选区与提交策略不能表达本项目的区域保护和记忆校验；也没有另写聊天模型循环。

辅助摘要沿用主插件绑定的provider、model和reasoningEffort，通过DSH `llm.stream` 发起独立 `purpose: compaction` 请求。每次使用新请求标识，只发送所选旧文字与摘要规则，不继承人格、工具定义、当前工作区或其他插件区域。模型工具请求、无效JSON、失败及超长结果均不提交。摘要请求的推理块和原始响应不写入业务档案；DSH摘要事件记录的是校验后的派生摘要，不标记为完整原始流。

## 触发与保护

每个DSH模型步骤之前检查，因此大工具结果返回后、下一次模型调用前也会检查。启用时必须显式配置**扣除输出预留后的可用输入预算**，不能把模型总窗口直接填写为可用输入。

```json
{
  "context": {},
  "compaction": {
    "inputTokens": 24000,
    "thresholdRatio": 0.75,
    "targetRatio": 0.58,
    "minGrowthTokens": 1024,
    "minSavingsTokens": 512,
    "cooldownMs": 60000,
    "retainTurns": 2,
    "maxSourceBytes": 65536,
    "maxSummaryChars": 2000,
    "timeoutMs": 30000
  }
}
```

此片段是记忆插件配置示例，24000仅为演示值，没有写入真实运行配置。其余字段为默认值。阈值按DSH压力估算与会话UTF-8字节量/3中的较大值检查，补偿中文和JSON的启发式低估；这不是准确的模型分词器。M4最终请求字节上限仍独立执行。

压缩要求同时满足压力阈值、增长量、冷却、可回收内容和最小收益。每次检查最多提交一个连续片段，按目标压力选择大小，后续步骤继续处理增量。不为了达到58%目标而删除受保护内容。保留区过大时记录 `protected-or-insufficient`；摘要失败或无收益也受冷却约束。这些是压缩调度条件，不是工具调用次数上限。

保护内容包括：

- 人格、权限规则、工具定义、DSH原生及其他插件区域。
- 第一轮稳定前缀、当前输入和进行中的轮次，以及最近若干完整轮次。
- M4工作记忆标记的当前taskId对应轮次，以及工作区、检索证据区本身。应通过工作记忆显式登记持续任务；没有登记时依靠当前输入与近期保留区，不能声称已自动识别所有长期目标。
- 工具调用对、含未知非文字内容的轮次、既有摘要、未建立归属清单的历史节点。

M5B只对已结束、归属明确、仍有效的纯文字历史生成摘要。工具返回继续由M5A做结构化精简和回查，工具轮次尚不做第二次语义摘要。所有插件区域都作为位置边界；不能跨过区域把两侧历史拼成一个替换范围。

## 来源、版本与删除

每个受管轮次保存开始记录与完成清单。摘要保存原事件seq和文字SHA-256、agent/会话、taskId、提供者版本、策略指纹、模型路由、工作/证据版本及记忆/反馈状态变更计数。正常请求、提交、恢复及来源回查都校验状态；使用摘要时再次核对原文哈希与完整提交标记。

目前采用**会话级保守失效**：记忆修订、删除、恢复，反馈档案删除/恢复，工作区或证据选择版本改变，会让旧状态下的受管历史及摘要退出活动视图。新增独立记忆或新增反馈档案不会使旧历史失效。M4其他区域仍按自己的逐项规则校验，不随本轮压缩重写。这比逐条依赖图更保守，可能撤下同一会话中仍有用的旧摘要；精细依赖分片留给M5C。

删除优先于稳定前缀、保留尾部及压缩收益。旧来源不会重新送入摘要器；删除与恢复造成的状态计数单调变化，恢复不会自动重新激活旧摘要。助手转述随其受管轮次退出，避免通过转述再次压缩。显式原文/已删除资料回查的轮次及其助手转述只供当轮使用，下一轮退出；原始档案仍保留。此规则不是自然语言语义遗忘保证，也不追溯接管M5B启用前无法验证归属的旧历史。

普通摘要失败保留仍有效历史。生成途中删除/修订、选区被替换或提供者注销时，结果不能提交；无效历史即使重算失败也先退出。输出过程中来源变化会阻止旧回答交付，不重放任何操作。

## 归档、计量和恢复

原文仍在DSH追加日志中。归属清单使用DSH `appendPluginRecord / pluginRecordOf`，而非运行时能写入、恢复时却不认识的自定义必需事件。清单与检查点共用DSH日志，避免另一个SQLite摘要库与会话日志之间的双写事务。读取插件记录时重新验证结构；损坏记录不猜测恢复。

只有完整的检查点与成功end标记才能进入上下文。缺少end的检查点、未封口的受管轮次会被隔离；原档案不删除、不重放工具。正常压缩完成后先flush，才把成功元数据与来源链接发布到统一行为时间线：`context.compaction.checked`。崩溃后日志是提交依据，不凭审计日志补做压缩或发送。

M4载体退出、M5A反馈退出和M5B失效退出在tokenMeter可用时都先记录匹配的 `compaction/prune`，紧接实际替换，避免旧内容已退出却继续计入旧压力。流式响应中每个块检查来源状态；只有首次准入或日志改变时重新扫描并核验不可变历史，减少重复工作。

## 本机验收与剩余边界

执行 `npm test`，211项测试通过，其中新增19项测试覆盖阈值、冷却、无收益、当前任务、人格/其他区域、跨会话、删除/恢复、生成及输出竞态、大工具结果后的检查、无工具重放、正常重启、不完整检查点、未封口轮次与旧摘要回查。另运行 `npm run demo:compaction`，演示指标见 [memory-phase-5b-results.json](memory-phase-5b-results.json)。

这些测试使用真实DSH装配、会话和持久化机制，模型输出由脚本控制。它们验证生命周期与隔离，不代表真实模型摘要保真率、生产token收益或服务器资源验收；未进行强制断电测试。2GB应用预算下沿用现有FastEmbed/ONNX部署思路，本阶段不新增embedding模型或独立常驻分析进程。

后续仍需M5C的多代摘要合并、逐条来源依赖分片、摘要内容保真评估及真实模型验收。已提交摘要目前保持稳定，不再次压缩；本阶段不做错误经验自动整理，不把摘要写入长期记忆，也不物理迁移或删除DSH原始日志。

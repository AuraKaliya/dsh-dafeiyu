# 统一媒体5D-3b：主人语音任务与runtime v4

2026-10-25；基线`d71ecc7`。

QQ可显式开启`media.voiceDirectives`，兼容默认关闭；依赖媒体接收和任务能力。`qq_task_submit/control`仅增加`voiceExposureId`，不接收模型自填转写／身份／目标。核心先核验实际消息及调用授权，程序读取完整语音证据，确认原QQ账号、当前主人、当前消息自己的record和已曝光观察，再按原有指示规则提取目标。其它成员、旧消息、file／video、未处理完整或无Speech者不能取得主人任务权限。

实际非空主文字优先，语音不能覆盖文字；入站`mainText`不写入ASR内容。语音的原音频／PCM／转写hash、处理版本和来源证明进入不可变任务来源；修改任务和解决异议的控制来源也保留证据，取消操作保留控制审计。运行、续跑、结果读取和交付沿既有祖先链检查这些证明；撤回实际语音可阻止运行中结果完成或使已完成结果不可用。

语音绑定版本与原文字权限hash分开。关闭语音会使语音来源任务失效，不凭空撤销已有文字任务；重新装配渠道／完整本地重启都要重新核验证据和当前开关。证据的技术完整性不等于ASR正确率，真实语音质量仍延期。

runtime v4是本阶段新来源协议的显式兼容门槛。v3必须先备份／显式迁移，不自动重写旧Run、请求、人格、文字回执；本步迁移只推进协议版本。Host预检、迁移目标、运行状态及状态文件读取同步支持v4，旧v2／v3状态快照仍可读取为历史证据。5F再完成统一media装配。

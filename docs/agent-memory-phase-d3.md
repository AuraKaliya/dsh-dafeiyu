# D3：交付凭据与模拟渠道闭环

日期：2026-10-24。项目0.19.0；contracts/core/memory 0.15.0；journal与channel-simulator 0.4.0。memory.sqlite仍为schema v6；新增核心delivery.sqlite，独立schema v1。

本轮使用虚构资料、脚本模型、真实DSH人格会话和模拟渠道验证。没有连接服务器、运行真实QQ或调用真实生成模型。

## 交付流程

受信原生协调器取得D2已完成草稿 → 确认目标会话当前任务与入站问题 → 进入目标会话队列 → 大肥鱼人格整理 → 独立保真检查及来源/权限复查 → 持久化正文绑定凭据 → 持久化发送中状态 → 最后复查 → 调用模拟渠道 → 保存明确回执或不确定状态。

普通聊天和任务交付共用同一route队列；不同会话可以并行。没有为D3另建聊天历史或另写人格模型循环。人格整理使用原目标DSH sessionId、当前人格和有效目标会话上下文，D2草稿通过临时task-delivery:material区域传入，不直接转发执行器结果。

本轮用于已接收问题的任务完成回复。原问题必须已结束普通处理（delivered或failed）；accepted、processing、reply-ready、sending或uncertain的普通回复不会被D3抢占。整理是对原问题的明确后续处理，不会生成新的渠道入站记录，也不重放原工具操作。

## 原生接口与渠道开关

| 接口 | 行为 |
|---|---|
| controller.delivery.submit({requestId,jobId,target},signal?) | 用D2 job提交一次任务交付意图；返回该意图状态 |
| controller.delivery.status({deliveryId}) | 查询当前任务自己的交付状态与渠道回执，不返回未核验正文 |

输入不接受待发送text、账号覆盖、sourceStamp或伪造凭据。核心从D2提供者重新取得固定的job/packet、原入站问题、目标、草稿、允许证据、来源快照和有效期。

渠道必须由注册插件明确声明taskDelivery='simulated'。项目自带channel-simulator已接入，qq适配器没有这个声明，无法走D3发送。这个声明是受信适配器的运行约定，不是对恶意同进程插件的沙箱；真实平台适配及账号/群成员核验须后续另行实施。

宿主必须具备带sources的来源追踪/压缩提供者；未启用时拒绝任务交付，不把来源无法退出的回答塞入会话。本轮测试启用记忆插件的既有来源跟踪机制。

## 目标、迟到与任务绑定

交付绑定完整渠道、账号、会话类型和ID，沿原入站渠道插件发送，并核验仍是同一个活动插件实例。人格版本、模型路由、目标DSH sessionId、D2来源快照和任务选择版本也被固定。

目标场景必须显式选择当前任务。切换A→B→A会推进selectionVersion，旧交付仍被拒绝；同一任务的其它独立工作项变化不自动覆盖本意图。

本轮采用保守的迟到规则：同一会话出现任何更新的入站消息，旧问题的未发送任务结果就视为可能过时。其它会话的新消息不影响本会话。真实群聊将来需要更细的“请求仍有效”策略，不能把这次模拟验收理解为已经解决高频群消息的交付体验。

这些检查在提交、排队后、人格请求流式处理、最终验证、凭据保存及调用渠道之前重复执行。旧问题、错误目标、已切换任务、已撤销授权或失效来源不会取得新的发送尝试。

## 人格整理和实际输入

整理沿用目标人格会话，保留原会话内仍有效的交流上下文。临时区域只包含D2允许的原问题、草稿和证据，不包含内部任务目标、私有候选、拒绝的来源或其它场景完整历史。

本次整理不给模型注册操作工具，并在DSH传输边界拒绝工具调用，避免为“补充回答”重复执行先前操作。D3人格请求过滤推理块及不需要的提供者重放数据，只将最终文本交给DSH持久化。

最终人格正文再用独立、无工具的请求核对D2允许证据；保真不通过、不完整输出或工具调用均不发送。权限判定由程序执行，模型只辅助保真检查。脚本测试验证了这些分支，尚未完成真实模型回答质量评估。

临时材料参与原有区域预算；如果预算不足导致材料没真正进入模型请求，D3会拒绝整理/发送，不退回直接转发草稿。可通过既有context.regions配置调整task-delivery:material预算，不能绕过其它区域的预算规则。

人格整理的实际输入及派生回答沿DSH来源记录保存。材料在这次交付结束后退出活动区域，后续普通回合会撤下依赖它的临时回答视图；发送事实和原始档案仍保留，不声称已经撤回消息。其它插件与原生区域保持原有管理方式。将有效回答长期保留为可再利用记忆，仍应通过观察/贡献接口显式处理。

## 凭据与一次尝试

delivery.sqlite保存交付意图、不可变来源绑定、最终正文和凭据。凭据包含目标、原问题、job、任务、人格及模型绑定哈希、正文哈希、有效期和人格整理的DSH来源引用。

这是核心管理的持久凭据，不是可由模型复制转用的网络令牌；API不接受调用方自造正文或凭据。正文和绑定写入后不可覆盖，向适配器传入的Reply及目标对象也冻结，防止意外改写。

同一任务requestId参数变化会冲突；同一job换requestId也只返回原意图。同一个入站问题只能拥有一个任务交付意图，不能换job绕过去重。运行中的重复请求返回当前状态，不启动第二次人格整理。

| 状态 | 含义与恢复 |
|---|---|
| rendering | 正在人格整理；重启标记interrupted，不重跑 |
| ready | 正文和凭据已经保存；重启标记interrupted，不自动发送 |
| sending | 已持久记录即将/已经调用传输；重启标记uncertain |
| sent | 渠道明确确认且返回非空回执 |
| not-sent | 渠道明确表示未发送 |
| uncertain | 异常、超时、取消发生在调用后、回执缺失或确认写入失败 |
| rejected | 调用渠道前校验、整理或持久化失败，未发起传输 |
| interrupted | 重启发现未完成的准备状态，停止自动处理 |

本轮D3采用每意图一次传输尝试，not-sent也不会因重复submit自动重试；没有提供D3原凭据重发入口。需要再次交付时，应由明确的新请求形成新意图，不能通过更换requestId偷偷重发。原普通聊天的retryDelivery接口行为保持不变，不能用它重放D3意图。

渠道已经被调用后，核心不能撤回外部副作用。此时发生取消或丢失确认，结果按uncertain保存；后来到达的确认不自动提升状态、不触发重发。若撤销发生在传输开始之后，不能保证已交给渠道的数据没有送达。本轮保证的是调用前校验与不盲目重试，不宣称跨进程“恰好一次”发送。

## 持久化与审计

状态更新和本地审计outbox同事务；outbox以稳定事件ID补入统一Journal。发送意图先落盘，之后才调用渠道；结果确认写入失败时保留uncertain，不能把持久化错误当成“肯定未发送”。

准备阶段的正文、凭据与状态原子提交，日志保留task.delivery.*、任务/job/意图身份及人格会话来源。状态查询只返回元数据和回执，不导出原私有证明或模型推理。

ledger依赖现有核心Journal的单活动宿主约束，不提供分布式租约。未知schema/数据库身份会拒绝启动，不重新初始化覆盖数据；初始化失败会释放已取得的Journal所有权。重启从ledger恢复状态，不重新调模型、工具或渠道。

现有memory.sqlite、人格和记忆边界不修改，旧记录不取得新发送权限；新增delivery.sqlite属于运行数据，被Git排除。真实部署前需纳入一致性备份和恢复流程，本轮没有部署动作。

# 第一阶段1B：接口契约与受控生命周期

日期：2026-10-24。接续1A提交`5c2c0e3`，工作分支`phase-1-core-host`。本步是开发中的增量，不是整个第一阶段或生产Host发布。

## 实现范围

- 保留`API_VERSION=2`与旧registerExtension；新增v3契约及`@dafeiyu/contracts/v3`，执行来源、task范围、结果、Host配置和生命周期均有严格类型／边界校验。
- v2/v3共享扩展、操作和渠道账号名称约束；v3注册保存脱离调用者后续修改的元数据，严格输入Schema、重复特性、依赖缺失和循环会被检查。
- 新`lifecycleMode=managed`把恢复、激活和停收分开。核心注册插件时不会提前处理accepted／reply-ready，也不会在未就绪时写入新接收回执。
- Memory的Task／表达／分析队列恢复推迟至recover；分析工作者须memory激活且core可受理后才能启动。已有legacy构造和脚本默认行为保留。
- D3交付账本恢复可推迟；任务交付提交受同一准入检查。没有新增真实渠道或主动发送。
- QQ只增加managed启动、停收和排空接口。未显式start前不连接；core未就绪时start被拒绝。没有改变账号、群范围、触发和收发业务。
- 提供者中途不可用会显示degraded并拒绝新受理，不被误报成存储损坏。停收时已有运行可以完成，尚未开始的工作保留恢复事实。

Host配置Schema固定阶段1字段与默认值，允许独立配置探针角色，拒绝未知根字段和重复插件／政策。资源并发和队列参数不构成每轮调用次数上限。

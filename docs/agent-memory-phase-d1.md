# D1：核心授权与任务内部跨场景检索

日期：2026-10-24。项目0.17.0，contracts/core/memory 0.13.0，memory.sqlite schema v5。

## 原生接口

| 入口 | 行为 |
|---|---|
| core.setTaskMemoryPolicy(input) | 受信原生协调器创建/替换稳定规则，expectedVersion从0开始 |
| controller.memory.grant(input) | 在规则范围内签发任务授权，返回内部读取能力 |
| controller.memory.resume(grantId) | 重启后检查持久授权，重建当前提供者绑定的读取能力 |
| controller.memory.revoke(input) | 用expectedVersion撤销授权；不可重新启用同一授权 |
| access.recall({query,strategy,limit},signal?) | 获准场景内召回，返回内部命中与来源信息 |
| access.open({hitId,offset,limit}) | 回查命中的原记忆记录，分页最多4000码点 |
| access.select({requestId,expectedVersion,hitIds}) | 将所选命中的可见预览片段关联到任务工作区 |

规则与授权sources使用完整conversation身份（渠道、账号、类型、ID），可附memoryIds白名单。最多8个场景，每场景白名单最多128个ID，重复场景/ID拒绝。授权必须指向规则的明确版本、同一active任务和当前任务epoch，期限大于当前时间且不超过24小时。原因经既有规则脱敏后保存。

规则默认不存在；没有规则就不能签发授权。授予场景集合必须是规则子集；规则有记录白名单时，授权必须指定更小或相同集合。记录的internalUse=none、原始来源失效和逻辑删除仍是硬限制，不会被任务授权覆盖。

这些入口只在受信原生核心/TaskController上提供。普通ExtensionHandle.tasks不提供检索函数，聊天工具也不接受route、grantId、purpose或executor来切换权限。本阶段固定执行主体为$task-coordinator；没有向真实能力插件或模型发放通用全局检索入口。

读取对象绑定当前核心任务引用及提供者。提供者卸载或核心关闭后旧对象不可使用；重启通过resume重新绑定。对象本身是受信原生能力，不能交给普通聊天工具直接返回正文。同进程恶意插件若本就持有核心/数据库权限，不属于这种接口能隔离的威胁边界。

## 检索、缓存与选择

复用MemoryRetrieval原有FTS5、中文分词、BGE、token分片、profile校验及降级逻辑，新增受信的内部读取路径。普通recall继续以原会话表达权限过滤。

内部路径使用原场景读取记录，先校验授权白名单、内部范围和完整来源，再分词、构建索引、计算BM25与向量。internalUse=none或未授权场景正文不会进入嵌入请求。每个场景仍受既有maxDocuments/maxChunks限制；各场景顺序处理以控制资源，未实现无限并行向量推理。

各场景独立召回后按场景内名次交错合并，避免直接比较不同语料的BM25数值；相同记忆去重，最多返回20项。第一版相同名次按授权场景顺序打破平局，不使用额外重排模型，不宣称这是最终相关性策略。

索引和向量分区包含agent、任务/epoch、grant及版本、policy及版本、真实来源route和完整profile；query/document角色与正文哈希仍分开。内部缓存不会污染普通会话索引，不同任务、不同授权不会借用命中凭据。重复有效查询可以复用同一授权下的向量。

缓存只加速计算。读取命中、回查、选择和后续任务读取都执行持久授权、原权限、当前来源及版本校验。命中返回原boundary/effectiveAccess用于来源说明，同时标记usage=internal-only；这些原场景权限不代表获得了新目标的表达许可。

短期hit保存来源证明、片段位置、profile及期限，不复制正文。期限为10分钟与授权期限的较早者，每授权最多保留128个最新hit；后续检索清理过期hit。过期或被淘汰hit需要重新检索。已经选择的证明独立保存在不可变task_links中，不依赖hit继续存在。

预览最多600码点；select只装配本次可见预览范围，完整原记忆须显式open。open返回的是命中记忆记录的正文，并不冒充外部网站、QQ消息或未保留来源的原文下载；底层真实来源仍通过既有引用追踪。

检索不会自动修改任务槽，不调用独立分析模型，不创建新的长期记忆，也不把未选命中注入DSH会话。

## 来源与撤销传播

任务选中证明包含原场景、记忆ID、修订、状态版本、内容哈希、完整祖先、时间线屏障、片段范围，以及授权的task/epoch、grant/version、policy/version。

证明有效性由任务工作区动态检查。撤销授权或替换规则后，已选内容立即退出任务内部读取；依赖这些输入的工作结果、观察贡献和新来源档案沿阶段C的不可变输入链失效。正在运行的旧工作只能进入late归档，不能写入当前结果槽。

所有D1选择都被标记为内部授权证据，即使原材料恰好允许在原会话表达，也不自动通过任务区域注入聊天。D2将另行决定针对目标的表达材料。

检索在每个异步边界及最终提交前检查授权、任务epoch、取消信号和所有查询场景的generation。前一个场景在后一个场景嵌入期间发生修改，也会拒绝组合快照。返回命中前再校验逐项来源证明；不把旧缓存当成有效证据。

撤销或源删除不能撤回先前已交给原生调用者的内存副本。消费方必须通过本接口重新回查/选择，或沿任务来源证明使用结果；本轮没有让模型持有跨场景正文，也未实现完整操作系统信息流隔离。

重新授权会生成新grant；恢复来源会推进状态版本。旧授权链接、旧hit和旧派生结果均不自动复活。需要重新检索、显式选择、开始新工作。一个任务撤销不影响另一任务的独立授权。

## 持久化、日志和兼容

schema v5新增稳定规则及不可变规则版本、不可变授权绑定/可撤销状态、幂等请求和短期hit表。v4升级不改写原记忆、范围、任务选择或删除状态，也不生成默认规则和授权。v1起的兼容迁移继续验证。旧程序不支持v5，未来部署需配套代码与一致性备份。

规则、授权、撤销、hit及对应审计outbox按SQLite事务提交；选择与原task_links/task_revisions同事务。请求ID参数变化会冲突。失败回滚不会留下半个授权或半批命中；审计沿用稳定事件ID补投。

审计仅进入内部任务/规则路由，保留规则、授权和任务身份、版本、查询哈希、命中数量及profile。查询正文和整批命中正文不写统一日志；选择后保留实际依赖。规则配置和检索本身不产生QQ发送。

重启保留有效授权、撤销状态、所选证据和未过期hit，不重跑检索/工具。原生读取对象必须重新取得。任务目标变化或暂停/恢复推进epoch，使此前授权失效。

派生向量使用既有全局LRU容量；单场景召回受原有文档/分片上限约束。旧授权的派生索引分区仍可留在本地磁盘，但无法获得读取权限；本轮未增加后台磁盘回收调度。正式部署前应结合实际任务量安排派生缓存清理，不把缓存持有当作永久授权。

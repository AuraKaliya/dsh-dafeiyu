# 智能体级记忆阶段B：插件观察与选择性贡献

日期：2026-10-24。项目0.15.0，contracts/core/memory 0.11.0。只在本机使用虚构插件、虚构来源和脚本模型验收，未连接服务器或修改真实QQ接入。

## 职责和接入点

能力插件决定观察哪些内容、怎样筛选、是否使用模型以及保留什么。主插件绑定实际扩展身份、渠道/会话和当前有效操作；记忆插件验证输入、持久化来源与贡献、执行范围和删除规则。记忆模块不替插件判断“感兴趣”，也不默认保存所有收到的消息。

ExtensionHandle新增三个插件级方法：

| 方法 | 用途 |
|---|---|
| observeMemory(report, context?) | 提交一份已结束的观察活动及选中贡献 |
| openObservationSource(input, context?) | 在原范围内分页回查该生产插件的来源档案 |
| changeObservationSource(input, context?) | 对来源进行带expectedVersion的逻辑删除/恢复 |

这三个接口不是自动暴露给模型的全局工具。已有observe仍负责连接/过滤等传输事实，保持原语义。记忆插件注册唯一memoryObservationProvider，核心固定绑定方法和身份；卸载生产插件或记忆提供者后，旧句柄立即失效。

拥有已注册渠道/账号的插件可以在后台提交本渠道观察，不必创建DSH聊天。没有渠道的能力插件必须传入属于自己正在执行的ActionContext；不能借用其它插件上下文、已结束上下文或模型伪造对象。实际QQ适配留待后续明确接入，本轮使用虚构渠道插件和虚构探索工具验证。

## 活动报告与四种结果

report包含requestId、conversation、startedAt、observedAt、finishedAt、outcome、selection、counts、sources、exposedSources和contributions。主体、生产插件版本、任务及操作父关系由核心绑定，输入不能覆盖。

selection记录插件自己的policyId、policyVersion和reasonCode。counts分别表示接收、程序处理和模型曝光数量，满足modelExposed≤processed≤received；这些是producerReported信息，不冒充宿主已经证明模型读过。时间检查startedAt≤observedAt≤finishedAt，但允许迟到记录。数据库顺序和日志顺序保持单调，不能把到达顺序当作事件发生顺序。

| 结果 | 编码和校验 |
|---|---|
| 原文 | form=original，source指向留存全文，正文从档案取出 |
| 片段 | form=fragment，提交source、start/end及text；按脱敏后原文的Unicode码点精确核对 |
| 摘要 | form=summary，正文由插件提供，保存全部声明的实际输入依赖 |
| 无贡献 | contributions=[]；可以sources=[]，只留下活动元数据，不产生记忆 |

failed活动禁止附带成功贡献。普通完成活动也可因“不感兴趣”没有贡献。是否保留无贡献活动的来源档案由sources决定，完全忽略内容时不提交sources；系统不会从计数中补造原文。

exposedSources表示这一活动共同暴露给结果生成过程的来源。每条贡献的exposure必须包含它们，不能仅填选中的支持引用而删掉已声明实际输入。各源也可以表示一个具有稳定身份和摘要哈希的批次，以保守覆盖较大的观察范围。

无贡献活动即使报告模型看过很多消息，也可只留下计数而不留存来源清单；没有派生内容时，不强制保存被忽略的材料。它的计数仍只是插件报告，不能据此提供未留存原文的回查。

接收这份报告不会启动模型回合、调用分析模型、发消息或把内容自动注入聊天。长期记忆保存为experience：原文/片段为reported_claim，摘要为inference，均为not_analyzed。存储通过不代表来源陈述或插件摘要已经事实核验。

## 来源留存与回查

每个来源具有稳定key、原始发生时间和archive：

- text：留存经既有脱敏规则处理的全文，哈希由程序计算。
- digest：只保留插件提供的内容摘要哈希，不传入或存储全文。摘要贡献可以引用它，原文或片段贡献不能引用它冒充原文。

来源注册为dafeiyu:observation-source:<UUID>，状态version初始为1。身份以agent＋route＋key定位，不依赖活动requestId或当前插件版本。相同文字、不同来源key保持独立；已存在key的正文、哈希、发生时间或初始范围不允许静默替换。插件升级可以重用同一未改动来源，保留首次生产版本和原任务归属。

来源声明可填写expectedVersion，省略时固定为1，不表示“自动采用最新版本”。来源在观察期间被删除或恢复后，旧报告提交会因版本冲突被拒绝；插件重新读取后才能显式提交新版本。原requestId的幂等重试仍只返回旧回执，不生成新内容。

本轮来源正文是不可变档案，version记录删除/恢复状态。没有来源原文编辑接口；上游新版本的接入必须保留可追溯版本身份，不能复用旧key覆盖正文，也不能用新key伪装被删除的同一来源。协议依赖可信适配器如实提供身份和曝光信息，不声称能验证恶意同进程插件的所有行为。

当前身份域是agent＋route＋key；它与既有QQ消息ID、网页版本等实际资源的映射，需要在真实能力适配时明确并测试。本轮不按相同文字猜测来源相同，也没有把既有聊天记录复制到新来源域。

全文回查最多4000码点一页，返回ref、状态版本、哈希、偏移和下一页位置。仅哈希来源返回digest_only和rawAvailable=false，不生成虚构全文。已删除回查须显式mode=deleted，标记deleted_lookup_only，并继续检查表达范围。

回查接口属于生产插件句柄；通用聊天工具不会自动获得这个新入口。其它能力可通过正常记忆引用使用已贡献条目；其源引用与留存能力可在MemoryView.observation中追踪。后续统一授权与跨插件原文访问另行扩展。回执不含正文，供插件管理；插件不应把内部回执整份当作对外回复。

## 五轴范围和因果关系

阶段A的所有权、来源场景、任务、内部使用与表达范围继续适用。来源及贡献都只能声明原会话或none，贡献继承所有实际来源限制，不能放宽。内部可读并不代表可以对外表达；留存本身也不授予内部使用权。生产插件仍能管理、逻辑删除自己不可读的档案，管理动作不返回正文。

生产插件身份与消息入口分开：例如由QQ请求触发的探索工具，生产者是探索插件，ingressPluginId仍指向消息入口。活动记录继承原调用trace，并以operation.started作为因果父事件；各memory.created再指向observation.recorded。后台渠道观察拥有独立活动身份，不伪造模型回合或任务。

有可信已注册工作状态时记录会话任务，否则保持未分配；尚未建立跨会话任务工作区或全局读取授权。任务名与插件名都不能成为跨会话旁路。

## 时序、事务与恢复

数据库升级至memory.sqlite schema v3，保留v1→v2范围迁移，并新增：

- observation_sources：不可变来源正文/哈希/初始范围，独立的逻辑删除状态版本。
- observation_activities：已结束报告、单调sequence、首次回执与幂等指纹。
- observation_contributions：活动、贡献形式、生产者、片段范围、实际曝光来源和记忆ID的映射。
- observation_source_requests：删除/恢复幂等回执。

来源、活动、所选记忆、映射、回执和outbox处于同一个SQLite事务；内部记忆写入使用嵌套savepoint。任一贡献无效或持久写入失败，整批回滚，不留下半个活动或部分记忆。

outbox向已有统一日志按稳定事件ID补投。日志先写成功、确认前中断也不会重复活动。auditPending表示持久提交成功但日志仍待补投，不能把回执解释为当前来源仍有效。再次提交相同requestId和参数返回原回执，参数变化则冲突，不重建记忆或重跑工具。

报告保存原始发生/观察/完成时间和实际入库时间；日志另有recordedAt和全局seq，activityRecordedAt区分原始入库与延迟补投。长时间运行活动的实时start/progress协议未在本轮实现；这里只接收完成或失败报告，已有核心工具开始/结束日志继续承担操作生命周期。

## 删除防复活

来源删除推进状态版本，依赖它的贡献、后代记忆、检索结果和已暴露聊天历史通过现有源校验退出。恢复再次推进版本，旧贡献保存的版本不会自动变成最新，因此不会恢复旧快照。原文仍保留，可按范围显式查询。

删除一条已贡献记忆后，原requestId重试只返回无正文的旧回执；换活动或贡献ID从同一被抑制来源重新提取会被拒绝。独立来源即使文字相同也不受影响。来源管理使用CAS和持久幂等回执，不能用插件重启或升级清除墓碑。

源状态变化计入memory generation及校验epoch：既有检索缓存、工作选择和摘要会复查，不因记忆正文哈希未变而继续使用过期来源。模型生成中删除来源会阻止回复交付。已经暴露的历史事实不会被宣称“从未发生”。

## 本机验收

`npm test`共332项通过，本轮新增22项虚构插件测试；`npm run demo:observations`展示原文、Unicode片段、仅哈希来源摘要、无贡献活动、插件自选策略、两种范围、删除、重启与恢复。报告见[agent-memory-phase-b-results.json](agent-memory-phase-b-results.json)。

覆盖共享曝光遗漏拒绝、身份/范围/时间/片段伪造、事件因果链、内部仅用、独立同文来源、源身份冲突、跨会话回查、失效上下文、插件卸载、脱敏、事务回滚、补投去重、迟到记录、升级保留来源、删除与恢复，以及生成中撤销。

示例中能力插件自行忽略一条消息，其正文没有传入记忆系统；另外提交3条贡献。无贡献活动没有生成记忆；仅哈希批次没有留存全文。活动接口产生的模型调用和消息交付均为0。没有运行真实QQ、真实模型或服务器容量测试。

旧记忆和范围旁表不改写，既有阶段A迁移/恢复测试继续通过。旧程序不支持schema v3，不能仅回退包版本强行打开数据库。本轮没有迁移真实私人记忆；未来部署需核对程序与备份。

下一步仍是阶段C跨场景任务工作区，再推进阶段D授权检索与对外交付。实际QQ观察策略、其它真实能力适配、自动分析触发和持续学习调度不在本轮自动启用。

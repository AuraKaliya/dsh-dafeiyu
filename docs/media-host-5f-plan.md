# 统一媒体5F：Host装配、数据迁移与恢复对账

2026-10-25；承接5E-5。先提交本细则，再实现配置／存储、运行／对账和联合检查，合并完成5E-6。

1. media保持可选，依赖memory、来源跟踪及原生执行。Host解析固定工具、Python、模型／词表、TTS配置路径；不在运行时安装依赖或下载权重。QQ媒体依赖media，语音任务还需ASR与声音后端。接收、发送、直接语音任务三个开关分别生效。旧配置不默认开启。
2. media v2位于core目录；旧profile首次启用或从v1升级均需显式迁移。初始化只创建存储，不执行模型／媒体处理。现有media库即使插件关闭也纳入检查和迁移，不能用init覆盖。
3. 迁移清单包含media.sqlite、media/objects中的不可变对象和media-analysis中的正式分析记录。记录相对路径、长度、实际hash；拒绝目录逃逸／链接与迁移中变化，验证备份后才应用schema。work目录是可回收处理中间文件，不冒称已备份；权重和凭据不复制为模板。旧Run、来源、回执、人格和记忆保持。
4. 先装配media、恢复其存储与工作目录，再开放QQ入站。退出先停止新输入，保留依赖直到已有任务／交付排空；超时取消传入实际工作进程。single-run不启动QQ，但可以装配明确授权的媒体能力。
5. 对账只读已经保存的QQ媒体计划／部件回执与核心状态，必须匹配同一manifest。可确认sent／unknown／blocked时更新媒体导出状态并释放租约；不重发、不重新生成TTS、不调用模型。核心与渠道状态不一致保留明确诊断，不能拿恢复过程冒充新发送。
6. 状态只显示配置、生命周期、计数及稳定错误码，不显示URL、路径、转写或字节。示例使用本地测试人格和脚本模型，真实视觉／音频／平台验收仍延期。

相关检查覆盖旧配置、依赖缺失、路径、v1→v2与新增media库、对象／分析记录备份、源变更／链接拒绝、真实本地Host装配与重启、单次运行模式、恢复对账和停止清理。只运行相关测试，全量回归留到部署／发布；不连接服务器。

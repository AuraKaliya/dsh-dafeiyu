# 智能体级记忆阶段C：跨场景任务工作区

日期：2026-10-24。项目0.16.0，contracts/core/memory 0.12.0，memory.sqlite schema v4。本轮只在本机使用虚构场景、插件、资料及脚本模型测试；没有连接服务器、启动真实QQ或调用真实模型。

## 本轮实现与边界

一个智能体级任务可以显式关联多个会话、多个插件贡献的观察和记忆。每个会话继续拥有独立的DSH会话、聊天历史和当前任务选择。任务关联只授予受信核心使用已选中的证据，不授予任意插件读取其它会话全文的权限。

任务工作区保存目标、状态、版本、已加入场景及插件、选中证据、工作项、结果槽和观察关联。目标与全局内部快照只供原生协调器使用，普通回复模型只收到原场景允许表达的投影。工作项的命名槽可承载进展、待办或判断，本轮没有自动规划器、自动跨场景检索和交付路由。

阶段A的旧范围不扩大；阶段B的筛选决策继续由能力插件承担。任务层不会把所有收到的消息、所有观察或所有长期记忆自动关联到任务。加入场景、选择任务、关联具体证据是三个独立动作。

## 主插件与能力接口

| 接口 | 责任 |
|---|---|
| core.createTaskWorkspace({requestId,title,goal}) | 受信原生协调器创建任务，返回TaskController |
| core.resumeTaskWorkspace(id) | 重启后由受信协调器重新取得控制器，不重跑工作 |
| controller.read() / update(input) | 读取内部快照；用expectedVersion修改目标、标题或状态 |
| controller.reference | 可交给能力插件的原生任务引用，不包含内部读取函数 |
| handle.tasks.join(reference,input,context?) | 将调用插件的已授权场景加入任务 |
| handle.tasks.activate(reference或null,input,context?) | 用场景选择版本切换或清空当前任务 |
| handle.tasks.link(reference,input,context?) | 在原场景授权下显式关联所选记忆或观察活动 |
| handle.tasks.begin(reference,input,context?) | 固定任务、场景、结果槽及输入版本，取得工作票据 |
| handle.tasks.observe(ticket,report) | 沿用观察协议，记录任务过程中的选择性贡献 |
| handle.tasks.complete(ticket,{requestId,text}) | 校验后写入结果槽；迟到结果仅留档 |
| handle.tasks.view(reference,conversation,context?) | 读取本场景允许表达的任务投影 |

这些是原生插件接口，没有新增可由聊天模型任意指定任务、agent或route的全局工具。引用与工作票据由核心以对象身份绑定提供者和生产插件；复制UUID、JSON反序列化或借用其它插件票据均不能取得权限。卸载核心、生产插件或提供者后旧句柄失效。

渠道插件只能在自己的已注册渠道与账号下操作；无渠道能力必须在属于自己的有效ActionContext内加入、选择、关联并开始工作。异步工作可在原工具调用结束后用已签发票据提交结果，但不能据此新建任意场景权限。重启后工作票据不恢复，原生协调器需要明确安排新的工作。

## 证据选择与范围

记忆链接固定原场景、memoryId、revision、状态version、内容哈希、完整记忆祖先和时间线证据屏障；观察链接固定activityId和活动正文/回执哈希。关联时、开始工作时、提交时和读取时都会复查来源。记忆必须在原场景允许内部使用，不能用任务ID绕过internalUse=none。

同一任务的原生内部快照可以同时包含A场景和B场景的有效选中证据。A的聊天模型只获得A范围内允许表达的材料；混合A/B输入产生的结论不会自动投影到A或B。改写、摘要和任务进展文字不改变该约束。

任务观察除自身声明的exposure外，还继承工作开始时固定的全部输入依赖。输入包含其它场景或仅限内部使用的材料时，新贡献及新原文档案强制externalExpression=none。已有档案保持最初不可变的身份、正文与范围；新派生贡献仍受任务输入约束。无贡献活动的元数据也执行输入依赖和表达检查。

生产插件如实声明其实际输入是协议前提。插件自行读取未登记材料、或取得受信核心完整权限后绕过接口，不属于同进程能力接口可以隔离的安全边界。本轮不以正文相似度猜测不同插件的外部资源身份。

## 任务切换和并发

| 版本 | 防止的问题 |
|---|---|
| task.version | 控制信息和关联变更的过期写入；保留不可变历史版本 |
| task.epoch | 目标或状态改变后旧工作的结论继续成为当前结果 |
| scene selection.version | A→B→A后，把第一次A任务的迟到结果误认成新结果 |
| slot.version | 同一结果槽中多个工作项互相覆盖 |
| 固定输入证明 | 工作进行中来源变化、删除或额外关联改变其真实输入基础 |

开始工作需要任务active、场景已加入且当前选中此任务。输入只包含显式选择的linkId，之后新增链接不会偷偷加入已开始的工作。空输入可以记录无依据的内部进展，但这种结果不能直接进入聊天投影。

同一任务的不同结果槽独立提交，不因另一个槽完成而失败。不同任务即使使用相同槽名也独立。同一槽的两个工作从相同版本出发，先成功的提交生效，另一份标记late。任务切换、目标变化、暂停再恢复、源失效均使旧工作不能覆盖当前状态。

迟到观察保留在原任务的活动关联中，不加入当前选中证据；迟到完成文字留在原工作档案，不写结果槽。普通内部快照仅显示其状态，不返回迟到正文。本轮没有模型可用的“强制采纳迟到结果”工具或专门的迟到正文查询接口；历史数据仍在数据库中，后续可增加受控回查。

## 上下文与DSH压缩的关系

记忆插件向现有通用上下文协调器增加memory:task-workspace区域。每项有稳定身份、版本及来源引用，按现有区域与总预算装配；使用本轮的任务选择版本和本项来源证明，不使用无关场景更新的总任务版本。因此B更新自身资料不会让A仍有效的片段全部退出。

当前投影至多12项，依序选择本场景有效证据与结果；每个任务最多64条不可变链接，每次关联最多8条，每项工作最多16个输入。容量满时拒绝新增，不静默删除历史证明。未来需要更大规模时应增加选择与归档策略，而不是无限塞入上下文。

任务目标与全局私有快照不自动进入聊天或辅助压缩模型。场景切换改变压缩的taskId和selection版本；任务区域来源通过既有上下文依赖验证参与压缩与历史退出。删除或切换导致旧项退出时，其它插件区域、人格和DSH原生区域继续由原协调器管理。

生成期间来源失效会阻止旧回答交付。历史已发生的暴露不会被声称从未发生；后续可见上下文退出失效内容，原档案保留。

## 删除、修订与恢复

任务链接不复制记忆正文成为独立权威，始终指向原场景的版本与来源。任务工作输入保存在不可变job.body中；由该工作产生的贡献和新来源档案持久绑定taskWorkId。后续修订贡献也无法去掉原工作的输入依赖。

删除一条来源只使依赖它的链接、工作结果、活动和派生记忆失效，不影响无关槽或其它场景的独立历史。查询所有输入时，拒绝访问、删除和版本变化分别处理；不能因为先发现一条过期输入而漏掉后面的已删除输入。

已删除数据只在既有显式deleted模式和原有授权下读取，不能转为正常任务证据。恢复推进状态版本，旧链接和结果仍失效；要继续工作必须显式选择新有效版本并开始新工作。新建任务、重启、重复提交和摘要转述不能清除删除屏障。

独立使用MemoryStore检查任务派生记录时，必须调用taskWorkspace配置真实的来源校验器；未配置时对这种记录拒绝读取。生产MemoryService已完成绑定。循环或过深的任务来源链也拒绝读取，不回退为“无来源”。

## 存储、时序和迁移

schema v4在原memory.sqlite中新增task_workspaces、task_revisions、task_members、task_selections、task_links、task_jobs、task_slots、task_requests和task_observations。旧记忆、范围、来源及墓碑原位保留，不自动加入任务，不自动改变权限。v1→v2→v3→v4可逐级迁移，重复打开不会重建旧数据。

任务变更、观察贡献、链接采纳、结果槽、幂等回执和统一日志outbox处于同一SQLite事务。任何阶段持久化失败整体回滚。开始/完成/迟到/中断等事件记录任务、工作、槽、原场景和因果父事件；资料的发生、观察、入库时间仍由观察协议保留。并行完成顺序不冒充因果关系。

outbox沿用稳定事件ID补投；日志写入成功但确认中断也不重复。所有变更接口以requestId和参数指纹幂等，变化的参数不能复用旧请求。观察的请求身份不能从一个工作项移到另一个工作项。

重启保留选择、已完成结果、来源证明和日志；遗留running工作标记interrupted，不重跑工具，不自动发送。恢复以一个数据库只有一个活动MemoryService宿主为前提，不提供多进程任务租约或分布式调度。数据库版本不兼容旧程序，未来部署需一致性备份、代码与schema配套检查；本轮没有迁移真实私人数据。

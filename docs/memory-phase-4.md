# 第四阶段：通用上下文贡献与受控装配

日期：2026-10-23。项目0.7.0；contracts、core、timeline、memory为0.4.0。仅本机虚构样本开发，没有访问或修改服务器、真实QQ或用户凭据。

## 1. 与DSH的关系

DSH继续负责模型循环、提示词和工具装配、持久会话及模型可见视图。大肥鱼主插件负责上下文贡献注册、会话授权、预算和请求准入。记忆插件负责工作状态、选择证据及来源有效性。其他关联插件以相同接口贡献自己的数据，不需要改动模型循环。

实现绑定本机DSH 0.2.1-rc.2与Cordis 4.0.5，复用：

- `systemPrompt.context`注册动态上下文，`system-prompt/assemble`准备贡献材料，`refreshContext`在请求准入时再次验证。
- `session.append`及单节点`surfaceOp: replace`记录可见视图替换；原始档案不删除。
- `llm/stream`在实际适配器调用前核对最终请求，并阻止过期结果交付。
- `agent/request-error`仅在需要本地重建已冻结的重复快照时使用，不新增私有模型循环。

DSH包的入口声明未导出`runtime-context`的类型扩展，本项目按安装版本已有的事件形状提供局部类型声明，未修改node_modules。后续升级DSH必须重跑相关验收。

## 2. 关联插件接口

在既有`registerExtension`参数上增加可选`contexts`，旧的动作和渠道插件仍兼容API_VERSION=2。

```typescript
contexts: [{
  id: 'progress',
  kind: 'operational-fact', // working-state / evidence / operational-fact
  async prepare(request) {
    const scope = ctx.dafeiyu.scopeForContext(request);
    return readSelectedFacts(scope); // ContextItem[]；由插件按范围读取
  },
  validate(request, item) {
    const scope = ctx.dafeiyu.scopeForContext(request);
    return isStillCurrent(scope, item); // 同步校验，不执行网络或外部操作
  },
}]
```

`ContextRequest`包含当前会话、来源消息标识和取消信号，其对象身份必须由核心签发；克隆、伪造及生命周期结束后的请求不能取得授权。提供者随插件注册句柄一起注销。插件只提供数据类型、名称与内容，预算、优先级及是否必需由核心配置。

每个原子条目包含`id`、`version`、`text`、来源`ref/version/hash`和`expiresAt`。核心校验结构、冻结副本并脱敏正文；提供者负责自己领域的来源、版本和适用范围检查。通用核心无法替任意插件证明外部事实真实性，也不是防恶意插件的操作系统沙箱。

异步准备默认超时5秒。可选提供者出错时不沿用旧内容，其他区域继续；必需提供者缺失、失效或超预算时停止请求。准备失败后的迟到结果不能再获得授权或进入本次快照。

## 3. 区域与预算

DSH中注册一个具名容器`dafeiyu:controlled-context:v1`，内部保留各`owner:region`、类别、条目和来源。一次性汇总使多区域采用一致预算；它不是把资料提升为系统指令。稳定的使用规则与人格放在系统提示词，材料放在有来源标记的动态数据区域。

容器为DSH的required运行区域，确保最后准入检查持续生效；其内各贡献者是否必需由核心区域策略独立决定。停用记忆装配应取消记忆插件的`context`配置或注销提供者，不能把DSH关闭optional runtime context视为已停用这个显式启用的容器。核心不屏蔽或替换DSH原生安全、工作目录等区域。

默认预算：

| 项目 | 默认值 |
|---|---:|
| 受控容器总上限 | 16000 UTF-8字节 |
| 工作记忆`memory:working` | 6000字节，优先级500 |
| 检索证据`memory:evidence` | 8000字节，优先级200 |
| 其他注册区域 | 4000字节，优先级100 |
| 最终请求序列化上限 | 1000000字节 |
| 输出规划预留 | 16000字节 |

先处理必需区域，再按优先级分配；同优先级确定性排序。每个区域有自己的上限，共享剩余总额。超额时剔除整条可选材料，不切掉否定、限定或引用尾部。当前不是加权公平调度，也不保证低优先级区域一定有份额。

核心配置例：

```json
{
  "context": {
    "maxBytes": 16000,
    "requestMaxBytes": 1000000,
    "outputReserveBytes": 16000,
    "prepareTimeoutMs": 5000,
    "regions": {
      "memory:working": { "maxBytes": 6000, "priority": 500, "required": false },
      "memory:evidence": { "maxBytes": 8000, "priority": 200, "required": false },
      "fictional-tasks:progress": { "maxBytes": 2000, "priority": 300, "required": false }
    }
  }
}
```

准备阶段估算人格、工具、历史和原生区域占用；发送前对实际`messages/tools/toolHistory`序列化体积执行最终检查，防止原生区域在异步阶段增长后绕过预算。超出总额时停止请求，当前不会自动压缩历史。

这些字节数可复现，包含部分元数据开销，**不是DeepSeek等生成模型的精确token计数**。BGE的tokenizer只负责embedding分片，不能替代生成模型tokenizer；实际输出token限制继续由DSH模型配置管理。本轮没有重新认证2GB部署容量。

## 4. 工作记忆与证据选择

记忆插件配置中添加`context: {}`开启两个区域。工作状态保存在独立的`working.sqlite`，按agent和route隔离。working与evidence分别维护状态版本、不可覆盖的旧版本、幂等请求账本和审计outbox。清空是新状态版本，不删除长期记忆或旧档案。

工作条目分为目标、约束、纠正、待办、结果和缺口，必须附来源。当前支持有效长期记忆或标准化原始入站消息作为直接来源；任意DSH工具结果或分析报告不能直接冒充工作状态的原始依据。真实工具材料可先按既有规则保存为有来源的长期记忆，再显式选择。

证据区保存选中的记忆ID、内容revision、状态version、哈希和Unicode码点范围，不保存完整命中列表。请求前按引用重新取得正文。语义检索分数只用于选择排序，不作为真实性概率；记忆类别、自述/观察等限定仍随片段装配。

工作状态与证据均绑定`taskId`和显式有效期，有效期最长24小时。任务不匹配时不装配证据；工作区清空后，清空前的证据选择不会悄悄重新生效，需显式重新选择。资料来源、记忆版本或删除状态变化也会使相应条目退出。恢复记忆后的状态version已改变，旧选择不会因此自动恢复。

| 工具 | 用途 |
|---|---|
| `dafeiyu_memory_working_set` | 按expectedVersion替换工作状态，返回回执 |
| `dafeiyu_memory_context_select` | 按精确版本、哈希和范围选择记忆 |
| `dafeiyu_memory_context_retrieve` | 内部检索并选择前N条有效完整分片，只返回计数和回执 |
| `dafeiyu_memory_context_status` | 查询区域版本、存储条数与期限，不返回正文 |
| `dafeiyu_memory_context_clear` | 清空指定区域，保留长期记忆 |

所有模型入口均不接受route或其他会话标识。`admission: pending-next-request`仅表示选择已保存；核心可能因预算、版本或删除规则排除其中一部分，实际采用结果以`context.admitted`事件为准。

每次模型步骤都会重新准备材料；发送前与流式输出期间继续核验。校验缓存仅存在于当前核心请求对象内，并绑定记忆generation及两个工作区域的版本；任一变化都会使缓存失效，有效期另行检查。分析任务没有自动写入这两个区域的回调。

## 5. 旧快照退出及原生插件共存

DSH动态上下文变化会追加完整运行时快照。本实现根据具名容器识别自己的旧贡献，写入单节点替换事件：旧容器退出模型可见视图，同一节点中其他原生区域的名称和文本原样保留。替换事件标记为`dafeiyu-context-retirement`，避免干扰DSH对最新运行时快照的跟踪。原始事件仍可审计回查，历史读取不会重新执行工具。

还验证了一个特殊路径：原生区域单独变化时，DSH会把未变化的受控容器复制到新快照。若最终冻结请求出现两份相同容器，核心在调用模型适配器前记录旧节点替换，并通过DSH请求恢复接口重建一次请求。该次本地恢复不调用外部模型、不执行工具，不是重新运行用户任务。若仍不一致则停止，不无限重试。保持不变的上下文不会每轮追加新快照。

来源在模型解析期间发生变化，最后刷新会剔除失效条目；来源在请求发出后变化，已发出的内容不能撤回，本轮旧结果会被拒绝交付。下一请求重新读取状态。

本阶段处理的是**受控装配快照**。原始用户消息、此前普通检索工具的返回、助手已转述的内容以及未来压缩器产生的摘要，不能宣称都已清除。原始对话不在本次删除范围内；在接入压缩插件前，还需要实现摘要来源依赖与协同替换策略。

## 6. 审计与验收

`context.preparing`记录贡献提供者与来源消息链；`context.admitted`记录实际采用的区域、条目版本、来源引用、字节占用、预算剔除/失效计数及退出的旧节点数，不复制正文。工作状态写入与outbox同一事务保存，审计重放使用固定事件ID。

运行：

```powershell
npm test
npm run demo:context
```

本轮新增29项上下文测试，加上既有135项，共164项。覆盖多区域共存、原生区域更新、最终预算、会话隔离、来源和版本、过期、逻辑删除、同轮工具后重新装配、注销时立即撤销授权、完整主机重启、迟到数据、候选不注入及快照不重复累加。

演示使用真实DSH服务与模型循环，模型、embedding适配器均为明确标注的模拟实现；未重新调用真实模型或启动真实BGE服务。第二、三阶段的真实服务验收仍保留原记录，不将其计入本轮新增验收。

虚构中文演示结果见[memory-phase-4-results.json](memory-phase-4-results.json)：初始包含工作记忆、选中证据、虚构任务插件三个区域，受控内容1504字节；删除记忆后前两个区域的相关材料退出，虚构任务区域保留447字节，原生DSH区域仍在。未选中的资料没有进入上下文，另一会话也无法取得这份记忆或任务区域。

尚未实现完整历史压缩、语义关系图、分析进程隔离和持久档案保留策略。后续插件可以使用本阶段的接口接入；直接贡献DSH原生区域的插件仍由DSH管理，我们仅识别其名称并计入最终请求预算，不擅自改变其权限或正文。

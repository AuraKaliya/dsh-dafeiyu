# 整体验收7B-6：离线批次、恢复与证据导出

2026-10-26；承接`c7dcaff`。本步只装配虚构模型、虚构材料和真实本地程序状态，没有模型服务、QQ、B站或服务器连接。

## 行为与边界

- 按原162项清单的冻结顺序选取子集或全部。重复ID、未知ID和模糊选择立即拒绝。已有尝试默认跳过；`--retry`追加新的attempt，保留全部旧结果，不覆盖失败。
- 单独SQLite执行租约防止多个执行器同时运行、导出或恢复。活进程持有租约时拒绝接管；进程退出后可以显式恢复。PID不可访问／疑似复用时保守报忙，不终止进程。
- `--recover`只把遗留running标记为interrupted并保留未知费用；没有自动重放。需要执行原案例时另加显式选择与`--retry`。
- 历史准备使用`p/<完整attempt UUID>/`独立目录。失败准备原件保留；后续尝试另起准备目录，成功基线仍由同一历史／重复的三种条件共享。短目录避免Windows SQLite旁路日志路径过长。
- 每项关闭运行时后，对实际SQLite、DSH会话、来源、回执及夹具生成文件hash索引；数据库同时记录逻辑hash。成功案例缺索引不能导出为可评阅案例。重新导出前核验全部已登记尝试的文件，内容变化、额外文件、路径越界或链接均拒绝。
- 多轮边界问题的每次实际回答进入`answer.json`。脚本回答的语义评价始终是not-performed；程序检查通过只进入needs-human-review，不写人工通过。
- 每批记录顺序、重试／恢复选项、起止时间、CPU用量、进程内存信息；hash绑定账本审计。内存峰值是整个进程生命期的高水位，不能误称单案例峰值。文件索引提供该案例已保存文件的字节数，不代表模型服务资源消耗。

## 本机操作

在项目根目录执行，先阅读清单；以下命令均只支持离线脚本模型：

```powershell
node scripts/prepare-integrated-acceptance.mjs --list
npm.cmd run build
# 完成相关源码提交后，创建新的D盘正式证据目录；记录输出的root。
node scripts/prepare-integrated-acceptance.mjs --prepare

# 将示例目录替换为上一步实际返回的root。
node scripts/run-integrated-offline.mjs --workspace '<D盘正式证据目录>' --case B01-neutral-1
node scripts/run-integrated-offline.mjs --workspace '<D盘正式证据目录>' --report
node scripts/run-integrated-offline.mjs --workspace '<D盘正式证据目录>' --recover
node scripts/run-integrated-offline.mjs --workspace '<D盘正式证据目录>' --case B01-neutral-1 --retry
```

`--all`选择全部162项离线场景，不等于全仓测试回归或真实模型验收。本次没有执行完整162项离线批次。CLI没有`--real`，不能靠更改布尔开关启用真实服务。

正式证据默认在`.runtime/acceptance/`，不参与测试临时回收，也不进入Git。开发检查仍在D盘受管临时目录执行，成功清理，失败按3次／72小时／1 GiB保留。执行器没有删除正式材料的命令。

## 导出格式

每次导出使用独立ID，不覆盖旧报告：

- `machine.json`：冻结配置、162项当前状态、所有尝试及调用分页索引、程序证据核验、费用、批次资源索引，以及reviewId映射。
- `attempts-*.json`、`calls-*.json`：每页最多64条，保留offset和原始顺序，避免多次复测挤爆单文件大小限制。每页hash由machine索引保存。
- `review.json`：仅提供reviewId、实际问题／回答、共同语义标准与待评状态；移除案例ID、条件和执行顺序字段，并重新打乱展示顺序。映射只供组织者使用，不与评阅包一同交给评阅者。答案本身可能提示场景，不能承诺心理意义上的完全盲评。
- `index.json`：绑定两份报告hash和本次导出计数。失败／中断的全部尝试仍在机器报告中；评阅包只包含每项最新且程序检查完成的回答。

程序不会从脚本答案生成语义成绩。实际模型／平台为false，humanAccepted为false；离线计费数字不能当作真实账单。

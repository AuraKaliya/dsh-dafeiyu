# R6f 生产启动、现行渠道与夜间版本接管细案

2026-10-26。接续 `server-execution-r6-plan.md` 与已完成的 Host 执行器定向检查。本阶段根据 22:47 的服务器现行源码补齐生产接线，仍先本地开发与相关测试；候选完成并满足整体验收后才切换服务器。本文不是上线证明。

## 一、范围与当前缺口

独立 ManagedHost 是新大肥鱼唯一模型／人格运行入口，使用官方 DSH Agent/Session/Tools；现有桌面基础组件保持。新增受信生产启动程序，构造真实 Windows 权限证明与费用端口。现行 QQ 0.7.7、B站 0.3.3 仍在服务；其新增真实记忆、私信、队列和每日版本均不能被空初始化覆盖。

目前已具备固定 executor、Core 来源授权、原生任务人格交付、显式迁移与本机官方 CLI 检查。仍缺：生产启动工厂、父子共享费用准入、B站固定主人私信渠道、旧真实记忆读取映射、23 点维护和版本服务、更新守护对新进程的真实健康/空闲判断。不能用 162 项人格场景通过替代这些接线。

## 二、生产启动与资金所有权

新增独立 `@dafeiyu/server-runtime`，依赖 Host、executor 和现有 standing-authority 模块；禁止反向把 Host 装入 server-bootstrap，避免依赖环。只接受固定版本的 JSON 配置、路径与摘要，不提供任意模块、命令、端口函数加载接口。

1. 同普通 Host 入口，在 import 官方 DSH 服务前绑定本进程 DSH_HOME；不修改桌面环境、基础 profile 或用户全局环境。
2. inspect/status/init/migrate 延续已有离线语义，不创建权限探针、不启动模型/平台、不自动补建库。生产 start 先验证配置、正式底色、迁移、资金授权及固定程序清单，再预热 Windows 证明端口；失败关闭已取得资源。
3. 受信预算挂载在模型服务就绪后、Core/Memory/渠道构建和任何激活之前。它覆盖父模型、记忆分析、摘要、人格整理、独立校验和版本日志；新分析器的 SharedTransport 仍回到父 llm/stream。子 CLI 通过既有 IPC 向同一所有者预留、结算。
4. 父进程和子任务不能各建一个“剩余额度”。每次实际派发绑定唯一 callId、route、请求摘要、输入/输出上界、实际费用回执。子端按真实 jobId 动态绑定；多个 job 共用同一权威，不复用一次 job 的回执。断链、异常用量、重启遗留预留按未知保留，恢复不自动调用模型。
5. 7C 继续使用 `.runtime/acceptance/7c-20261026` 原账本、lease、attempt 与时钟。运行工厂只借用程序端口，不创建 attempt/授权/时钟，不复制原账本到服务器；开发联测使用虚构账本。9 笔实际费用未知标记和现有停止规则保持。
6. 正式服务器运营资金另在部署清单中明确授权来源、金额/时间边界与停止行为；本方案不生成新增授权，不把验收剩余额度改成永久运营资金。没有可用资金端口不能开放付费 dispatch。总额或期限到限时停止新派发，保存已有回执，不能自动追加。
7. Windows port 由启动程序持有；Host 和 executor 完成排空/结算后才关闭探针。状态只包含身份摘要、在途数量、费用摘要和稳定错误码，不记录 secret、环境全文或内部思考。

专用 CLI 仍只提供固定文本、文件与命令操作，采用已验证的文本计费边界。父 Host 视觉必须另证 Files 内部重试/上传费用覆盖，未经证明不能放行 7D 视觉付费调用；不以禁用正常重试冒充关闭 Files 重试。

## 三、原位历史与版本数据适配

新增 `@dafeiyu/server-compat` 的 existing-only 历史适配器：只在指定服务器现存 history.sqlite 上打开，不创建父目录、marker、DDL 或 Git 仓库。先验证真实路径、schema=1、必需列/索引/不可变记录触发器和完整性；不匹配时明确停止。开发测试仅用 D 盘虚构库。

原 records/imports/cycles/versions/blobs/snapshots 原地保留，原 ID、source_key、hash、水位和已提交版不改写。新 Host 事件使用独立命名空间与实际来源摘要，重复同 key 同内容幂等，异内容冲突。新增记录只接收程序端白名单结构和已脱敏可见内容，丢弃 thinking/reasoning/replay；没有跨会话的模型通用查询接口。

cycle/version 写入使用原身份与预期版本状态的事务比较，不覆盖并发推进、未知字段或已完成记录。existing-only 打开不能调用旧 HistoryStore/NightlyCycle 构造器。旧 session 归档不再整根扫描；旧 imports 保持，新增归档只来自本项目持有的精确事件/会话 ID。已清除历史不重建。

已核实本地参考文件与线上原字节一致：调用限制解除开发中的 version-manager、nightly-cycle、persona-memory、shared-memory，摘要见线上审计；可以参考对应算法，不能覆盖线上文件。history-store 本地参考与线上不一致，只依据本轮现行可见源码及后续 schema 元数据适配，不猜测缺失代码。

## 四、固定主人 B站私信渠道

新 `channel-bili-owner` 与公开浏览能力分开。接入真实账号 170759822 和唯一主人 13461350 的独立私聊 scene；模型不能指定 receiver、凭据、任意 URL 或账号。不加载旧 worker、旧 PersonaMemory、全局旧 tools，也不把 B站消息标成 QQ 主人任务。

底层 transport 可复用经原位 hash 核验的现行 BiliAccount/BiliAuth 的固定 readDm/sendDm 行为，或实现等价的严格端口；只能在服务器内使用原登录态，不复制到本地。旧发布、登录管理及任意私信工具不进入新普通会话。项目已确定的 B站首版仍为搜索、画面/音频/字幕/弹幕/评论理解；不新增自主评论。现行旧公开发布能力的注册变化必须单列在切换差异清单，不静默称为完整保留，也不借管理员 CLI 绕过平台对象限制。

新渠道持久化真实入站、来源摘要和发送计划，Core 负责正式人格会话和回复。发送必须绑定原入站、原 scene、固定主人、正文 hash 与活交付核验；pending、sending、sent、unknown 分开。发送前先记派发，真实 receipt 才能完成；不确定结果保留，不换请求 ID 重试。先限定文字并明确单条上限；若分段则每段有独立持久回执，不能只截断后声称全文已交付。

显式迁移旧 seen、legacySeen/legacyIdUntil、since、accountUid、精确字符串 seqno/ID 以及 queue/claimed 状态。未认领队列只在来源核验和单消费者切换后接入；claimed/不确定项保留为待核对，不自动重放。旧 state/新 ledger 在服务器原位备份，私人正文不下载到本地或 Git。旧 QQ/Bili 不会因为新代码安装而自动停止；切换必须排空并核验唯一消费者。

## 五、真实记忆与夜间周期

现有偏好、关系、用户事实及撤回信息继续保留。新增只读 legacy 来源映射，依据原 route/user/resetAt/有效期限制读取；输出标为历史主张，具有真实文件/记录版本，不直接成为 adopted 人格。未知归属材料不可放进全局 prompt，也不能加载用户已拒绝的旧固定核心。后续人格改变仍走 propose/review/trial/outcome/adoption/publish。

独立版本服务沿用北京时间 23:00、firstDay=2026-10-22 与原 daily/manual cycle ID，顺序固定：新 Memory 维护屏障 → 项目可见记录归档 → 冻结版本计划与私有快照 → 官方 DSH 受限日志会话 → Git HEAD 比较交换 → 原 history 中 version/cycle 完成。原 prepared/commit_prepared 计划先按冻结证据处理，后来的事件归下一增量；不能创建 bootstrap 请求绕过既有状态。

维护屏障须复用现有 Activity/Memory 唯一调度者，汇总冻结范围的真实 receipt、剩余项目与持久水位；pending 为空、metadata settle 或模型说“完成”都不构成证明。必要的维护窗口是程序级暂停准入并保留服务，不调用 close 后伪装仍在线。维护、归档、日志、资金或 Git 任一失败均保留真实阶段，不提前 complete。

Git 使用受信固定仓库/可执行文件、冻结 tree/临时 index、expected HEAD 比较交换。保留正常工作树/暂存区修改；运行库、凭据、可变私密记忆不入 Git。新 SQLite 私有快照使用正确备份路径和 hash 清单，不交给旧 UTF-8 文本脱敏函数，不纳入代码回滚。日志仅获取可见证据索引与统计。

## 六、守护与清理切换

保留独立 SYSTEM update-guard。维护守护前核实没有 active update；只在独立维护流程扩展新进程控制、真实 Host/executor/DM/versioning 空闲和健康判定、新 TypeScript 测试入口及代码清单。不得用旧 QQ/Bili 同名健康文件伪装新入口成功。

新候选在验证期间保持入站与自主唤醒受控，检查实际平台连接与依赖就绪，不产生双消费者或测试公开发言。代码回滚仅换代码/配置，不能覆盖新增真实记忆；有新数据或发送后须依据保留账本接管，不能把旧 seen/游标回填成旧备份。只有确认健康及账户/主人绑定后发送一次已授权 QQ 问候，保留实际回执。

插件清理只针对市场额外下载/配置项，逐项证明不属于官方基础功能及其必需依赖闭包，先解除注册，再按候选清单处理代码。保护基础 DSH、仍被使用的兼容库、守护、凭据与真实数据。来源/依赖不明项继续待核验；不得直接清空目录。

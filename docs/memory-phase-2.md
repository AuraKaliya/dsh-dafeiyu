# 记忆能力插件第二阶段：中文全文、BGE召回、分片与缓存

日期：2026-10-23（北京时间）。项目0.5.0，记忆插件0.2.0。当前完成用户指定的第二阶段检索闭环；只在本机用虚构样本验收，没有连接或修改服务器，没有加载到真实QQ实例。

## 实现范围

- 对当前会话内有效记忆正文建立中文全文索引。
- 通过已验证的FastEmbed＋ONNX协议调用本机BGE服务。
- 用真实BGE tokenizer按token分片，保留完整正文与Unicode码点范围。
- 缓存绑定完整profile、智能体、会话、查询／文档角色及文本哈希。
- 继承第一阶段的来源依赖、逻辑删除与版本过滤，防止旧索引或旧缓存恢复已删除记录。

本阶段全文检索对象是已保存的记忆正文，不是任意DSH原始聊天档案。原文回查仍走时间线及记忆来源接口。未实现自动记忆提炼、信息真实性分析、语义关系图扩展、上下文压缩或自动注入。

## 公开入口与兼容性

配置retrieval后新增 `dafeiyu_memory_recall` 工具；未配置时保持第一阶段8个工具，不启动任何模型或tokenizer进程。直接调用未配置的recall返回not_configured。

| 参数 | 行为 |
|---|---|
| query | 查询问题，1～2000字符；调用方不要手动添加embedding指令 |
| strategy | lexical／semantic／hybrid，默认hybrid |
| limit | 返回1～20条不同记忆，默认5 |
| rebuild | true时重建当前会话、当前profile的派生索引 |

延续核心v2字符串工具参数，服务边界转换数值和布尔值并严格校验；模型不能指定route、profile、文件路径或数据库。

第一阶段的 `dafeiyu_memory_search` 继续提供兼容的字面搜索与分页。已删除记忆仍通过专门的deleted_search／deleted_open查询，不混入新的全文或语义入口。

结果包含memory ref、内容与状态版本、来源引用、分数类型、命中片段和Unicode码点范围。片段预览最多600码点，截断时明确标记；偏移指向记忆正文，不冒充DSH原始消息中的字符位置。需要全部内容时使用memory_open，再沿sources回查原文。

所有结果标记untrustedEvidence，分数不是可信概率。返回候选不等于已经证明问题有答案。

## 中文全文检索

使用SQLite FTS5。文本先作NFKC规范化和小写转换，提取Unicode汉字单字／双字及拉丁字母、数字、下划线标识符。原文与偏移保持不变，规范化只用于索引词项。

可覆盖两字姓名、扩展汉字、全角编号及常见中英混合标识。词项编码成安全ASCII token后组成FTS表达式，用户输入的引号、OR、NEAR或通配符不会成为查询语法。

FTS候选在SQL中按智能体、会话及profile限制；应用只处理该范围的记录。BM25的文档数、词频与长度统计仅来自本次可见语料，不使用全库FTS bm25分数。因此其他会话增加同词材料不会改变本会话的词频统计或候选。

查询最多512个不同索引词项，超过时明确返回query_too_complex，不静默截取关键词。它是当前轻量中文检索方案，不是通用中文词法分析或实体识别器。

## BGE与完整profile

默认profile位于 [bge-onnx-v1.json](../packages/memory/profiles/bge-onnx-v1.json)。模型固定为BAAI/bge-small-zh-v1.5、512维、CLS／L2、float32输出；文档不加前缀，查询由客户端添加一次中文检索指令。

profile绑定：

1. 模型和分词配置7个文件的SHA256。
2. 已核对的FastEmbed、ORT、tokenizers等8个软件版本。
3. 既有服务代码及4份FastEmbed关键源码指纹。
4. 池化、归一化、维度、数据格式、查询／文档前缀。
5. token／字符上限、分片算法版本、全文词项算法版本。
6. tokenizer工作程序代码SHA256及传输契约版本。

完整定义规范序列化后生成profile hash，运行时深冻结，避免对象被意外修改后继续沿用旧缓存键。改变定义会产生独立缓存和索引命名空间，即使模型名和维度相同也不会混用。

tokenizer进程首次启动时核对本机指定的模型文件、软件版本和服务代码。HTTP推理前核对health中的模型名、维度和加载状态；响应核对模型、顺序、条数、512维、有限值及范数。

这些检查验证配置的本机材料和接口契约，并不构成远端进程的密码学证明。现有health没有完整profile指纹，未来部署仍需核对实际加载的服务，禁止在不切换profile的情况下偷偷替换模型。

## 按token分片

新增轻量Python tokenizer工作进程，只加载已核对的tokenizer，不加载FastEmbed模型或Torch，不读取聊天档案，不访问网络。

默认每片最多480 token，包含特殊token；同时限制每片6000个Unicode码点。先依据真实token偏移选边界，尽量在后半段的句号、分号或换行处分片，再重新编码每片核对预算。超长未知词等特殊情况通过缩短片段并重新编码处理，不假设字符数等于token数。

片段范围连续、不重叠，拼接后必须与正文完全相同。emoji、组合字符、换行和空格保留原状。该版本没有实体感知或重叠窗口优化，跨片段语义需要后续通过来源回查或检索策略补充。

查询包含前缀后超过512 token时返回query_too_long，不交给服务静默截断。分片器无法证明完整覆盖或预算时，拒绝发布该索引。

## 缓存与派生存储

记忆数据库仍保持第一阶段schema=1，不迁移或重置权威正文、版本和删除标记。新增独立retrieval.sqlite，当前派生schema=2：

| 表 | 内容 |
|---|---|
| profiles | 完整profile定义及hash |
| snapshots | 各智能体／会话／profile对应的记忆世代 |
| chunks | 当前可见版本的分片、位置、文本、词项和稳定来源顺序 |
| chunk_fts | FTS5词项索引，由触发器维护 |
| vector_cache | 有界float32向量缓存，不保存原始查询文本 |

缓存键为 `(agentId, route, profileHash, role, textHash)`。相同文本在不同会话或查询／文档角色下不能直接复用缓存；缓存不是召回候选库，命中缓存不授予访问权限。

默认最多8192个向量，约16MiB原始向量数据，实际数据库还包含索引和元数据。按近似最近使用淘汰，命中时间最多每分钟更新一次，避免每次缓存读取都产生同步磁盘写入。损坏或格式不符的向量会被移出派生缓存并重新计算。

只为变化的记忆重新分片，只为缺失的向量调用BGE。profile变化不清空原始记忆；旧profile数据不参与当前查询，缓存受全库条数上限约束。派生索引schema=1可迁移到2，保留向量缓存并让范围快照失效后重建稳定排序。

## 检索、隔离与删除

流程：核心签发范围 → 读取当前有效记忆 → 分片／索引同步 → 全文或语义召回 → 可选RRF → 按记忆去重 → 再核对当前状态 → 返回片段与来源。

正常索引只包括未删除、未被替代且来源依赖仍有效的当前版本。逻辑删除即时影响读取授权；旧派生行的物理清理由下次同步完成，不能在此间通过recall读取。恢复后再次检查当前有效性，符合条件时可复用同profile向量。

每次异步分词／推理前后检查活跃上下文和会话记忆世代。若其间删除、更正或依赖发生变化，返回stale_state，不能写入旧响应的向量缓存或返回旧候选。插件卸载和操作取消同样撤销后续使用。

重建只处理当前授权范围的派生索引，已删除内容继续留在原始记忆库中，专门查询仍可查到；不会因为重建或缓存存在而复活。旧的已删除内容、其他会话内容不发送给本次embedding请求。

混合排序采用固定RRF k=60。同分时按稳定的来源顺序处理，不依赖随机记忆ID。每条记忆选一个最佳片段，避免长记忆的多个片段占满结果列表。关系图扩展、时间意图重排尚未加入。

## 降级和资源边界

推理端不可用、返回错误向量或模型身份不符时，hybrid明确降级为lexical并附degradationReason；semantic不伪装成功。若当前记录还不能完成真实token分片，则返回tokenizer_unavailable或profile_mismatch，不能偷偷用字符切片冒充token分片。

只允许loopback HTTP的 `/v1/embeddings` 地址，拒绝外部域名、URL凭据、查询参数及重定向。请求串行，每批不超过8条且总字符数不超过24000；客户端限制响应体大小，不自动下载模型或切换外部服务。

默认每个会话最多同步1000条有效记忆、5000个片段。超出返回capacity_exceeded，不把部分索引冒充完整结果。降低容量后已有快照也会重新检查；删除条目后可重新同步。词频统计按行处理，避免为全部片段常驻保存词频Map。

以上是单次检索、内存和缓存资源参数，不是每轮工具调用次数限制。已有记忆容量不因此被删除；可调整配置或在后续加入后台增量索引策略。

服务器总内存4GB，继续按2GB规划预算。产品客户端只启动tokenizer工作进程并复用已有推理服务，不额外加载BGE。当前测试没有完成2GB受限整机组合压力验收，不能用前一轮约439MiB的模型压力值代替新增索引、DSH与其他程序的组合测量。

## 配置和本机运行

retrieval为可选配置，使用明确绝对路径：

```ts
{
  agentId: 'dafeiyu',
  dataDir: '<本机独立测试数据目录>',
  retrieval: {
    endpoint: 'http://127.0.0.1:<本机测试端口>/v1/embeddings',
    python: '<已准备环境的Python绝对路径>',
    modelDir: '<指纹匹配的ONNX模型目录>',
    serviceFile: '<已核对的embedding_service.py绝对路径>',
    // pythonPackages: '<使用独立packages目录时指定>',
    // profileFile: '<可选的完整profile文件；默认使用包内profile>',
    timeoutMs: 30000,
    maxDocuments: 1000,
    maxChunks: 5000,
    maxCacheEntries: 8192
  }
}
```

本机真实验收前置条件为上一轮已准备的FastEmbed环境和模型文件；没有自动安装或下载逻辑。可以按 [既有复现说明](../benchmarks/fastembed/README.md) 准备。

```powershell
npm.cmd test
npm.cmd run accept:memory-retrieval
node scripts/verify-memory-retrieval.mjs
```

第二个命令先运行真实tokenizer契约测试，再在本机临时端口启动已核对的服务副本，执行验收并关闭进程树。它不连接服务器6190/6191。结果保存在独立.runtime目录及 [虚构样本验收结果](results/memory-phase-2.json)。

## 验收结果

- TypeScript构建及105项自动化测试全部通过，含本阶段新增23项；原有82项继续通过。
- 真实BGE tokenizer的4项测试通过：长中文尾部、Unicode／组合字符、超长未知词和空白边界。
- 真实本机BGE HTTP服务＋产品记忆插件＋真实DSH服务的闭环通过；对话模型使用脚本模拟模型，不是新的真实对话模型／QQ验收。
- 继续使用100条虚构材料。本入口只做正常有效记忆召回，排除2个专门历史／已删除查询后共45个查询，其中41个有答案；4个无答案查询不计入Recall。

| 方式 | Hit@1 | Recall@5 | MRR@10 |
|---|---:|---:|---:|
| 中文全文 | 58.54% | 92.68% | 0.7305 |
| BGE语义召回 | 73.17% | 95.12% | 0.8374 |
| 混合召回 | 78.05% | 95.12% | 0.8585 |

语义阶段计算了97个可见文档向量和45个查询向量，共142个；随后混合阶段与重复查询使用同profile缓存，没有新增向量计算。无答案查询仍可能返回相似候选，不能根据非空结果推断有答案。

长文本验收命中了正文码点1425～1765的尾部片段；删除后强制重建返回0条，专门删除查询仍保留完整正文。自动化测试还覆盖其他会话对词频和后端输入不产生影响、父记忆删除、profile变化、缓存角色隔离、异步失效、降级、非法HTTP响应、容量变化与索引重建。

本样本规模小且手工标注，不能代替真实长期分布、长时间运行或大规模索引测试。原来的43个有答案模型评测包含2个专门查询，与这里41个正常查询口径不同，不能直接把两个百分比当作模型退化。

本轮未修改服务器、未启用真实QQ、未上传运行数据库或缓存。独立分析、上下文装配及完整记忆整理仍待后续开发。

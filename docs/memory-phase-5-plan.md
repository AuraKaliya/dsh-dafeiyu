# 第五阶段开发方案：大肥鱼专属主动压缩与归档

日期：2026-10-23。方案承接记忆方案v1.3及第四阶段通用装配接口。

当前进度：M5A工具反馈及M5B主动历史压缩已在本机实现，分别见[A验收](memory-phase-5a.md)和[B验收](memory-phase-5b.md)。M5B采用会话级状态代号保守失效，工具轮次和已有摘要暂不再做语义压缩。M5C多代摘要、精细依赖分片及错误经验整理仍待开发。本文件中的规划不代表全部能力已上线；服务器和真实QQ未修改。

## 1. 范围与职责

压缩专门服务大肥鱼，按agent、渠道、账号、会话和任务划分输入。主插件掌握注册、授权、预算与提交时机；记忆插件实现反馈归档、材料选择、摘要依赖和失效规则；DSH继续提供模型循环、会话、检查点和模型可见视图。

不改写无关插件代码、不接管其他DSH智能体的请求。同一大肥鱼会话只有一个压缩提交协调者。其他插件区域默认保护，只有明确适配的区域可以按自身策略参与处理。

## 2. 根据提示词架构选择内容

| 内容 | 策略 |
|---|---|
| 固定人格、稳定行为与权限规则、工具定义 | 保持稳定，不做语义摘要 |
| 当前目标、最新纠正、授权边界、未完成事项 | 保留当前有效版本，优先保障容量 |
| 当前正在使用的原文证据和工具结果 | 保留必要原文，不提前收起 |
| 已使用完的检索命中、工具输出、阶段讨论 | 收起正文，留下结论、原文引用和必要限定 |
| 已提交且仍有效的历史摘要 | 尽量保持稳定，必要时再合并 |
| 无关插件及未识别区域 | 保留，不猜测其语义后压缩 |

逻辑区域不等于消息位置。不能为了分区重排用户消息、工具调用和结果。选区必须满足工具配对边界；遇到不能拆分的受保护混合节点，选择其他合法区间或报告无法安全缩减。

尽量保留选区之前的稳定前缀，减少重复改写和缓存失效。最新用户输入与正在使用的尾部同样保护。删除、更正和权限变化优先于缓存收益，稳定前缀不能成为过期数据的永久豁免区。

## 3. 主动触发与预算（M5B）

自动检查是正式功能，手动入口用于诊断和验收。每次模型请求前检查，并在大型工具返回后更新压力状态。

联合判断：整体预计输入压力、自上次有效整理后的新增量、可安全回收的材料量、是否存在当前任务不能丢失的内容、压缩预期收益与自身成本。初始本机实验可采用可用输入预算约75%触发、争取降至55%—60%的目标，必须按实际路由和中文样本校准后再确定部署值。

配置还应包含最小可回收量、冷却与增长条件、近期原文保留量、摘要输出预算。压缩成功后更新基线；没有新增长或有效收益时不重复整理同一份材料。限制针对一次恢复流程的收敛，不恢复任何旧的每轮工具调用次数上限。

接入DSH tokenMeter并保留字节硬上限。计量中的文本启发式不等于当前生成模型的精确tokenizer；BGE tokenizer不能替代生成模型token计量。若主要占用来自受保护区域，报告预算不足，不擅自压缩其他插件。

## 4. 工具反馈先减少无用累计（M5A）

提供者显式声明结构化反馈协议。反馈应保留：执行结果、副作用状态、原始完整性、资源版本、错误代码与信息、回执、来源及原始数据。

先保存可归档的完整返回值，再生成有界反馈。优先保留状态、错误代码和回查引用；详细诊断或回执超预算时明确标记未内联，不冒充完整反馈。正文预览只能标记为预览，不能代表语义结论。

档案按需分页读取，不重新执行工具。原始输入已经不完整时，读到档案末页也不能改称完整。回查片段只用于当前请求它的回合，之后退出活动视图；原始档案仍在。

未知或未适配工具保持原有返回形状。当前不启发式裁剪任意工具输出，不自动调用模型生成工具摘要。生产工具的适配需要逐项定义其状态和重要字段，不能把虚构工具验收当作QQ/B站等真实工具已经适配。

## 5. 增量历史压缩与多代摘要（M5B/M5C）

流程：原始日志已经持久化 → 冻结合法选区及来源版本 → 排除已删除/失效材料 → 生成结构化摘要 → 验证来源、缩减收益及任务完整性 → 提交前复查 → 使用DSH检查点替换 → 重新装配当前区域。

摘要应分片记录结论、决定及原因、未完成事项、约束、纠正和证据缺口。每片绑定会话、任务、来源事件和原文位置、记忆内容版本与状态版本、插件区域、哈希、规则版本和模型路由。

多代摘要保留到原始依据的依赖链，不能只剩“摘要引用摘要”。当前任务由工作记忆提供，历史摘要表达其当时状态。摘要不自动晋升为长期记忆，也不能变成新的权限来源。

复用DSH压缩约定、工具配对检查、生命周期、取消与恢复。Basic后端只开放摘要钩子，具体实现前应锁定安装版本验证；选区保护、提交前记忆校验和多区域依赖需要适配，不能只替换提示词。一个会话不同时挂载两个自动压缩写者。

M5B已为第四阶段载体退出和M5A反馈退出补齐tokenMeter可用时的prune计量衔接，防止旧内容退出后压力数字未下降而反复触发。摘要辅助请求有独立请求标识、用途和预算，使用当前绑定模型，不混同正常聊天回答。复用公开压缩机制与检查点，不直接套用Basic固定选区策略。

## 6. 删除、版本与恢复

逻辑删除保留原文及版本，排除正常读取、摘要、装配及重建。显式寻找已删除资料继续受会话范围约束，不等于恢复。

声明的来源被更正或删除时，工具反馈、工作状态及摘要各自检查依赖。摘要无法可靠拆分时先撤下整个受影响片段，再按有效来源重算。独立无关区域保持原样；确实依赖被删来源的其他条目也应失效。

压缩期间出现删除、纠正或选区变化，拒绝旧结果。普通摘要失败保留仍有效的原上下文；删除导致的失效内容即使重算失败也不能恢复。恢复原记忆后重新校验，不自动重新激活旧摘要或旧回查视图。

原始聊天、普通未适配工具输出及助手转述不属于M5A的全面清除范围。M5B开始记录受管轮次，使用会话级状态代号撤下旧轮次及其转述；原始归档保留。启用前无归属清单的历史不自动纳入摘要，仍不能宣称一次档案删除已经让模型语义上完全遗忘。

## 7. 归档与部分失败

DSH日志继续作为对话原文依据；工具反馈档案保存工具实际返回的JSON值或文本数据，经过既有凭据与思考字段脱敏。摘要与索引属于派生数据，重建必须读取当前删除状态。

SQLite档案、状态和审计outbox原子提交。M5B选择将轮次清单、压缩状态和检查点放入同一DSH日志，避免另设摘要SQLite库的双写；使用正式插件记录接口，恢复时核对来源哈希、当前状态和成功end标记。未封口轮次及未完成检查点退出活动视图，不凭审计日志重做操作。

原文归档失败必须明确报告；操作已经成功时，不得把归档失败描述为原操作没有执行，更不得自动重放有副作用动作。异常没有可靠结果时保留未知状态。暂不物理搬移或删除DSH管理的日志；持久档案保留策略后续单独确定。

## 8. 减少错误的后续方向

工具参数、分页与返回边界明确化；重复读取在资源版本相同且授权仍有效时可复用已知资料。失败经验先保留为有适用条件和有效期的任务状态，重试依据错误类型及前置条件是否改变。暂时超时不能固化为“能力不可用”。相同参数也不表示发送、写入等操作可以重放。

衡量效果应同时看：活动上下文增量、重复错误率、关键约束遗漏、回查次数、压缩开销、缓存复用和其他区域完整性。不能只追求压缩比例。

2026-10-26。本地只读接入分析已收敛为[可实施的 R6 主方案](server-execution-r6-plan.md)。详细契约、实施拆分、恢复、费用、验收与阻断以主方案为准，本文保留结论和部署边界，避免两份完整规范漂移。尚未实施或部署；当前校准结束后先完成R6并重新freeze/cal，正式162不先运行。

## 确定事实与选定路径

- 当前ManagedHost没有通用文件／命令工具或旧管理员CLI执行器；它只装配工具注册表和本项目能力。
- Core的聊天及原生Task均屏蔽继承的全局工具；把包挂入现有DSH不会自动恢复管理员能力。现有包有Cordis apply/inject，可以复用现有DSH服务，不必重写人格、记忆或模型循环。
- 选定“现有DSH/Cordis＋受信bootstrap＋V3 CLI适配＋专用headless profile＋独立update-guard”。不恢复全局工具继承，不开放任意plugin import。
- 完整CLI声明external-write。Core只新增默认关闭的原生Task命名授权；旧配置不补默认字段、旧Run/人格记录和hash不改。普通会话仍不能直接执行。
- 主人任务由真实QQ来源、身份和指令核验；自主wake使用独立standing authority和真实活动证明，不伪造主人消息。
- 子CLI使用固定可信路径／profile，真实管理员token另验。计费在每次实际派发前向父预算端口预留，复用唯一授权账本；旧calls计数或headless step_end汇总不能作费用保护。
- 结果经新Core来源核验和目标人格回报链发送，不直接转发executor报告，不复用旧ServerTasks的自动发送／附件旁路。

## 用户最新插件清理边界

“清空其它插件”只指后来从市场额外下载／额外配置的插件。**DSH自身架构中的官方基础功能插件绝对不能动**；必须按实际inventory、安装来源、有效bundle与依赖闭包分类，不能按官方前缀或所在目录猜测。

- 保留DSH基础服务、官方基础功能及其必需依赖；新大肥鱼按独立固定清单装配。
- 额外插件经依赖核验后按明确清单解除注册／移除；不能连带删除基础或新大肥鱼需要的依赖。
- 旧QQ/Bili额外插件只有在新链路接管、排空并确认单一消费者后才停用／移除。
- 独立SYSTEM update-guard属于运维保护，保留并适配，不当普通市场插件清除。
- 真实新增记忆、关系、会话、账号及凭据保留；不重跑旧初始化、Cutover/Finalize，不恢复已清除历史。
- 来源或依赖关系未明时先核验；清理不是清空整个DSH profile再重装。

## 仍须明确验证的边界

专用headless不装QQ/Bili发送或公开发布工具、不注入平台凭据；generic CLI不会因此获得新的平台权限。管理员CLI仍非OS沙箱，不能声称仅提示词或不加载发送工具就绝对阻止文件／网络绕行；实际隔离强度和未决副作用须如实记录。

旧本地执行器/guard镜像仅提供参考。上线前只读核对服务器实际DSH/Node/ABI、profile/工具、Windows身份、账号绑定、Git差异、guard状态、任务和数据路径，再形成合并候选；不能依旧镜像直接上线。代码与可变库/会话/媒体/executor账本分离，避免guard代码回滚覆盖真实数据。

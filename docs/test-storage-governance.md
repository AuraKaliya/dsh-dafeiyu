日期：2026-10-25。依据用户确认的方案实施；范围仅限本地测试文件治理，暂不继续QQ 2C，不连接或修改服务器。

## 2. 唯一测试入口

```powershell
npm.cmd test
npm.cmd test -- build-tests/qq.test.js
npm.cmd test -- tests/tooling/test-storage.test.ts
npm.cmd run test:cleanup
```

入口 `scripts/run-tests.mjs` 先取得专用测试锁，再建立 `.runtime/tests/run-<UUID>/`。本机解析后必须位于D盘。每次编译、测试进程及其子进程通过预加载脚本获得独立workers目录；TEMP／TMP／TMPDIR／DSH_HOME和测试HOME／AppData均在本次运行内。只改变子进程环境，不修改系统或用户环境变量；测试用Host协调库也进入临时HOME，不借用用户真实协调文件。

原23处系统临时目录调用改为受控的 `testTempDir()`。绕过入口直接运行这些测试时，在创建临时文件前报错，提示使用受管入口。明确传入工作目录的正式验收／演示保持原目录；迁移演示改用显式的D盘演示目录，不借用C盘Temp。

资源先由原夹具关闭，整个测试运行结束后再删除工作目录。数据库关闭／重开、崩溃恢复和迁移中断用例可在同一次运行中继续使用原数据。主测试进程与子进程都有归属标记；活跃进程、错误标记、目录链接替换及来源不明内容会阻止清理，不猜测其归属。

## 3. 保留、回收与空间限制

- 成功运行：所有进程退出后删除工作目录，保留简短结构化结果。
- 失败运行：按最近时间保留最多3次、最长72小时、合计不超过1 GiB。超龄、超过次数／累计大小或单次超过容量的现场删除，仍保留结果报告；不自动突破上限。现场指本次运行的合成测试文件，不复制真实凭据或聊天。
- 异常退出：下次入口先检查原主进程及所有已登记子进程；确认结束后标记interrupted并套用相同保留规则。异常现场无法确定结束时间时，从创建时间计算72小时，不重新延长保留期。初始化中断而缺少归属标记时报告待核查，不自动接管。
- 清理失败：有限重试，结果必须列出阻塞；即使功能测试通过，入口也返回失败。下次运行先重试清理，未解决前不继续堆积新数据。目录链接只移除链接本身，不遍历目标。
- 开始前及运行中检查：D盘至少保留5 GiB可用空间；单次工作目录上限2 GiB、运行时长上限10分钟。达到门槛停止本次测试子进程树、记录失败并进行保留／清理。这些是开发测试预算，不是大肥鱼的模型调用次数限制。

专用目录内保留owner／run／process标记；递归删除前核验绝对路径与真实路径，删除根目录自身或越界路径被拒绝。主机上的其它Node进程不由测试清理器停止。运行结果保存在 `.runtime/test-reports/`，最多20份，只含状态／计数／阶段耗时和清理结果；每一步选取必要报告保存到项目文档与Git。

保留期限在每次受管入口开始／结束时执行；`npm.cmd run test:cleanup`可只执行回收，不构建、不运行测试。未安装系统计划任务或常驻清理服务，因此机器／项目不运行时不会在72小时到点主动执行；过期现场在下一次上述入口立即回收。活跃／无法核验的目录继续保留并使清理失败，不能为了满足数字上限越过保护边界。

## 4. 历史目录处理原则

用户已明确允许直接删除历史测试。候选限定为系统Temp下一层真实目录，前缀和六位随机后缀能对应测试源码。清理的是整个历史用例目录，包含故障／负面输入／异常数据库等旧测试内容；不再根据其中的模拟配置字样逐份分类。

清单冻结具体目录名、归属和目录身份，执行前检查路径及目录是否被替换；不跟随目录链接，不处理其它应用的Temp内容。独立保存的正式材料目录和带 `report.json` 的旧结果目录保留；无法对应测试源码的调试目录单列。清理前确认没有仍在运行的测试，逐目录记录移除／保留／失败。磁盘净变化与文件逻辑大小分别计量。

## 5. 检查标准

覆盖：D盘及子进程隔离；成功清理；失败次数／时长／总大小边界；真实进程强制退出；活跃进程保护；Windows实际独占文件锁与重试；目录链接／越界／伪造标记；原有重启恢复及迁移回归。历史清理器另覆盖已核实候选、未知／正式／活跃目录、清单被修改和检查后变化的拒绝。

所有功能回归使用本地DSH、SQLite和模拟模型／平台；真实验收继续延期。本治理不降低既有546项断言，不把清理成功当作真实模型或QQ验收。

# R6f-1 原位历史适配器检查

日期：2026-10-26。新增 server-compat 的 existing-only 历史适配器，供后续夜间版本接管使用。它没有模型工具、网络、Git 初始化或后台任务入口；本步没有打开服务器历史库。

实际实现：固定 root/历史记录/history.sqlite，先只读校验路径、BigInt 物理身份、schema、必需表列、唯一约束、不可变记录触发器及完整性，再以 SQLite URI `mode=rw` 打开现存库。缺失库拒绝创建，缺失保护拒绝修复。程序侧新记录使用独立 host 来源命名空间及结构脱敏；旧 records/imports/watermark 和其它表行保持。

周期和版本按完整旧行 token 比较交换，保留未知字段及额外列；阶段、日志证据和提交事实不能跳序，已完成记录拒绝重写。传入的 Run/Git 引用只是持久事实，调用方仍必须核验真实执行；此库不替调用方证明记忆已整理、模型已写日志或 Git 已提交。

受管报告 `.runtime/test-reports/1f704242-1ddc-44f6-82f6-ee108507a62b.json`：10/10 通过。首项实际运行当前 Node/SQLite，证明字符串 URI 的 mode=rw 不会创建不存在的目标；其余覆盖原行/marker/脏文件保留、路径链接、错误 schema、错误触发器、同来源冲突、脱敏、两连接 CAS、版本阶段、终态与水位保护。使用虚构 SQLite 和合成日志，不冒充真实模型或服务器版本保存。

初轮组合报告 `b34e1d83-6368-4123-a41a-05b4bde2dfc7` 的本模块 4 通过/6 失败，原因是触发器 SQL 规范化后与未同样规范化的固定期望比较。修正为两者采用同一规范化；仍完整匹配指定触发器，新增把 new.body 偷换成 new.source 的拒绝检查。未放宽数据保护。

本实现只提供原位持久化边界；真实旧 schema/水位、唯一写入者、维护屏障、可见事件归档、日志会话、Git CAS、私有 SQLite 快照和更新守护仍按后续子步接线。独立说明见 `reviews/r6-existing-archive-implementation.md`。定向检查不替代发布全量；D 盘成功现场已回收，失败留存无清理阻断，用户原修改保留。

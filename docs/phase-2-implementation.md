# 第二阶段本机接入实现

分支：phase-2-local-qq。测试机器人1994142241、主人私聊756013063、唯一测试群1106067626。所有端点均为本机，服务器不参与。

## 本地组合

- 模型使用DSH已保存的deepseek-official / deepseek-flash / max。
- 主插件新增reasoningEffort，传入DSH AgentOptions；不会在QQ插件中直接调用模型API。
- scripts/local-host.mjs组合DSH服务并使用独立DSH_HOME、会话与数据库。
- 凭据通过DSH credentials-local服务引用本机现有version=1凭据文件，关闭热监听；不复制密钥，不调用写入接口。验收结束检查凭据文件是否改变。
- 原始模型会话保存在忽略目录中，审阅报告只提取最终回复、调用元数据、用量和稳定错误分类，不导出模型内部思考。
- 独立SnowLuma v2.1.1使用随附Node v24.22.1；QQ版本9.9.27.45758。
- 只在本机回环地址开放HTTP13000、WS13001、WebUI15099，令牌单独保存在忽略目录并设置本机账户ACL。
- 用户明确允许仅调整本次SnowLuma运行目录的完整性级别；未改变QQ、系统全局设置或服务器。

## QQ插件

`@dafeiyu/channel-qq`提供稳定渠道接口，内部用OneBot HTTP执行明确操作，以WebSocket接收事件。只接受回环地址，不接受带凭据或查询参数的URL。

启动/重连核验get_login_info和get_status；入站self_id必须匹配，私聊和群分别按允许名单筛选；每次发送前再核验登录账号。群只响应真实@或引用本会话中已发送的机器人消息。消息中的昵称不产生身份权限。

每个允许会话保存最多200条引用缓存，机器人回执另行保存。引用ID允许负数。缓存查找按会话隔离，找不到时标记未取得，不调用任意跨会话读取接口。不进行历史消息补取或旧聊天重放。

不支持的媒体明确标记为未读取，当前仅文字输入输出。输出超4000字时明确未发送，不自动拆分为可能部分成功的多条消息。分段消息交付属于后续实现。

已收到并成功提交核心的消息另存持久去重标识，连接重启不重复触发。一次发送遇到网络异常、未知回执或回执持久化失败都标记结果未知，不自动重发。平台发送失败响应也保守视为未知，不把所有接口错误都当成没有发送。

心跳缺失会断开并重连，记录可能存在事件缺口。没有向平台索取或承诺全部离线消息。关闭时合作式取消，并等待正在进行的交付结束后关闭本地存储。

## 接口演进

关联插件接口从v1更新为v2，增加ExtensionHandle.observe，向统一事件记录提交连接/忽略/不支持等事实而不唤醒模型。第一阶段入站消息字段未改变；所有本仓库扩展、测试和演示已同步更新。旧v1扩展会明确拒绝，而不是静默兼容。

现有SQLite与DSH会话格式未改变；新增QQ渠道存储是独立文件。observe仅允许该扩展拥有的渠道账号，记录带会话范围和插件版本。

## 验收入口

```powershell
npm.cmd test
npm.cmd run accept:model
npm.cmd run qq:mock
npm.cmd run qq:stop -- B
npm.cmd run qq:real
npm.cmd run qq:stop -- C
```

QQ入口需要已准备的独立SnowLuma和`.runtime/phase2/onebot.token`；软件发行包与令牌不入Git，不由项目脚本重新分发。B/C共享一个本地账号占用记录，防止同一测试账号被两个实例同时回复。

停止后留下stop.request，重新启动前须确认进程已停止，再显式移除该文件。不得用删除锁文件的方式强行启动第二个实例。

阶段B采用固定模拟回复；阶段C使用真实模型。二者使用不同会话和存储目录。具体通过情况以验收记录及本地报告为准，不能把模拟OneBot服务器测试当成真实QQ验收。

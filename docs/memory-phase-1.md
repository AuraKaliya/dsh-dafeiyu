# 记忆能力插件第一阶段：存储、版本与逻辑删除

日期：2026-10-23（北京时间）。项目版本0.4.0；新插件 `@dafeiyu/memory` 版本0.1.0；现有核心协议仍为v2，DSH仍固定0.2.1-rc.2。

本轮实现开发方案v1.3中用户指定的第一阶段存储闭环：显式记录、更正版本、逻辑删除、已删除查询、恢复、来源依赖与会话隔离。候选自动提炼、语义真实性分析、embedding、关系检索、工作记忆装配及压缩不在本次实现范围。

## 实际交付

记忆插件通过主插件注册8个工具，不建立新的模型循环，不默认加载到QQ实例。

| 工具 | 实际功能 |
|---|---|
| dafeiyu_memory_record | 创建有来源的当前会话记忆 |
| dafeiyu_memory_revise | 创建新内容版本，保留旧版本 |
| dafeiyu_memory_search | 查询当前有效、未删除且依据未变化的条目 |
| dafeiyu_memory_open | 正常读取；显式history模式可打开指定旧版本 |
| dafeiyu_memory_delete | 将条目及全部历史版本设为逻辑删除 |
| dafeiyu_memory_deleted_search | 专门查找已删除或受已删除依据影响的记录 |
| dafeiyu_memory_deleted_open | 打开已删除记录的指定版本，标记仅用于查找 |
| dafeiyu_memory_restore | 解除条目自身的删除状态，不回退内容 |

工具接口保持现有字符串参数约定。sourceRefs使用JSON字符串数组；版本和页大小字符串在边界转换并验证。不存在任意SQL、任意数据库路径、模型自选route或其他会话入口。

## 数据与版本

配置项：`agentId`、`dataDir`；数据库位于dataDir下的memory.sqlite。使用独立SQLite、WAL、FULL同步及外键。application_id与user_version检查拒绝其他应用或未知版本数据库，不重置已有文件。

| 数据表 | 职责 |
|---|---|
| memory_items | 所属智能体、会话、当前版本指针和删除状态 |
| memory_revisions | 不可改写的内容版本、类别、陈述类型、来源快照和内容哈希 |
| dependencies | 版本之间的记忆来源依赖 |
| memory_events | 只追加的记忆变更及操作原因 |
| outbox | 向统一事件库可靠补录的待办 |
| requests | 按智能体、会话与requestId隔离的幂等收据 |
| scope_generations | 使旧分页在会话记忆变更后失效 |

`revision`表示内容版本：记录从1开始，更正时递增。`version`表示条目状态版本：创建、更正、删除和恢复都递增。修改操作必须提供expectedVersion，不能把内容revision当作并发控制版本。

示例：创建得到revision=1/version=1；更正得到2/2；删除得到2/3；恢复得到2/4。恢复仍是第二版内容，不能重新覆盖为第一版。

记忆包含experience、knowledge、preference、procedure类别，以及observation、self_report、reported_claim、inference陈述类型。当前全部标记analysisStatus=not_analyzed；来源可访问和哈希匹配不等于主张已经得到语义验证。

本阶段内容有效性只有active与superseded，结合来源变化阻止旧派生认识进入正常使用。完整的invalid/expired状态、适用时间、候选流程及自动整理待后续阶段实现，不宣称开发方案中所有长期记忆字段已经齐备。

## 逻辑删除与恢复

删除范围固定为 `memory-item-and-revisions`，结果明确返回 `sourceArchivesUnchanged=true`。内容不物理删除，正常查询和history读取都不会返回被删除条目；专门入口可查看原内容及删除原因。

查找结果带 `useRestriction=deleted_lookup_only`，查询不修改删除状态、不新增内容版本、不自动恢复。恢复只解除该条目自身的删除标记，并按当前来源状态判断是否能重新使用；结果visibleNow=false表示当前仍有不可用依据等限制。

删除记忆不等同于删除其DSH原文档案、历史工具回显或已经进入模型的聊天上下文。这些历史材料没有被物理清除或统一回收；原文级删除覆盖、当前上下文替换是后续独立接入工作，不能把本阶段描述为所有历史渠道均已遗忘。

版本读取通过id和revision精确定位，旧版本显示superseded。恢复请求不接受“把某个旧revision设为当前”的参数；明确更正需要独立创建新版本。

## 来源、依赖与范围

每个模型可调用的服务操作先通过核心的scopeFor校验当前活跃ActionContext。复制对象、过期上下文、注销插件或被取消的操作不能取得权限。模型不能在参数中替换智能体、账号、群或会话。直接MemoryStore和数据库访问仍属于可信宿主能力，接口隔离不是操作系统沙箱。

数据库查询先限定agentId与route。记忆来源可以是已授权时间线引用，也可以是同一会话当前有效的记忆版本引用。写入前核对来源可访问性和完整导出内容的哈希；异步读取后重新验证核心上下文，提交事务时再检查记忆依赖版本，防止迟到结果覆盖新依据。

引用格式：`dafeiyu:memory:<UUID>:<revision>`。时间线引用沿用现有格式。哈希标识来源快照，但不复制整套DSH会话；创建后若原始档案不可读，不伪造补回档案，需通过来源回查确认实际可用性。

父记忆被删除时，所有依赖它的后代版本退出正常和history读取，可在专门删除查询中看到受影响记录；条目自身是否删除与effectivelyDeleted分别展示。父记忆更正后，依赖旧版本的记录退出正常检索，仍可显式历史查阅。恢复未变化的父版本时，重新校验依赖后可恢复可见性；内容版本已经变化则不会自动认定旧派生认识仍有效。

返回值的basisStatus标明current／changed／deleted；依据变化的历史内容带historical_evidence_only，避免因条目本身仍是最新版本而误认为其依据仍然有效。

独立的来源依赖仅用于有效性判断，不是语义关系图，也没有推断实体关联。权限粒度目前为会话；没有新增会话内按个人划分的修改权限或主人跨群查看能力。

## 派生结果回流防护

时间线导出新增memoryUse标记。助手回答、合成上下文、工具错误，以及包含结构化历史／记忆导出标记的工具回显，被标记为derived-only，不能被该插件直接当作新的主依据。

已删除记忆引用不能用于创建新记忆；已删除查询的结构化工具回显也不能绕过限制。普通真实工具结果仍可作为候选依据。该规则要求回到原始证据或有效记忆引用，避免重复转述被计作独立证据。

这不是通用自然语言溯源器，不能识别任意重述、用户重新提交的文本或所有第三方工具的隐藏来源。本阶段没有自动提炼流程，也没有声称彻底阻止所有语义形式的重新记忆。

## 一致性、幂等与恢复

内容版本、当前状态、来源依赖、幂等收据、变更事件和outbox在一个记忆数据库事务中提交。写入事件失败时全部回滚。

统一事件库与记忆库是两个数据库，不假定跨库原子提交。Journal新增可信宿主接口appendOnce，按稳定事件UUID去重并检查重复事件内容。发布成功但确认前中断时，重启补录不会重复生成事件。

发布暂时失败不会谎报记忆回滚；写入结果返回auditPending=true。插件启动、操作前和写入后尝试补录；没有新增后台定时任务。若之后没有调用或重启，待办会留存等待下次补录。

每次写入要求requestId。相同键和规范化内容重试不重复写入，不同内容复用同一键返回idempotency_conflict。收据仅含标识与版本，不包含记忆全文，因此重试旧请求不会直接返回后来已删除的文本。收据记录的是原操作结果；进一步修改前仍需重新读取当前version。

重启只打开数据库和补录元数据，不运行历史模型、工具或QQ发送。SQL触发器禁止物理删除条目、改写内容版本、依赖或历史变更事件。

## 查询、分页与资源边界

本阶段查询为已脱敏内容的字面、不区分大小写匹配，不是聊天全文搜索、向量检索或关联检索。默认只列当前版本；旧版本通过显式history读取。

分页上限50条，内容每条最多8000字符；游标绑定智能体、会话、模式、关键词、页大小和会话记忆世代。同一会话发生变更后旧游标返回stale_cursor；其他会话变更或只读审计不使游标失效。读取仍复核当前状态，不能利用旧游标取回删除内容。

没有加载embedding模型或分析进程；不改变既有2GB预算。当前来源递归校验与字面扫描尚未经过大规模性能验证，不能代替M2索引和组合内存验收。

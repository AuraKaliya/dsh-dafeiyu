# M5C第一部分：精细来源记录与局部失效

日期：2026-10-24。项目0.10.0；contracts/core/memory/timeline为0.7.0。仅本机虚构样本，无服务器或真实QQ操作。完整后续设计见[M5C方案](memory-phase-5c-plan.md)。

本页记录C1交付时的行为。0.11.0的新摘要采用分片、局部视图和简短引用，见[C2验收](memory-phase-5c2.md)；原C1证明包装开销保留为历史对照。

## 已实现

启用记忆插件的compaction配置后，主插件在DSH真正请求模型之前记录`plugin:dafeiyu/request-sources`，保存实际可见的历史、选中上下文条目、来源与版本。回答生成后记录`plugin:dafeiyu/source-record`，关联原事件、原文哈希、父消息及请求清单。

用户原始消息只继承自己的来源，不继承这轮全部历史。助手回答继承实际看到的所有受管输入。工具结果继承调用来源，以及已适配工具返回的记忆/档案依赖。模型自行列出的引用不参与缩小依赖。仅给核心实际提交的输入消息建立来源身份，外部额外插入的用户消息不冒充该输入。

新增摘要使用schemaVersion 2，保存所选原文的依赖并集；提交与恢复时核对原文哈希、依赖并集及成功检查点。旧schemaVersion 1继续按保守代号校验。当前仍不合并已有摘要，不自动把一句混合回答拆成多个事实片段。

## 局部失效行为

源版本变化后，源到消息的反向映射定位受影响节点。退出的是相关消息或摘要，而不是整段会话；无关消息的id、正文及现有摘要保持不变。DSH原生和其他插件区域保留。工具调用消息及配对结果是结构单元，必要时一同退出，保留追加档案且不重放工具。

退出事实写入统一时间线`context.sources.retired`，带原DSH事件引用，不含正文。旧派生回答/工具结果的正常来源回查也验证依赖，防止绕过活动视图的退出。显式原文与已删除内容回查仍使用既有受限能力。

会话状态计数和工作区版本现在用于发现变化、刷新验证缓存，不直接判定全部新历史失效。工作条目版本与容器版本分开：改A不改B条目的版本；取消检索选择不撤销仍合法的历史依据。

## 删除恢复与来源身份

来源由agent、会话、消息身份/引用和哈希共同确定。两条独立消息即使文字、时间、发言者相同，也不混为一个来源；多个引用指向同一消息时共用来源状态。来源状态标记记录与该来源有关的记忆变更，删除后再恢复也不会退回旧标记。

祖先失效沿派生方向传播：C同时依赖A和独立B时，A失效不能通过C反向污染B的原文。直接共享同一条不可拆分原文的记录仍可能保守共同失效，消息内部的语义分片留给C2。正常记忆读取/检索也携带原文来源状态证明，不能经另一个记忆条目绕回已受抑制的原文。

记忆读取返回当时的祖先revision/version/hash。新写入的证据选择、工作条目和反馈档案保存祖先版本与原文来源状态标记。父记忆删除后恢复、或同源记忆状态变化后恢复，旧选择与反馈不会因子记忆自身版本未变而自动重新生效。

启用精细压缩时，旧选择/反馈若缺少这些证明，不按当前状态补写过去：工作条目暂不装配，反馈仅可按历史模式查看；显式更新选择可生成新的合法记录。未配置compaction的旧入口保留兼容行为，新写入仍保存来源证明。

## 实现边界

- 基本失效单元是原始消息、整条回答/工具对和单个摘要。一个回答看过A、B，就保守依赖两者；不声称能准确判断每个句子的语义因果。
- 同一个原始消息里不可分的多项内容仍可能共同失效；本轮区分不同消息身份，没有实现消息内部语义分片。
- 已适配的记忆读取/检索和结构化反馈采用明确依赖；其他工具保留局部的旧式状态代号依赖，不伪装为精细来源。它们及其后续派生回答可能较保守地退出，独立原始消息不随之清空。
- M5B的旧摘要/轮次仍可按其已有证明处理；更早没有归属清单的历史遇到无法核验的输入会停止准入，需要单独迁移核验，不猜测来源。
- 撤下已知派生链不等于语义遗忘。用户新提供的独立信息不会仅因词句相似而被自动删除。

## 存储、性能与恢复

来源记录与请求清单共用DSH日志，使用正式插件记录接口；无新增事实数据库。会话内反向映射重建自日志，删除/版本检查访问记忆与反馈权威存储。验证缓存绑定会话、当前轮次、来源状态、存储generation和提供者实例；区域条目仍实时检查。

单条依赖清单最多4096项，验证缓存最多8192项；超过清单容量停止处理，不截断依赖。源树哈希不等于索引授权。原文保留、重启恢复和不完整检查点规则沿用M5B；审计不是重放模型或工具的指令。

本轮不新增embedding模型、独立分析进程或图数据库。长会话内存和持久SQLite反向投影属于后续规模验证，本机短样本不构成2GB部署容量保证。

C1检查点仍携带完整依赖元数据，增加了可验证来源，也增加了模型输入开销。同一组M5B虚构样本在当前代码下，40,860字节的选区对应11,004字节的摘要检查点，旧实现记录为3,804字节；这不是摘要保真率或实际计费token指标。C2需将完整证明与模型可见的简短引用分离，并继续验证提交、回查与恢复的一致性。

DSH保留未知插件记录不代表旧版大肥鱼插件能解释新记录。本轮没有验证0.6.0二进制读取0.10.0生成的数据；代码版本回退不能替代数据兼容迁移。

## 验收

新增20项专项测试，覆盖独立B历史保留、混合输入完整依赖、选择取消、条目版本、删除/恢复、祖先恢复、无关并发变更、重启与来源回查、v2摘要局部失效、会话隔离、相同内容不同消息、同源不同引用、旧版处理、读取旁路及依赖反向误伤。

`npm test`全量231项通过，其中新增20项专项测试。`npm run demo:provenance`验证3个独立检查点保持id和正文，4个相关检查点退出，恢复后不重新激活；结果见[memory-phase-5c1-results.json](memory-phase-5c1-results.json)。`demo:compaction`兼容演示亦通过。使用真实DSH装配、持久化和替换机制，模型输出由脚本控制；不代表真实模型的摘要质量或多代合并已经验收。

## 装配和兼容

启用执行器要求 Memory 与来源跟踪、相同模型路由和 QQ 账号／主人绑定、独立 server-executor 资源以及精确动作授权；普通聊天 policy 不能执行外部写入，自主任务还要求 standing authority。拒绝网络程序路径与放在可变数据目录内的授权文件。JSON 不能指定替代 runner、端口函数或生产／模拟身份。

服务按既有 Host 次序恢复、激活、排空和关闭；未知执行会降低健康状态并阻止重派，不伪造成功。停止接收新任务时，已有任务继续核验来源并完成回执；超时取消保留实际未知副作用。

executor schema/status 字段均为可选：原配置未启用时不新增数据库或 manifest 字段，不改变原 policy 摘要。显式增加 disabled 插件会正常改变完整配置摘要；移除这一配置项后恢复原摘要。不能把两份不同配置说成同一候选。

## 数据启用与备份

首次空 profile 仅在显式 init 时创建 executor.sqlite v1；既有 profile 新增执行器必须经过受管备份、迁移、验证，再绑定 manifest。普通 inspect 只读 schema、身份、不可变触发器与归档关联，不构造服务、不执行恢复、不派发模型。

迁移保留所有任务、unknown、预算关联及不可变回执，包含 `results/<job UUID>.json` 的 hash／大小与无引用归档；不能把孤立归档改写成成功结果。目录外文件、链接、错误身份、未知 schema、丢失或变化的归档均拒绝。读取过程使用 BigInt 物理文件身份，避免 Windows inode 超过 Number 精度；备份验证同时核对 SQLite 逻辑行和归档字节。已有但关闭的执行器记录照常保留、备份，不因关闭插件删除。

# 大肥鱼 · dsh-dafeiyu

基于 DeepSeek Harness 的可成长智能体。通过交流与探索积累经历，由记忆与成长统一管理阶段人格、偏好和关系；核心使用这些状态，独立判断并执行明确任务。

## 功能

| 模块 | 功能 |
|---|---|
| 核心 | 对话、持续任务、异议与进度、来源核验、压缩后的接续 |
| 记忆与成长 | 选择性记忆、工作状态、经历关联、经验更新、人格候选/试行/采用 |
| QQ | OneBot收发、自然称呼、群列表同步与群助手过滤、浏览观察、任务、长消息分段与媒体接口 |
| B站 | 搜索、视频信息、评论、字幕、弹幕与视频媒体；可选独立主人私信 |
| 媒体 | 抽帧、视觉、语音识别、声音事件、文档和可选语音输出，需要配置相应工具/模型 |
| 自主活动 | 按自身计划定时或条件唤醒、调整频率、休息与整理记忆 |

QQ和B站各是一个平台插件，内部渠道与能力接口独立。B站公开评论、弹幕发布未开放。管理员执行组件保留在源码中，普通安装不会授予系统操作权限。

QQ群助手状态由本插件自己的适配层通过原版SnowLuma读取，与检查群列表共用一次刷新。收进群助手后停止该群自动处理；移出后只接收新消息，保留原会话和记忆。`joinedGroups:false`只开放配置群与实际加入集合的交集，仍会核验群助手状态；`true`开放其余符合条件的已加入群。协议端缺少读取能力时群处理显示不可用，主人私聊继续。旧QQ库需先按Host提示备份升级。

## 安装与启动

当前完整功能以 **Windows** 为目标，需要 Node.js **24.13+（24系列）**、兼容的DSH **0.2.1-rc.2**、DeepSeek API模型和本机OneBot服务。此仓库附带预编译运行代码，安装不需要TypeScript编译，也不需要其它私人仓库。

1. 在DSH插件管理中从本GitHub仓库安装组合包；也可下载仓库后使用插件管理的本地目录安装。安装界面中的来源与版本应指向本仓库。
2. 把 `examples/dafeiyu.config.json` 复制到**插件目录以外**的本机配置目录。填写模型名、DSH凭据文件、机器人QQ、主人QQ、OneBot地址和令牌文件。账号字段没有默认值。
3. 当前版本尚未提供图形初始化表单。退出DSH后，在当前profile的 `cordis.patch.yml` 中配置 `settingsFile`，具体写法见[配置说明](docs/configuration.md#接到dsh桌面)。`nodePath` 默认为PATH中的 `node`；找不到Node时填写其绝对路径。
4. 先启动本机OneBot服务并登录配置的机器人QQ，再打开DSH并启用插件。连接成功后自动初始化并启动；首次不会主动给任何预设QQ发消息。停用插件会先结束当前工作并关闭独立运行进程。插件管理页的“运行中”仅表示插件入口已加载，实际连接以 `status` 输出为准。

也可以独立运行：

```sh
npm install --omit=dev --ignore-scripts
node bin/dafeiyu.mjs check --settings /absolute/path/dafeiyu.config.json
node bin/dafeiyu.mjs start --settings /absolute/path/dafeiyu.config.json
```

Windows也可使用上述命令，路径换成本机路径。`check`检查必填项及凭据文件是否存在，**不等于网络连接验收**；`start`实际核验QQ身份和连接。`status`读取运行状态。模型凭据使用DSH的版本1凭据文件与 `DEEPSEEK_API_KEY` 条目；不要把API密钥写进本配置或提交到Git。

OneBot令牌文件只存令牌文本，至少32字符；HTTP与WebSocket地址须指向本机回环地址。普通安装需要机器人与主人使用不同账号。群聊默认关闭；填写 `groupIds` 指定群，或主动设置 `joinedGroups: true` 接入实际加入的群。`naturalNames` 是触发称呼，可按记忆中的昵称配置。

## 可选B站与媒体

基础配置可直接进行QQ文字交流、任务和成长。视频画面/音频理解还需要在 `media` 中配置 FFmpeg、FFprobe、视觉模型及本机音频模型；这些资源不随插件打包。配置结构见 [配置说明](docs/configuration.md)。未配置的处理器会明确报告缺口，不把字幕当成音画理解。

B站公开能力使用 `bilibili.capabilities`。私信另需 `bilibili.channel.accountUid`、`ownerUid` 和 `sessionFile`；只接受这两个账号之间的私信，不允许模型指定其它收件人。登录态由安装者在本机准备，插件不提供扫码登录界面、不复制其它机器登录态。启用初次接收边界前的历史消息不会回放。

## 数据与隐私

- 所有实例数据放在主动配置的 `dataDir`。首次自动生成唯一身份；升级和重启使用原库，不重置成长。
- 本地和服务器分别使用自己的配置、QQ登录和数据目录。两者可以采用不同昵称，各自保存记忆；默认没有跨机器同步。
- 主人账号是权限配置，昵称与关系状态不能授予管理员身份。改变账号绑定应使用新数据目录，不能静默接管旧实例。
- 聊天、任务日志和长期记忆采用现有持久保存策略；记忆“删除”主要是可恢复的逻辑删除，不能视为所有磁盘副本已擦除。媒体缓存按容量回收。详见 [架构与数据](docs/architecture.md)。
- 仓库和安装包不含私人聊天、验收原文、登录态、API密钥、主人QQ或B站账号默认值。

## 开发与验证

`runtime/` 是随包分发的预编译代码；`source/` 是完整运行模块的TypeScript源码和公开的本机检查样例。进入 `source/` 后 `npm ci --ignore-scripts`、`npm run build`，运行 `npm test` 做公开样例检查。

[本轮验证](docs/validation.md)覆盖167个文件、1300项本机检查。当前发布区分真实本机组件与模拟模型/平台；联网模型与真实QQ/B站效果仍需使用安装者主动配置的账号验收。仓库不宣称162项真实模型验收全部通过。

# 当前接口与记忆驱动架构

本文件依据本轮源代码整理。自有模块统一为 0.28.7（API_VERSION = 7），扩展协议由 contracts 的 API_VERSION 唯一定义。

## 单一当前接口

- 扩展仅通过 registerExtension 和当前 Extension / ActionCapability / ExecutionContext 注册及调用。动作明确声明 conversation、task 或 any 范围。
- Host 公共插件名称为 memory-growth、qq、bilibili 等当前名称。一个 B站声明包含 capabilities 和 channel，内部服务由装配层建立。
- 上下文统一组装，来源追踪始终启用。新安装创建完整当前结构；已有受支持的数据库由显式迁移器在停机备份后升级。运行构造器不隐式迁移，不通过忽略版本或身份检查兼容旧库。
- 无法通过当前校验的数据不能进入执行。程序不识别或转换所谓“旧请求”。

## 执行与交付

消息任务通过已持久操作及实际子任务核对受理后，当前会话只作简短确认，工具集合收窄至空；下一条消息重新取得对应工具。确认不代表任务完成或结果送达。若模型在确认时输出内部工具控制标记，保留原始执行记录，并向渠道投影准确的受理通知；结果由后台任务单独交付。

QQ 使用 `qq_messages` 编排一到十二个文字/媒体位置项，每条文字通常一到两句话。显式条目是消息边界，800 字符传输上限可能进一步分条；旧的普通正文采用按句兼容分条。实际条数来自渠道持久化发送账本，`qq-delivery-counts` 最多提供当前会话最近六次的 total、confirmed、pending、sending、unknown 和回执。计划条数不代表已发条数，已发也不代表已读。

认证主人私聊可查询当前获准群；群之间仍隔离，退群或撤权会使旧来源失效。`qq_groups` 分开返回可读范围、`replyFromCurrentConversation` 和 `replyViaAuthorizedGroupPatrol`；这些是程序授权范围，`platformSendPermission: not-probed` 表示未探测平台禁言状态。不能把私聊不能直接向群发言解释成机器人在群内没有发送权限。`qq_browse` 中 `mentionedBot` 来自实际收到或补拉的提及结构；旧记录缺少该字段时保持未知。

任务与自主分享使用不同的结果来源锚点。自主分享绑定真实活动结果和主人目标，不伪造入站消息；沿用结果核验、不可变正文与 QQ 分段账本。每个运行保留一个结果目标，群巡视使用该群的真实消息会话，不复制私人探索结果到多个群。

需要独立重写的结果正文逐段核验；程序要求覆盖全部段落，事实段引用实际来源ID，再据每段判断决定是否允许发送。纯粹说明材料不足、不作外部结论的scope-limited段可无引用；个人意见或意向也不等于已执行事实。一个整体“通过”字段不能替代段落检查，混入外部断言仍须核对。最多三稿沿用同一证据，反馈带原句并保留历史问题；不因表达修订重做业务。模型推断、旧聊天回答和执行器自述均不自动成为外部事实；接收与缓存条件不能与回复触发条件混淆。

活动计划创建和修改返回已保存版本的周期、时区、静默区间和回复方式，最终汇报沿用这些程序回执。认证主人可在新的私聊任务中调整已有计划；更新同时绑定新指令来源、计划版本及执行代次，不能沿用旧代次继续发送。普通群成员与非主人仍只能操作自身获准任务的计划。

新回执中的activationPolicy说明其证据只覆盖配置保存；需要等来源任务结束或让出，并在前台空闲等条件满足时调度。仅配置目标应在保存后结束，不等待受自身阻塞的首次执行。状态查询的dispatch分别说明来源状态、是否等待当前任务及前台是否忙碌；不把这些信息合并为笼统的“已运行”。旧历史回执缺少该附加字段时保持原样，不补造执行证明。

认证主人沿用同一任务修订群巡视频率时，仍启用且basis为空的原计划可以保留ID，通过当前意图重新绑定授权；旧意图锚点保持失效，当前身份与可访问资源仍由核心校验。其它来源失效不得按此路径自动继承，应在原ID上明确当前目标和来源，不能以取消重建冒充原计划更新。

模型用量在实例入口记录请求开始和结算，覆盖对话、任务、媒体、结果表达、核验及恢复。runtime v5 增加独立请求账本，允许运行结束后的真实请求结算，不开放其它执行输入的事后修改。未结束请求、未知用量、未归属请求分别显示；旧版本漏记的数据不补造。非缓存输入、缓存读/写和输出按 SDK 不重叠语义求和。

新确认的 QQ 回复保存确认时间，近期历史可看见自己的文字回复；任务/媒体占位仍不直接暴露受限正文。旧未知时间只有取得真实平台历史时间后才可补齐。纯文字、无触发的群观察可成批提交缓存与接收记录，其余消息按原顺序处理；持久化强度不降低。

`dsh_tool_list` 默认分页返回名称和简短用途；`kind` 选择 tools/skills，`query` 筛选，`name` 查询单项详情。按响应 `next` 继续，携带 `catalogVersion` 防止跨版本拼接。详情先整体脱敏再按字符分页；声明可读、实际执行授权和外部依赖健康分别判断。通用工具执行仍需原有任务权限，B站阅读阶段不引入通用执行工具。

DSH结果中小段正文直接展开；较大子节点由 `unread/read/next` 提供续读入口。字段列完不等于正文读完，命令工具返回也不等于命令检查成功，需结合退出状态和实际内容判断。消息及媒体的解析复用只针对未变化的本地事实，来源权限、删除和外部数据库变化仍逐次核对。

Core 负责身份、权限和模块绑定；ConversationCoordinator 负责会话调度、消息处理、恢复与发送；ExecutionCoordinator 负责任务运行和授权。DSH 负责实际模型循环、会话及工具调用。

普通任务的流程是：受理与授权 → 组装当前记忆及资料 → 主 Agent 调用工具、判断结果 → 必要时使用 dafeiyu_task_outcome 等待 → 保存主 Agent 的最终答复 → 检查来源与发送权限 → 渠道写入及回执。dafeiyu_task_review 仅返回复核建议，不决定完成状态，也不写入记忆。

普通可交付结果直接使用主 Agent 已保存的回答。包含其它会话、私有执行器数据或其它受限资料时，由目标范围的材料重新组织表达并核验。发送仍保留逐段检查、写入时限、确定未发送与效果未知的区分；未知结果不会被自动重发。

核验只读请求遇到短暂模型传输或限流失败时，在同一个核验时限内最多重试两次，沿用原候选和证据并重新检查来源，尊重服务端等待时间。账号错误、明确的不忠实结论和取消不重试；失败诊断保留错误码、HTTP状态及实际尝试次数，不包含服务端原始错误正文。

会话、任务和压缩都采用当前格式的崩溃恢复。DSH 的会话恢复边界与未完成压缩检查会阻止未提交摘要变成证据；这不是数据格式迁移。

## 记忆与成长

Memory 保存初始记忆、经历、实际操作报告、Agent 主动留下的反思和自我认识修订。GrowthService 是记忆能力的一部分；Core 的 PersonaRuntime 只投影记忆，不维护第二份人格状态。

- dafeiyu_memory_pending / experience 提供本范围的经历索引和分页读取。
- dafeiyu_memory_reflect 保存自己的看法、不确定性和后续打算，可绑定实际操作记录。
- dafeiyu_memory_self_status / update / withdraw 管理明确的自我认识。更新必须依据已保存的反思；全局可读部分经过自我信息与隐私检查，原始依据仍留在所属范围。
- 初始模板只在记忆初始化时导入。之后修改或移除模板不会替换已经保存的初始记忆。
- 经历索引和读取也检查消息来源撤回；已撤回内容不能经自动提醒重新进入上下文。经历与反思是有时间、范围和来源的材料，不被当成额外指令或未经核验的世界事实。

一轮完成或失败只保存实际事件和待反思状态，不自动启动另一轮人格评价或整理。主 Agent 在合适时机主动记录。可选的经历整理由明确工具请求发起；Activity 可以等待当前运行结束后交给 DSH 执行，不从任务完成事件自动制造整理任务。

## 模块边界

Journal、Runtime、Memory、QQ、B站、媒体、Activity、执行器分别提供自己的存储检查与状态接口。Host 路由这些接口，协调生命周期和资源租约。执行器的结果归档完整性检查由执行器模块拥有。DSH 原生查询库的检查属于 Host 的 DSH 接入边界。

能力模块教 Agent 当前工具如何使用、返回什么事实和限制；主 Agent 决定如何行动以及如何理解经历。人格改变的持久来源始终是记忆。

## 本地验证

使用 npm run build 和 npm test。测试运行器按当前源码编译所有子进程夹具，清理已不存在源码的编译产物，并在既有临时空间预算内分批执行。公开包检查包含隔离安装、冷启动、重启、私有工作区隔离与隐私扫描。

离线回归、真实模型、真实平台和连续运行分别验收。是否执行外发、服务器部署及连续运行时长，以当前用户授权和对应验收记录为准；历史记录不代表当前版本已经通过。

## 管理中心与活动轮次

DSH 设置页通过管理协议组合模块自己的界面与操作。管理调用只接受 DSH 已认证的主人连接；不会由模型请求中的角色字段授予管理权限。配置与状态分离，模块按职责提供 UI 描述和管理端口。当前管理行为及验证范围见 [管理中心](management-center.md)。

恢复管理：activity 的 recovery.probe 接受 requestId、expectedGeneration，返回持久探测回执；media 的 recovery.arm 另需 key，返回一次短期读取许可。活动库与媒体库为 v4。许可、实际验证和业务接续是不同状态；只有当前代次的成功能解除对应暂停。恢复探测按 maintenance/recovery 计量，独立探测没有业务 Run，不伪造绑定。

B站管理 `verify.read` 的可选 `transport` 默认 `http`；选择 `browser` 时使用已登录网页身份及真实读取验证，视频必须取得一帧。一次许可绑定 UID、端点和当前实例，记录属于管理操作，不伪造业务 Task/Run。旧回调不能清除更新的失败，其它暂停范围保持独立；浏览器验证不会更新 HTTP 登录结论。该参数和结果保存在现有 JSON 目标/结果字段中，B站存储仍为 v6。

动作可提供程序侧 `readiness()`，返回临时可用性与原因。任务每步装配模型请求时据此收窄当前工具；它与生命周期及来源授权分别判断，不让暂停反向作废已读证据。DSH 的 in-history 模型路由会保留历史声明用于解释旧调用，并用正式的工具移除/增加记录表示当前集合；不能把历史声明仍在请求中误判为暂停没有生效。

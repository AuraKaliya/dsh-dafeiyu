# 当前接口与记忆驱动架构

本文件依据本轮源代码整理。自有模块统一为 0.24.0，扩展协议由 contracts 的 API_VERSION 唯一定义。

## 单一当前接口

- 扩展仅通过 registerExtension 和当前 Extension / ActionCapability / ExecutionContext 注册及调用。动作明确声明 conversation、task 或 any 范围。
- Host 公共插件名称为 memory-growth、qq、bilibili 等当前名称。一个 B站声明包含 capabilities 和 channel，内部服务由装配层建立。
- 上下文统一组装，来源追踪始终启用。持久数据仅有完整当前结构的创建和校验，不进行版本迁移、别名转换或旧格式读取。
- 无法通过当前校验的数据不能进入执行。程序不识别或转换所谓“旧请求”。

## 执行与交付

Core 负责身份、权限和模块绑定；ConversationCoordinator 负责会话调度、消息处理、恢复与发送；ExecutionCoordinator 负责任务运行和授权。DSH 负责实际模型循环、会话及工具调用。

普通任务的流程是：受理与授权 → 组装当前记忆及资料 → 主 Agent 调用工具、判断结果 → 必要时使用 dafeiyu_task_outcome 等待 → 保存主 Agent 的最终答复 → 检查来源与发送权限 → 渠道写入及回执。dafeiyu_task_review 仅返回复核建议，不决定完成状态，也不写入记忆。

普通可交付结果直接使用主 Agent 已保存的回答。包含其它会话、私有执行器数据或其它受限资料时，由目标范围的材料重新组织表达并核验。发送仍保留逐段检查、写入时限、确定未发送与效果未知的区分；未知结果不会被自动重发。

会话、任务和压缩都采用当前格式的崩溃恢复。DSH 的会话恢复边界与未完成压缩检查会阻止未提交摘要变成证据；这不是数据格式迁移。

## 记忆与成长

Memory 保存初始记忆、经历、实际操作报告、Agent 主动留下的反思和自我认识修订。GrowthService 是记忆能力的一部分；Core 的 PersonaRuntime 只投影记忆，不维护第二份人格状态。

- dafeiyu_memory_pending / experience 提供本范围的经历索引和分页读取。
- dafeiyu_memory_reflect 保存自己的看法、不确定性和后续打算，可绑定实际操作记录。
- dafeiyu_memory_self_status / update / withdraw 管理明确的自我认识。更新必须依据已保存的反思；全局可读部分经过自我信息与隐私检查，原始依据仍留在所属范围。
- 初始模板只在记忆初始化时导入。之后修改或移除模板不会替换已经保存的初始记忆。
- 经历索引和读取也检查消息来源撤回；已撤回内容不能经自动提醒重新进入上下文。经历与反思是有时间、范围和来源的材料，不被当成额外指令或未经核验的世界事实。

一轮完成或失败只保存实际事件和待反思状态，不自动启动另一轮人格评价或整理。主 Agent 在合适时机主动记录。可选的经历整理由明确工具请求发起；Activity 可以等待当前运行结束后交给 DSH 执行，不从任务完成事件自动制造整理任务。

## 模块边界

Journal、Runtime、Memory、QQ、B站、媒体、Activity、执行器分别提供自己的存储检查与状态接口。Host 路由这些接口，协调生命周期和资源租约。执行器的结果归档完整性检查由执行器模块拥有。DSH 原生查询库的检查属于 Host 的 DSH 接入边界。

能力模块教 Agent 当前工具如何使用、返回什么事实和限制；主 Agent 决定如何行动以及如何理解经历。人格改变的持久来源始终是记忆。

## 本地验证

使用 npm run build 和 npm test。测试运行器按当前源码编译所有子进程夹具，清理已不存在源码的编译产物，并在既有临时空间预算内分批执行。公开包检查包含隔离安装、冷启动、重启、私有工作区隔离与隐私扫描。

本轮仅本地开发与验证；不包含服务器部署、真实平台外发或付费模型语义验收。最终验证结果与提交见 源码仓库的最终检查记录。

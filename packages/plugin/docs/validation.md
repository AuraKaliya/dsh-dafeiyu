# 验证范围

验收按当前源码和实际生成包分别执行，不累加旧版本或重复复测的测试数量。

| 层次 | 内容 | 能证明什么 |
|---|---|---|
| 类型与程序回归 | 生命周期、协议、存储、登录缓存、诊断、读取、来源和交付 | 固定输入及故障条件下的程序行为 |
| 独立发布包 | 自有依赖安装、CLI 检查、空数据初始化、身份稳定、启动及重启 | 不依赖开发工作区完成安装 |
| DSH 装配 | 实际 profile 解析、管理调用、冷启动、重复启动及进程清理 | 当前包在被验收 DSH 中运行 |
| 真实平台 | 真实账号、模型、QQ/B站及媒体后端的明确样本 | 该时间和环境下实际通过的能力 |

完整回归使用 npm test；短冒烟使用 npm run test:smoke。独立安装与模型/平台样本另行运行并保存可复核记录。慢盘或隔离目录可设置 DAFEIYU_TEST_CONCURRENCY=1 串行运行，以排除多个 SQLite/SDK 测试争用；不放宽每项功能的取消和超时边界。

最终报告验收包含真实失败正文与完整证据包的回放。核验器须拒绝把缓存为空解释为“从未收到”、把回复触发条件解释为缓存条件，并接受保留观察范围的正确版本。漏段、重复段、未知证据ID和来源分类被提升均需程序回归；模型返回合法结构不能单独证明其事实判断正确。

也要检查误拒：没有独立材料时，正确声明无法确认应当通过，不能循环要求一份缺失证据来证明“不知道”。对照中加入夹带确定性断言的版本，确保合理限制不变成免检通道；修订流程应验证多稿只复用已读证据、未通过正文不发送。

计划验收区分配置完成和实际执行。测试配置任务仍运行时，回执已保存、来源仍pending、后台尚未执行；设置任务结束后再验证巡视，不能在设置任务内等待它自己释放的调度条件。真实模型短样本先验证不会自等待，再纳入完整两小时流程。

计划修改还必须覆盖新任务与原任务修订两种承接方式；后者要核对意图代次变化、原计划ID保持、原授权失效与新授权有效。完整驱动在修改汇报后立即读回计划，验证同ID、版本、频率、静默区间和近期调度时间，失败即保存证据并停止本轮，不把“已汇报”当成“要求已满足”。

B站真实验收先登录 UID，再视频、搜索、评论和字幕样本。平台仍受限时保留错误与暂停，不宣称风控解除。网页可见、字幕可读、画面采样、视觉理解及音轨处理分别记录覆盖范围。

安装检查必须核对实际依赖与加载目录；静态 ready 不等于在线。最终报告记录当前测试运行 ID、版本/修订、库版本、备份、进程就绪回执和未完成的外部条件。历史报告不会作为本版重新执行的证明。

恢复验收必须走到结果交付：已有资料和画面 → 模型或媒体故障 → 多次调度保持暂停 → 验证恢复或许可一次实际读取 → 同一 Task 接续 → 仅补缺口 → 主人结果送达 → 重启不重发。分别覆盖新旧代次竞态、单飞、缓存不能证明依赖恢复、未知写入不重试、取消和迁移。脚本模型及模拟平台用于可重复故障注入，真实模型/B站/DSH和两小时墙钟观察另行记录，不能混算。

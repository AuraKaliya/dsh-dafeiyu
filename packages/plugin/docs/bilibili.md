# B站登录与读取

开启公开能力需 `bilibili.capabilities: true`，并按配置校验准备 `media`。支持关键词搜索、视频资料、评论、字幕、弹幕和批量帧；不包含发表评论或发布弹幕。

## 本地 Cookie

配置中的 `bilibili.session` 包含 `file` 与 `expectedUid`。文件位于发布包以外，格式为 JSON 对象：必填 `uid`、`SESSDATA`；可选 `buvid3`、`bili_jct`。UID 为数字字符串，须与服务端实际登录账号一致。Cookie 不通过聊天提交，不进入模型上下文或管理返回。

文件使用 UTF-8 无 BOM。只有提供方需要的允许字段进入 API Cookie 头；字幕、媒体 CDN 和重定向目标不携带这些凭据。浏览器登录态与 HTTP 文件是不同的接入方式；不会在安装时自动读取任意浏览器或其它账号。

配置 HTTP、浏览器及私信时统一预期 UID。路径或 UID 变更停止实例后应用；同 UID 的 Cookie 内容更新会使当前认证缓存和旧请求结果失效，重新核对身份。

## 验证与诊断

管理中心的“验证登录”开始一个有操作 ID 的后台检查。“测试读取”选择指定公开样本；已有有效登录检查时复用结果。状态刷新不请求平台，也不调用模型。

登录检查默认缓存 5 分钟，同一凭据的并发检查合并。缓存到期显示待重新核对，不等于平台 Cookie 已过期。明确登录失效、账号不符或本地文件不可读时立即失效；全部调用者取消会取消共享检查。

匿名 API、账号 API、浏览器和资源请求保留各自诊断范围，同时遵守有效的共享冷却。新配置的账号可在冷却结束后验证，旧匿名暂停历史保留。管理验证许可绑定账号、目标接口、凭据代次及实例代次；不能清除共享风控或其它接口的限制。

过期登录态的明确账号复核可以验证新的 Cookie；成功仅恢复该账号的登录状态。视频或搜索仍受限时继续显示相应限制。“登录有效”和“所有读取可用”不会合并成一个成功标志。

## 阅读流程与长任务

直接调用 `bili_search` 传关键词；旧的搜索来源枚举工具已经移除。评论使用返回的短游标，去重集合在后端；字幕分页复用已经下载的材料。

`bili_frames` 一批最多 6 个不同时间点，一次必要导航后取帧。将成功帧的 `source` 列表传给 `dafeiyu_media_read` 的 `images` 模式，进行一次多图理解。保留请求位置、实际位置及逐点失败，画面采样不代表音轨理解或完整观看。

阅读记录按任务及任务意图版本隔离。工作上下文携带有界的短进度，完整材料和历史版本留在后端。默认每 3 个完成视频切段，或在下一次模型请求达到预算前切段；新段使用新会话，同一总期限和原始证据继续有效。

输入软限 24,000、硬限 32,000 token，按模型实际窗口和输出预留继续收紧；单任务最多 8 段。已有读取记录在失败、等待或重启后保留，继续使用原任务入口，不通过新建任务重刷。仅最终段进入最终结果交付。

## 真实验收

顺序：验证 UID → 原失败视频 → 搜索 → 一页评论 → 一个字幕轨两次分页。使用普通公开样本，不执行发布动作；出现新风控、账号不符或登录失效时停止后续网络检查。

记录每步真实请求及错误码、登录验证次数、缓存命中和结果范围，保持凭据脱敏。无字幕和无可见评论是材料条件，不等同于认证失败。离线固定数据测试与真实平台结果分别报告。

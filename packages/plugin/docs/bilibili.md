# B站登录与读取

管理中心的“测试读取”可选择本地凭据（HTTP）或已登录的 DSH 浏览器。HTTP 验证不会替代浏览器验证。浏览器视频验证会核对配置 UID 并实际取得一帧；其它浏览器验证只检查指定的搜索、评论或热门列表样本。只有真实成功且没有更新故障，才解除该浏览器端点的暂停；不会清除其它端点、HTTP、资源或共享暂停，也不意味着已理解整部视频。

管理协议沿用 owner 限定的 `verify.read`，增加可选 `transport: "http" | "browser"`，默认是 HTTP。浏览器视频和评论使用 `bvid`，HTTP 评论仍使用 `aid`；搜索使用 `keyword`。浏览器验证不需要 HTTP Cookie 文件，操作保存在既有读取验证记录中。暂停期间不能手工改库清标记；应在页面已正常可访问后执行一次受控验证。

“验证挑战”只用于可见验证控件或明确阻断提示。推荐视频标题里的“已验证账户”等普通内容不能证明挑战；页面状态检查未完成会单独报告，不据此要求重新登录。

阅读失败先区分平台连接、内容读取、模型处理与交付。`MODEL_INCOMPLETE`、`SEGMENT_LIMIT_REACHED` 或上下文容量错误不表示 B站离线；先看同一任务及其接续中的实际成功读取。登录通过也不能证明所有接口可用。

长阅读会话保留当前视频页、字幕轨和 `nextOffset`，即使尚未调用 `bili_reading_save` 也可通过 `bili_reading_get` 的 `resume` 继续。记录中的 `judgementSaved=false` 只表示没有保存判断，不表示没有读取。接续提示只带有界进度和来源入口，正文按需读取；原有任务来源、硬容量、时间及接续次数上限保持有效。

`bili_subtitles` 不传 `track` 时只列轨道，不要求时间区间；读取正文时 `startMs` 默认零，`endMs` 默认视频末尾与六分钟上限中的较小值。使用返回的 `nextOffset` 翻当前区间。浏览器未配置时不会暴露 `bili_frames`；可用 `bili_media` 登记流，再用媒体工具读取画面和音轨。Cookie HTTP 登录态与浏览器登录态是不同配置，不能互相替代。

开启公开能力需 `bilibili.capabilities: true`，并按配置校验准备 `media`。支持关键词搜索、视频资料、评论、字幕、弹幕和批量帧；不包含发表评论或发布弹幕。

## 本地 Cookie

配置中的 `bilibili.session` 包含 `file` 与 `expectedUid`。文件位于发布包以外，格式为 JSON 对象：必填 `uid`、`SESSDATA`；可选 `buvid3`、`bili_jct`。UID 为数字字符串，须与服务端实际登录账号一致。Cookie 不通过聊天提交，不进入模型上下文或管理返回。

文件使用 UTF-8 无 BOM。只有提供方需要的允许字段进入 API Cookie 头；字幕、媒体 CDN 和重定向目标不携带这些凭据。浏览器登录态与 HTTP 文件是不同的接入方式；不会在安装时自动读取任意浏览器或其它账号。

配置 HTTP、浏览器及私信时统一预期 UID。路径或 UID 变更停止实例后应用；同 UID 的 Cookie 内容更新会使当前认证缓存和旧请求结果失效，重新核对身份。

## 验证与诊断

管理中心的“验证登录”开始一个有操作 ID 的后台检查。“测试读取”选择指定公开样本；已有有效登录检查时复用结果。状态刷新不请求平台，也不调用模型。

登录检查默认缓存 5 分钟，同一凭据的并发检查合并。缓存到期显示待重新核对，不等于平台 Cookie 已过期。明确登录失效、账号不符或本地文件不可读时立即失效；全部调用者取消会取消共享检查。

匿名 API、账号 API、浏览器和资源请求保留各自诊断范围，同时遵守有效的共享冷却。新配置的账号可在冷却结束后验证，旧匿名暂停历史保留。管理验证许可绑定账号、目标接口、凭据代次及实例代次；不能清除共享风控或其它接口的限制。

过期登录态的明确账号复核可以验证新的 Cookie；成功仅恢复该账号的登录状态。视频或搜索仍受限时继续显示相应限制。“登录有效”和“所有读取可用”不会合并成一个成功标志。

## 阅读流程与长任务

直接调用 `bili_search` 传关键词；旧的搜索来源枚举工具已经移除。评论使用返回的短游标，去重集合在后端；字幕分页复用已经下载的材料。

`bili_frames` 一批最多 6 个不同时间点，一次必要导航后取帧。将成功帧的 `source` 列表传给 `dafeiyu_media_read` 的 `images` 模式，进行一次多图理解。保留请求位置、实际位置及逐点失败，画面采样不代表音轨理解或完整观看。

阅读记录按任务及任务意图版本隔离。工作上下文保留简明进度，完整材料、游标和来源留在后端。资源获取、内容曝光、视觉理解与判断分别记录；`mediaReadings` 来自实际理解回执。

统一容量为 `contextCapacity.maxTokens`，默认一百万 token，并受模型真实窗口约束。没有固定三视频换段、八段终止或 24k/32k 阅读门槛。来源与检查点保留；平台明确拒绝容量时按已完成工作接续，重启或确认词不重新创建裸目标。详见[任务运行说明](task-runtime.md)。

媒体整文件读取优先采用完整字节范围，仍校验 ETag、Content-Range、长度和内容。媒体 CDN 的资源故障不扩大为整个账号/API 的暂停，共享风控、账号身份和具体接口的限制仍生效。

## 真实验收

顺序：验证 UID → 原失败视频 → 搜索 → 一页评论 → 一个字幕轨两次分页。使用普通公开样本，不执行发布动作；出现新风控、账号不符或登录失效时停止后续网络检查。

记录每步真实请求及错误码、登录验证次数、缓存命中和结果范围，保持凭据脱敏。无字幕和无可见评论是材料条件，不等同于认证失败。离线固定数据测试与真实平台结果分别报告。

## 登录态更新与暂停

本地凭据文件是一次导出的快照。DSH 浏览器中的登录态更新，不会自动改写该文件。浏览器仍已登录但 HTTP 返回 -101 时，先核对期望 UID，再通过已授权的本地会话导出接口写入新文件并验证；不要把 Cookie 粘贴到聊天。保留旧文件和配置备份，验证成功后再切换路径。

账号验证成功只证明该登录态有效。浏览器验证挑战、单个接口风控和媒体资源暂停分别处理，不能据此清空所有暂停。已暂停的读取动作会从当前任务可用工具集合中撤下，已读记录入口保留；恢复后新一轮装配才重新提供对应工具。

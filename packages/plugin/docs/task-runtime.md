# 任务承接、上下文与读取

当前实现使用同一个任务 ID 承接原请求、补充、确认、继续和进度查询。Core 校验真实消息、主人、会话、撤回状态与任务版本；任务意图和回执持久化。模型更换 requestId 不会重新创建任务；修订中断后重放同一决策，不重复修订，也不取消已经受理的接续运行。

`ownerIntent` 保留原请求、最新要求、约束和委托决策。普通聊天调用任务入口后负责确认，执行器负责实际工作和最终汇报。仅在聊天里答应或写入记忆，不能把新的执行要求传递给已有任务。

## 容量和等待的含义

| 项目 | 当前规则 |
|---|---|
| 模型共享窗口 | `contextCapacity.maxTokens` 默认 1,000,000；仍受真实模型窗口限制 |
| 计量 | SDK 消息及工具投影用于估算；实际 usage 单独记录，估算偏高不拒绝输入 |
| 请求字节 | 审计指标，不作为第二个模型容量门槛；不会为满足旧字节阈值删除必要输入 |
| 必要上下文 | 校验来源后保留完整条目；更新事实不会继续累积为永远有效的旧快照 |
| 可选索引 | 按 `contextSelection` 选择，完整任务、正文和来源保留在对应存储中 |
| 任务期限 | 只有显式设置 `taskTimeoutMs` 才设置总期限；不是默认十分钟或固定段数 |
| 网络等待 | 独立于任务期限；模型默认空闲等待 300 秒，用户取消和退出仍可中止 |
| 模型瞬时故障 | 当前请求最多重试两次，不重新执行已经完成的工具 |
| 重复失败 | 同一意图版本、动作和参数在一分钟内连续两次相同失败，后续返回 `TOOL_NO_PROGRESS`，不重复派发 |
| 工具单页 | 字幕默认最多 25 条、最多可请求 50 条，按页面容量提前收束并返回精确 `next`；评论使用短游标，长 DSH 结果使用结果引用续读 |
| 资源限制 | 媒体文件、单次网络响应、图片批次及受控进程仍有各自资源限制，不能解释成任务总 token 上限 |

平台明确报告上下文容量不足时，程序保存已完成操作和来源并尝试接续；首个请求就无法容纳且没有可接续工作时保留明确错误。网络失败不会一律归为上下文不足。

## B站与 DSH 衔接

字幕、弹幕和媒体入口可用 `bvid`，由程序解析分 P 和 `cid`，也支持已曝光的 `videoPageId`。字幕返回的 `next` 包含后续参数，避免模型手工拼接分页。资源已获取、内容已暴露、媒体已理解、模型已形成判断分别记录；`mediaReadings` 仅来自成功的媒体理解及来源回执。

阅读阶段可查询宿主目录，再通过 `dsh_tool_read` 使用宿主允许的只读工具。宿主会在实际派发前拒绝 shell、写入和安装动作；普通授权执行继续使用原有独立权限检查。目录存在、登录成功、资源登记、抓图、生成正文和消息已送达是不同状态。

每次来源校验仍检查当前权限和撤回。撤回记录以增量索引加速，外部提交立即使缓存失效；媒体内容哈希在入口校验 JSON 一次，结果与旧哈希完全一致，不需要修改历史数据。
